# 传感器配置

适用版本以 [VERSION](../../VERSION) 为准，环境为 Ubuntu 22.04 + ROS 2 Humble。命令在源码仓库根目录执行，每个终端先加载相同安装环境。

组合模型从 sensors.xacro 声明传感器类型、挂载和参数文件；核心按同一模型计算雷达、IMU 与相机。完整参数表在 [配置文件](../api/配置文件.md)，插件参数文件在 [插件接口](../api/插件接口.md#parameter-files)，字段与时间单位在 [传感器数据](../api/传感器数据.md)。

## 理想测量与算法误差测试

所有标准传感器和随附车型默认不注入误差：里程计比例误差、固定偏移、随机噪声以及雷达额外丢点概率均为 **0**。零误差表示不添加测量扰动；扫描采样、相机像素量化和碰撞期间轮式里程计与真值的差异仍然存在。

四轮车提供两份可直接使用的配置：

| 配置 | 用途 |
| --- | --- |
| [ideal.yaml](../../examples/wheel_car_4w/wheel_car_4w_sim/config/noise/ideal.yaml) | 所有误差为 0，与默认模型一致 |
| [algorithm_test.yaml](../../examples/wheel_car_4w/wheel_car_4w_sim/config/noise/algorithm_test.yaml) | 里程计比例误差、偏移与噪声，雷达/IMU/RGB 扰动示例；属于人为测试条件 |

在已构建并 source 安装环境的终端启动误差测试：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  gui:=false cameras:=false lidar_profile:=vlp16 \
  noise_config:=package://wheel_car_4w_sim/config/noise/algorithm_test.yaml
```

结束当前 launch 后，将文件名改成 `ideal.yaml`，即可启动理想对照组。相机误差参数不会自动开启相机；需要图像时使用 `cameras:=true`，并准备可用渲染后端。

自定义时复制配置到自己的目录，按需修改，再传入其绝对路径。`sensors` 下使用模型的实例名（如 `body_imu`），不是话题名或 link 名。文件在雷达预设之后应用，只覆盖列出的误差字段；未知实例、错误传感器类型或非误差字段会报错。修改后重新启动。

`noise_config` 同样适用于 Ackermann、全向轮和无人机的示例入口。前三种标准轮式里程计使用 `odometry`；无人机没有轮式编码器，配置只包含 `sensors`。RGB、Depth、RGB-D 分别使用匹配的颜色/深度字段。所有字段、单位及约束见 [误差配置接口](../api/配置文件.md#noise-config)。

做对照实验时固定 `simulation.seed`、场景、步长、采样频率和控制输入，先记录零误差结果，再逐项增加误差，最后组合扰动并更换种子做重复试验。同一配置、种子、实例名与仿真时间序列可复现随机扰动；改变采样频率或积分步长后不能直接期待逐样本一致。固定偏移不随时间变化，当前未实现温漂、随机游走或完整硬件误差模型。

## 选择雷达

四轮车可直接选择预设，每次只运行一条：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=vlp16
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid360
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid40
```

Mid-360 在当前示例 launch 默认使用 CustomMsg 与配套显示点云。需要原生 xyzirt_v1 时增加 `lidar_interface:=native`；选择 Livox PointCloud2 用 `xfer_format:=0`。不要只重映射名称便认为字段兼容，具体见 [雷达选择说明](../../examples/wheel_car_4w/雷达配置说明.md)。

在自己的模型中覆盖参数时，先保存已有安装 link、name 和 topic，再调整扫描图案、帧率、列数与范围。Mid-360 的列数和帧率需满足固定点率约束；其他图案的参数不要混填。修改后重新启动，查看 manifest 中实际加载的参数。

## 增加一个雷达或 IMU

第一次添加传感器请先完成[添加 IMU 教程](../tutorials/添加IMU.md)，其中包含 link/joint、组合模型、runtime 和验收命令。下列清单用于已有模型的日常修改。

1. 在 URDF/Xacro 添加安装 link 与 fixed joint，确定相对机体的外参。
2. 在 `<litesim3d version="1">` 块中增加 sensor，使用独立 name 和 topic，link 指向刚才创建的安装坐标。
3. 引用实现包的完整参数文件，通过自己的文件或 overrides 覆盖安装、频率和噪声。
4. 重新启动，检查消息 frame、TF 和采样频率；多机使用相对话题名。

例如已有 imu_link 时：

```xml
<litesim3d version="1">
  <sensor name="front_imu" class="litesim3d_imu/Imu">
    <parameters file="package://litesim3d_imu/config/parameters.yaml"/>
    <overrides>
link: imu_link
topic: imu/front
rate_hz: 200.0
accel_sigma: [0.02, 0.02, 0.02]
gyro_sigma: [0.001, 0.001, 0.001]
    </overrides>
  </sensor>
</litesim3d>
```

这个片段需要放入自己的模型；它不会自动创建 imu_link。组合模型已经声明 sensor 时，移除旧 YAML 中全部 lidars/imus/cameras 列表，避免重复来源。没有 sensor 扩展的旧模型仍可按 [兼容 YAML 参数](../api/配置文件.md#imus) 添加 IMU。

## 滚动扫描与噪声

做去畸变算法输入时，将雷达 scan_mode 设为 rolling，保留逐点时间。snapshot 适合先检查几何和连接，不能用作扫描运动畸变输入。先固定 seed 并保留零噪声结果，再逐项增加 range_bias_m、range_sigma_m 或 dropout，便于区分几何与测量误差。

原生云无回波保留 NaN 槽位，消费端先过滤非有限 xyz；range_boundary 仅用于显示最大范围，不接入建图。默认雷达排除自身传感器 link，仍可看到车体；只关心环境时设 self_filter=robot，需要指定排除时使用 links 与 excluded_links。

IMU sigma 为每样本标准差。先在水平静止状态检查安装方向与重力比力，再加偏差/噪声；不要把 raw IMU 的占位姿态当作姿态估计。噪声影响测量，不移动世界真值。

## 轮式里程计

组合模型在 odometry 声明选择独立估计插件；几何参数与底盘引用同一配置节。更换里程计时保留底盘插件，只换估计器 class 与它的参数文件。旧 YAML 使用 odom.mode 和误差参数，迁移后不能两处同时声明。

`linear_scale_error: [0.02, 0]` 表示车体前向速度多估计 2%，`angular_scale_error: -0.01` 表示 yaw 角速度少估计 1%。`linear_bias_mps` 和 `angular_bias_radps` 是固定速度偏移，非零时静止也会累计漂移；`*_sigma_*` 为每次解算的高斯标准差。位姿由带误差的速度积分，重置后清除累计漂移并重新开始随机序列。完整示例见本页前面的误差配置。

误差只进入里程计估计，不改变实际轮速、碰撞或其他传感器的真实运动输入。对照精度时用 `/sim/ground_truth/<robot_id>/odom` 作为独立评测通道；不要把该真值输入被测算法。里程计协方差不会自动根据这些参数传播成位姿协方差。

需要观察轮子受阻时的累计误差，可在组合模型 runtime 的 robot 下设置 continue_on_collision=true。车体仍受碰撞阻挡；编码器 odom 可能继续移动，激光/IMU/相机继续反映真实车体。理想里程计也不等于碰撞期间的世界真值。

## RGB 与深度相机

启用、关闭预览和切换 RGB/Depth/RGB-D 的步骤见 [车载相机](SDF与独立窗口.md#车载-rgb-与深度相机)。相机必须挂在 optical link，需要渲染后端；关闭窗口不等于关闭相机。

## 检查数据

```bash
ros2 topic list
ros2 topic echo /sim/status --once
ros2 topic info /points_raw --verbose
ros2 topic echo /imu/data_raw --once --qos-reliability best_effort
```

命令中的话题应改为实际配置值，尤其是 Mid-360 和多机器人。频率以仿真时间为基准，实际 RTF 降低时墙钟接收频率也会降低。首次接入先核对 frame、时间单位、消息布局和 QoS，再观察算法结果。
