## 完整测试的判定

每个待发布需求必须对应至少一个正常场景和适用的异常或边界场景。所有适用用例必须完成实现和执行，并保留环境、输入、断言结果和可复查证据。模块覆盖率只补充缺口分析，不能替代行为测试。

| 状态 | 使用条件 | 能否计入通过 |
| --- | --- | --- |
| PASS | 在指定环境执行，全部断言满足且证据可读取 | 是 |
| FAIL | 执行后存在不满足的断言 | 否 |
| ERROR | 测试程序、依赖或环境异常，未完成判断 | 否 |
| BLOCKED | 已尝试执行但有明确外部阻塞，记录原因 | 否 |
| NOT_RUN | 尚未执行，包括没有实现 | 否 |
| NOT_APPLICABLE | 在运行前确认不属于本次已声明范围，说明依据 | 不加入分母；不等于通过 |

框架中的 skip、xfail、超时和空测试不能转为 PASS。修复失败后需要保留原失败结果和重新执行的结果；重跑通过不能删除间歇失败的记录。

开发前的初始功能状态均为 NOT_RUN；[文档检查记录](文档检查记录.md)保留当时的检查历史。当前实现和真实执行结果以 [M1 测试报告](M1测试报告.md)为准。

## 数值与统计标准

以下是初始验收目标，适用于局部坐标绝对值不超过 100 m 的参考场景。D0 可以根据明确的硬件、后端精度和算法适用范围修订，但必须先记录版本与原因，再执行测试。

| 名称 | 适用条件 | 初始通过条件 |
| --- | --- | --- |
| 变换容差 | 双精度解析变换与关节链 | 平移误差 ≤ 1e-6 m；旋转测地角误差 ≤ 1e-6 rad |
| 四元数约束 | 任何有效状态 | 有限；归一化误差 ≤ 1e-9；q 与 -q 按同一旋转处理 |
| 测距容差 | 无噪声解析场景与 float32 输出 | 有效点距离误差 ≤ 1e-3 m；遮挡和无回波类别完全正确 |
| 运动容差 | P01，dt=0.005 s，连续运行 10 s，关闭限加速和噪声的解析专用配置 | 终点位置误差 ≤ 1e-3 m；偏航误差 ≤ 1e-4 rad |
| 碰撞容差 | F04，最大位移覆盖测试定义 | 不能穿越障碍；几何穿透深度 ≤ 1e-3 m |
| 坡面容差 | F05 连续可达表面 | 离地距离误差 ≤ 2e-3 m；法向夹角 ≤ 1e-3 rad |
| 事件计数 | 60 s 仿真时间，固定步长与频率 | 计数与精确事件计划相差不超过端点约定的 1 个样本，长期无累计偏差 |
| 逐点时间 | 滚动扫描 | 时间非负且小于扫描周期；相对解析时刻误差 ≤ 1e-6 s |
| IMU 数值 | 无噪声 P01，远离不连续点 | 比力误差 ≤ 1e-3 m/s²；角速度误差 ≤ 1e-4 rad/s |
| 高斯噪声 | 无截断参考距离，N=100000，固定种子集合 | 均值与配置偏置之差 ≤ 5σ/√N；样本标准差相对误差 ≤ 2% |
| 随机丢点 | N=100000，p=0.1 或 p=0.5 | 比例误差 ≤ 5√(p(1-p)/N)；p=0、1 单独精确断言 |
| 同平台复现 | 同构建、平台、线程策略、种子和输入 | 稳定排序后的核心状态与传感器数据哈希一致 |

σ=0 的情况单独精确判断，不使用会除以零的统计公式。统计测试使用预先固定的种子列表，失败后不得换种子重试直到通过。可用独立二项分布或卡方检验替代近似界限，但须在执行前固定方法与显著性水平。

性质测试应验证变换与逆变换相消、刚体整体变换不改变局部测距、增加被遮挡物不改变最近回波、增加扫描分辨率不改变已有方向的理想交点，以及打开可视化不改变核心状态。这些测试用于发现只有固定示例无法暴露的错误。

## 点云与运动畸变验证

必须从原始字节重新解析 PointCloud2，校验 fields、offset、datatype、point_step、row_step、data 长度、大小端、frame_id、时间戳和 NaN 标记；不能只看 RViz2 显示正常。

静态测试覆盖水平和倾斜平面、球面、盒体、不同高度障碍、盲区内遮挡、射线起点位于几何内部及自身遮挡。至少有一组场景能区分真实三维射线和二维激光的高度复制。

运动测试使用 P01 解析位姿逐点计算参考交点，分别验证平移、旋转与带安装偏置的复合运动。原始畸变点云和按真值去畸变的参考点云分开检查；如果实现只是给同一瞬时扫描附加 time 字段，该测试必须失败。

## ROS 2 与时间验证

ROS 集成测试至少覆盖以下组合：仿真时间启用、算法误用系统时间、暂停与继续、单步、完整重置、带时间与不带时间速度模式、匹配与不匹配 QoS、迟加入订阅者、外部估计器接管 TF、接收端较慢及进程异常退出。

接收端根据消息时间等待 TF。正常配置在就绪期结束后，测试中每条待使用传感器消息在 0.5 s 墙钟超时内取得必要的变换；0.5 s 是集成测试等待预算，不是允许传感器时间戳偏移 0.5 s。缺失变换应造成明确失败。

逻辑采样误差按仿真时间统计；DDS 到达延迟按墙钟统计。单机性能延迟使用同一单调时钟，不能直接相减不同机器的未同步时钟。重置前后的数据按 run_id 和独立记录文件隔离，检查旧速度命令、旧 TF、未完成点云和算法内部历史未被复用。

## 算法验收

M2 至少选择一个实际三维建图或定位算法，再选择一个实际导航算法。D0 固定源码版本、参数、输入字段和时间约定；适配应局限于消息转换和配置，不改变算法主体以迎合仿真结果。

| 配置 | 场景与输入 | 初始目标 |
| --- | --- | --- |
| A0 接口验证 | 实际算法订阅点云及所需 IMU 或里程计，运行 F07 | 输入完整、无字段或 TF 错误、无 NaN 状态或异常退出 |
| A1 三维轨迹 | F07 固定 100 m 路线；理想传感器与配置误差模式分别运行 | 理想模式 ATE RMSE ≤ 0.10 m；误差模式 ≤ 0.20 m；每项报告完整率与失败次数 |
| A2 三维地图 | 仅在所选算法输出地图时启用；2 cm 体素下采样 | 对独立可见参考表面，点到表面 RMSE ≤ 0.05 m、95% 点误差 ≤ 0.10 m；可见区域覆盖率 ≥ 90% |
| A3 地面导航 | F07，20 个可达目标，每目标 5 个种子，共 100 次 | 到达率 ≥ 95%；接触碰撞 0 次；终点距离 ≤ 0.15 m、偏航误差 ≤ 0.10 rad，持续 1 s |
| A4 不可达与异常 | 固定不可达目标、传感器中断及恢复场景 | 按声明策略失败或恢复；不穿墙、不使用陈旧控制继续无界运动 |

ATE 为时间关联后的绝对轨迹误差。采用冻结的初始坐标对齐，不进行尺度拟合或逐段重新对齐；若额外报告全轨迹 SE3 对齐结果，必须单独标注。时间关联容差为 5 ms，允许对连续真值插值；必须同时报告匹配比例，成功运行的匹配比例须 ≥ 99%，低于该值的运行计为失败。不能删除失配或发散区段来改善均方根误差。

A1 理想模式执行一次，误差模式使用固定种子 0 至 4 执行五次，各次均需满足目标，并分别报告误差。噪声初始配置为激光 σ=0.01 m、固定偏置 0、丢点率 0.01；里程计误差、IMU 噪声和偏置在 D0 按目标算法冻结。A2 覆盖率定义为独立可见参考表面按 2 cm 体素采样后，与任一估计地图点距离不超过 0.10 m 的参考点比例；初始门槛为 90%。可见表面集合及生成协议在夹具版本中固定，不允许仅以低误差但极稀疏的地图通过。

A3 每次限时 120 s 仿真时间；不可达目标最多等待 60 s 后按约定退出。目标、初值、控制限制和规划参数保持不变。失败和超时都计入 100 次分母。真值接触检测独立于规划器的碰撞报告。

A4 初始降级策略为有效点云超时 0.5 s 后停止继续推进导航，最迟在该超时加 `v/a_dec+dt` 内停车；恢复数据后 5 s 内重新规划，或明确结束本次任务并保持停止。该策略由算法或其已声明的控制保护层执行，测试应核对实施者，不能假定仿真器会因为缺少点云自动停止仍持续到达的合法速度命令。

若导航算法将点云投影成二维代价地图，该结果只证明地面导航链路有效。要宣称三维地形规划有效，还需相应规划算法及 F05、F06 的独立测试，不能用二维导航通过代替。

真值仅提供给评测程序。检查算法订阅图、重映射、TF 发布者和启动配置，防止算法读取真值位姿、真值去畸变点云或真值定位变换。初始位姿先验若允许，必须固定其范围和误差。

## 性能负载与测量方法

B0 环境记录必须包含 CPU 型号、物理及逻辑核心数、内存、操作系统、编译器、构建类型、ROS 2、RMW、几何后端、线程数、电源模式和后台负载。未锁定 B0 的结果只能作为探索数据。

| 负载 | 配置 | 判定用途 |
| --- | --- | --- |
| B1 基准 | F09 约 100000 三角形；1 个 R01；32×1024 点每帧，10 Hz，约 327680 射线每秒；IMU 200 Hz；odom 50 Hz；最多 4 个射线工作线程 | M2 性能门禁 |
| B2 压力 | F10 约 1000000 三角形；64×2048，20 Hz，约 2621440 射线每秒 | 性能曲线、内存上界和过载行为；不默认保证实时 |
| B3 多机器人 | 4 个机器人，每个 16×512，10 Hz；固定相同场景和线程预算 | M3 启用多机器人时的性能门禁基线，D0 对应扩展评审时冻结阈值 |

B1 初始目标：无节拍限速运行的平均实时率 RTF ≥ 1.0；RTF 定义为推进的仿真时长除以墙钟时长。按 1 倍节拍运行时，整体 RTF 与 1 的差不超过 2%，仿真器内部漏生成完整扫描帧为 0。

B1 雷达整帧计算墙钟耗时 p99 ≤ 80 ms；计算完成到桥接发布调用完成 p99 ≤ 20 ms，分别标明测量边界。仿真核心与 ROS 桥接进程树的峰值 RSS ≤ 1 GiB。RViz2、robot_state_publisher 和被测算法分别统计，不能计入同一内存数字后仍声称是“仿真核心占用”。CPU 以一个逻辑核心 100% 计，记录平均值、p95 和最大值，避免多核百分比口径混淆。

先预热 30 s，再采样 120 s，重复 5 次；B1 的全部 5 次都应满足目标，并保留每次数据。窗口开启与关闭分别测试。文件加载的冷启动与热启动分开报告，不能用热缓存成绩代表冷启动。

压力负载若无法实时运行，应降低实际推进速度并如实报告 RTF，或根据显式策略丢帧并计数。不能跳过物理时间更新、伪造旧帧时间戳或无限堆积队列维持表面频率。

## 稳定性与错误恢复

| 项目 | 输入 | 初始通过条件 |
| --- | --- | --- |
| 长时间运行 | B1，连续 8 h 墙钟；每 10 min 记录资源 | 无崩溃或死锁；预热后 RSS 回归斜率 ≤ 1 MiB/h，结束前后同状态差 ≤ 32 MiB；峰值仍满足预算 |
| 重置循环 | 100 次完整实验重置，重新启动规定消费端 | 无旧命令或旧数据污染；每轮能产生正确首帧；资源不累计增长 |
| 启停循环 | 100 次启动与正常退出 | 无残留进程、未关闭文件或占用端口；退出状态符合约定 |
| 错误配置 | R04、F11 及非法 YAML 参数 | 拒绝加载，清楚定位错误；已运行场景不被部分修改 |
| 资源缺失 | 删除测试副本中的 mesh 或不可读资源 | 受控失败，指出缺失资源，不出现无提示空模型 |
| 传输拥塞 | 订阅者降速、停止或 QoS 不匹配 | 队列有界，诊断准确，恢复策略可验证 |

ASan 与 UBSan 在支持的 Linux 构建上执行，结果必须无检测错误；并行几何或传感器路径增加单独的 TSan 构建。不能把互不兼容的检测器同时启用后以工具失败代替代码判断。超时按真实故障记录。

## CI 与发布门禁

| 执行时机 | 必测范围 |
| --- | --- |
| 每次变更 | 文档与接口检查、构建、受影响单元及组件用例、ROS 冒烟测试 |
| 每次合入候选 | 全部 M1 用例与已实现 M2 用例、安装后运行、固定场景算法冒烟 |
| 夜间或专门测试任务 | 误差统计、异常输入、检测器、扩展负载和重复实验 |
| M2 发布候选 | 全部适用功能用例、完整算法验收、B1 五次性能、8 h 稳定性、100 次重置与启停 |
| M3 扩展发布 | 启用扩展的全部用例，加完整已有功能回归 |

每个用例 ID 必须对应可执行测试或清楚定义的手工流程。自动化测试使用非零退出码报告失败，输出 JUnit 或同等结果；不能使用只检查进程存活或无断言的空测试。

覆盖率初始门槛：核心变换、时间、几何、运动和传感器模块行覆盖率 ≥ 90%、分支覆盖率 ≥ 80%；项目自有逻辑整体行覆盖率 ≥ 80%、分支覆盖率 ≥ 70%。第三方、自动生成消息和纯资源文件可排除，但必须在报告中列出排除规则。每个修复的有效缺陷新增能复现问题的回归测试。

发布条件是所有本阶段必测项 PASS、无未关闭的崩溃、几何错误、时间错误、数据布局错误、真值泄露或碰撞穿透问题。NOT_RUN、BLOCKED、ERROR 都阻止适用能力的验收；可选范围只有在发布前明确未包含时才能记为 NOT_APPLICABLE。

## 证据与结果归档

每次执行建立独立结果目录，保存运行清单、用例结果、原始参数、场景和资源哈希、ROS 日志、必要的 rosbag2、真值和估计轨迹、性能原始采样及汇总报告。目录名称和生成命令由实现确定，此处不假定已经存在测试脚本。

最终报告使用[测试报告模板](测试报告模板.md)。报告必须列出适用用例总数、PASS、FAIL、ERROR、BLOCKED、NOT_RUN、NOT_APPLICABLE 数量、关联缺陷和证据路径；通过率分母包含所有适用但未完成的用例。

仿真验收仅说明声明模型和场景内的能力。真实机器人运行、设备接口、工厂或现场验收需要独立授权与证据，不能从上述软件测试推导已完成。
