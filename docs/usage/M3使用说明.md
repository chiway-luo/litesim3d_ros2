# M3 使用说明

本文介绍多机器人、固定障碍物、理想 Ackermann 和点云字段适配。先按 [安装与构建](安装与构建.md) 准备环境，然后从源码仓库根目录执行：

```bash
source "$(python3 scripts/paths.py install)/setup.bash"
export ROS_DOMAIN_ID=70 ROS_LOCALHOST_ONLY=1
ros2 launch litesim3d_ros2 world.launch.py
```

默认启动 4 个机器人和 4 个 robot_state_publisher，所有机器人共用一个仿真时钟。按 Ctrl+C 退出完整 launch。指定自己的世界文件：

```bash
ros2 launch litesim3d_ros2 world.launch.py config:=/绝对路径/world.yaml paused:=true manifest:=/绝对路径/world.json
```

```yaml
schema_version: 1
config: m3_robot.yaml
robots:
  - {id: r0, xyz: [0, 0, 0]}
  - {id: r1, xyz: [2, 0, 0], rpy: [0, 0, 0]}
```

`config` 是普通单机器人配置路径，支持相对路径和 package URI。世界内 1–4 个机器人共用 URDF、传感器与物理参数；ID 必须以字母开头，仅含字母、数字和下划线，传感器话题须为相对名称。位姿不能重叠。场景障碍物保持初始位姿，机器人之间仍执行碰撞检查。

| 接口 | 内容 |
| --- | --- |
| `/r0/cmd_vel` 等 | 对应机器人的 `geometry_msgs/Twist`，可统一切换 TwistStamped，不影响其他机器人 |
| `/r0/points_raw`、`/r0/imu/data_raw` | 原始传感器，默认 best effort、KEEP_LAST 5，可切换 reliable |
| `/r0/odom`、`/r0/joint_states` | 独立里程计与关节状态 |
| `/r0/robot_description` | transient-local URDF |
| `/tf`、`/tf_static` | `r0/odom → r0/base_link → r0/lidar_link` 等独立前缀树 |
| `/clock` | 世界节点唯一发布，发现重复发布者则故障退出 |
| `/sim/pause`、`/sim/step` | 整个世界同时暂停/继续或单步，Step 请求 ID 幂等 |
| `/sim/status` | 每台机器人诊断、拒绝命令、超时、QoS 冲突、队列策略、TF 责任和性能窗口 |
| `/sim/ground_truth/r0/odom`、`contacts` | 实验真值与碰撞信息，不作为算法输入 |

每个 odom 原点是机器人初始位姿；不向算法 TF 注入全局真值。多机支持整体暂停/单步；完整会话重置仍使用 M2 单机 `sim_session`。多机完整重置和统一全局 RViz 布景留作后续扩展。

多机启动参数：

| 参数 | 默认值与行为 |
| --- | --- |
| `cmd_mode` | `twist`；`stamped` 时各机器人命令话题统一使用 TwistStamped |
| `sensor_reliable` | `false`；`true` 时点云和 IMU 使用 reliable，队列深度仍为 5 |
| `publish_odom_tf` | `true`；`false` 时全部 odom TF 交给外部估计器 |
| `external_odom_tf_robots` | 空；逗号分隔的机器人 ID，如 `r1,r3`，仅这些机器人停止发布 odom TF |
| `startup_timeout` | `15.0` 秒；等待各 robot_state_publisher 就绪的墙钟上限，必须为正数 |

Stamped 命令的 `header.frame_id` 必须是接收机器人的带前缀 base_link（如 `r0/base_link`），时间戳必须在当前仿真时间的有效窗口内。空 frame、跨机器人 frame、过期/未来/非法时间戳以及非有限速度会被拒绝，且不刷新停车超时。发布示例中的时间戳应读取当前 `/clock`，不能使用系统墙钟。

```bash
ros2 launch litesim3d_ros2 world.launch.py cmd_mode:=stamped sensor_reliable:=true external_odom_tf_robots:=r1,r3
```

外部 TF 只用于显示与估计，不改变碰撞或传感器真值。重复 odom TF 发布者、错误父 frame 或多时钟会使整个世界故障退出。必需的仿真/RSP 子进程意外退出时，launch 清理其他子进程并返回非零；用户对完整 launch 按 Ctrl+C 则正常退出。布尔启动参数只接受 `true`/`false`。

`manifest` 额外记录 ROS/RMW、桥接与 launch 源码指纹、墙钟记录时刻、命令/QoS/TF 设置和每台机器人一致的退出原因，便于复查运行版本。

## 固定障碍物与 Ackermann

通过 YAML/SDF 加载的场景障碍物固定在初始位姿，不计算障碍物速度、位移、受力或碰撞后的反弹。旧 YAML 的 `motion` 字段仍做格式与数值校验，但不执行运动；对应实体 ID 写入 manifest 的 `config.ignored_entity_motion`，`config.obstacles_fixed` 为 true。

`robot.drive.continue_on_collision: true` 允许轮式机器人在车体受阻时继续驱动轮子并累计 `/odom`；默认 false，小车示例启用。多机器人接触时，车体真实位姿仍被阻挡，传感器仍查询真实轨迹。命令超时、暂停和零速度指令继续生效。

同一仿真步内，各机器人按共同采样时刻推进。核心 World 进入 Fault 后，后续 tick 不推进时间、不产生输出，也不能恢复运行；应新建实验。

Ackermann 配置：`robot.motion_model: ackermann`，`robot.drive.wheelbase: 1.0`（米），`max_steering_rad: 0.6`。输入仍为 v/ω，满足 `|ω| ≤ |v| tan(max_steering_rad) / wheelbase`，允许倒车，v=0 时不转向。轮速、速度限幅、加减速、URDF 与配置一致性仍受原有校验约束。

```bash
ros2 launch litesim3d_ros2 demo.launch.py config:=$(ros2 pkg prefix litesim3d_core)/share/litesim3d_core/config/ackermann.yaml
# 历史 dynamic.yaml 仍可加载；其中障碍物现在固定在初始位置
ros2 launch litesim3d_ros2 demo.launch.py config:=$(ros2 pkg prefix litesim3d_core)/share/litesim3d_core/config/dynamic.yaml
```

## 点云字段适配与算法消费

在同一已 source 的环境中分别启动：

```bash
ros2 run litesim3d_ros2 sim_ouster_adapter --ros-args -p input_topic:=/r0/points_raw -p output_topic:=/points_ouster
ros2 run litesim3d_ros2 sim_cloud_probe
ros2 topic echo /probe_status
```

适配器保留点方向、组织结构与坐标，产生冻结的 Ouster original 字节布局；时间由秒转纳秒、range 用毫米。完整字段、填充、无回波和合成强度语义见 [基线](../testing/M3基线.md)。`adapter_status` 报告接受/拒绝计数和错误。`sim_cloud_probe` 使用本机 PCL 读取全部字段并执行 0.1 m VoxelGrid，输出版本、有限点数、体素数和最多 8 个质心；无效尺寸或字段在进入 PCL 前拒绝。它是可复现的算法消费验证工具。

测试与性能命令见 [测试文档](../testing/README.md)。适配器的 PCL 消费验证不能替代外部 SLAM 或导航闭环验证。
