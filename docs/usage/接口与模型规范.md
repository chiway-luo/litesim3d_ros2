# litesim3d_ros2 接口与模型规范

适用版本：仓库 [VERSION](../../VERSION) 声明的版本。

本文记录当前接口与模型约定。完整操作和配置以 [接入与使用手册](接入与使用手册.md) 为入口；测试门槛和执行结果集中在 [测试文档](../testing/README.md)，历史设计另见 [开发方案](../design/开发方案.md)。

## 坐标与单位

内部长度为米、角度为弧度、时间为秒或整数纳秒，采用右手坐标系；机器人机体坐标为 x 前、y 左、z 上。姿态存为归一化四元数，内部位置和姿态计算采用双精度。外部配置若接受角度制，字段必须明确带有 `_deg`，导入时统一转换。[REP 103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)

记 `T_WL(t)` 为时刻 t 雷达坐标到仿真世界坐标的变换，`p_W = T_WL(t) p_L`。显示、射线与碰撞统一使用同一条变换链；网格局部 origin、scale、link 变换和实体世界位姿都只能应用一次。

`world` 为仿真真值坐标；算法侧的基本关系为 `map → odom → base_link → sensor_link`，允许插入 URDF 的根链接等中间坐标。`map` 可以由定位修正，`odom` 用作连续局部参考。默认不向算法 TF 树发布 `world → base_link` 或真值 `map → odom`。[REP 105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)

## 时间与调度

建议基准步长为 0.005 s，内核以整数纳秒累加，不使用渲染帧间隔积分。传感器按自身频率调度；非整数倍频率通过整数或有理数事件调度避免累计漂移。事件落在积分步内时，应使用轨迹插值或子步计算该采样时刻的状态。

每个步长的逻辑顺序为：取出本步有效输入，推进世界与机器人状态，计算到期采样，提交本步状态快照，然后向 ROS 2 输出时钟、状态与已完成的传感器帧。发布的数据不能包含当前仿真时间尚未发生的采样。

ROS 2 各话题跨 DDS 传输没有统一的到达先后保证。接收端按消息时间查询 TF 并在限定时间内等待，不能用某次回调先到作为数据正确性的依据。仿真器发布 `/clock`，所有算法、可视化和记录节点启用 `use_sim_time`。[ROS 2 时间设计](https://design.ros2.org/articles/clock_and_time.html)

| 参数 | 初始建议 | 行为 |
| --- | --- | --- |
| step_size | 0.005 s | 正数，按基线固定 |
| lidar_rate | 10 Hz | 基准雷达扫描周期 0.1 s |
| imu_rate | 200 Hz | M2 启用 |
| odom_rate | 50 Hz | 测量里程计 |
| real_time_factor | 1.0 | 墙钟节拍目标，不改变模型时间步长 |
| seed | 42 | 每个实体和传感器派生独立随机流 |
| command_timeout | 0.5 s 仿真时间 | 到期后目标速度归零，按减速度约束停车 |

同一构建、硬件、浮点模式、随机实现、种子和按时间记录的输入应产生相同核心输出。跨平台比较使用数值容差；标准库随机分布和并行归约不同，不能直接宣称跨平台逐字节一致。外部 ROS 2 算法闭环不自动具有确定性，需要记录接收后的控制输入及生效步号。

## 运行状态与实验操作

运行状态为加载、就绪、运行、暂停、重置、故障和退出。只有成功完成模型与场景校验后才能开始运行；失败操作不能部分修改当前世界。

| 操作 | 前置条件 | 完成后的状态 |
| --- | --- | --- |
| pause | 运行或暂停 | 暂停；停止推进时间和采样，可重复调用 |
| resume | 就绪或暂停 | 从当前仿真时刻继续 |
| step N | 暂停，N 为合法正整数 | 精确执行 N 步并保持暂停；重复 request_id 不再次推进 |
| set_pose | 仅启动前 ready 状态 | 校验并设置初值；实验开始后的 paused 状态也会拒绝，应使用协调 reset |
| reset | 实验协调器已停止消费端和控制发布端 | 创建新 run_id，重建状态与随机流，清除消息与 TF 缓存后重新启动消费端 |

普通 launch 可通过完整退出后重新启动创建新实验；在线单机协调 reset 由 `sim_session` 提供。管理器等待登记成员 executor、输入订阅类型/QoS、ROS 图归属和 DDS 匹配后才返回成功，详见 [会话操作](M2使用说明.md#协调重置)。新实验时间从 1 ns 开始，避免 0 被误当作未初始化时间；首个传感器事件仍按其采样计划触发。

重置不能只把 `/clock` 改小。需要停止旧控制输入、清空队列、丢弃未完成帧，并重建或重启依赖历史状态的 TF、robot_state_publisher、滤波器和算法节点。各标准传感器消息没有 run_id 字段，运行清单和 `/sim/status` 负责关联实验，算法记录包按实验分开。

暂停时仿真控制超时也暂停；继续后按仿真时间判定超时。控制输入队列必须有界，暂停期间保留最后一个有效速度命令。墙钟进程看门狗属于单独机制，不能与仿真控制超时混为一谈。

## URDF 导入

使用与目标 ROS 2 发行版匹配的 urdfdom。接受 URDF 1.0 兼容内容；Xacro 作为预处理步骤生成 URDF，并将展开结果及其资源哈希写入运行清单。[urdfdom](https://github.com/ros/urdfdom)

| 元素 | 当前行为 |
| --- | --- |
| link、joint、origin、axis | 构建单根无环关节树，统一处理旋转与平移 |
| fixed | 固定变换 |
| revolute、continuous、prismatic | 运动学更新；适用的位置和速度限制生效 |
| mimic | 支持倍率与偏移，拒绝循环依赖 |
| floating、planar | 报告不支持并拒绝作为可运行模型导入 |
| visual | 显示几何，可作为默认传感器表面来源 |
| collision | 碰撞几何，支持同一 link 的多个碰撞元素 |
| inertial | 可解析和保存；运动学模式不据此计算动力学 |
| box、sphere、cylinder | 检查正尺寸，转换为可查询几何 |
| mesh | 支持 STL、DAE、OBJ；通过 Assimp 导入并校验网格 |
| Gazebo 或其他扩展 | 记录为未执行扩展；传感器必须由本项目配置显式声明 |

资源支持 `package://`、本地文件路径和相对路径。相对路径以 URDF 文件所在目录为基准；Xacro 模型使用展开时记录的资源解析基准。安装后必须通过包资源索引定位，不依赖源代码目录。网格单位按导入规范显式记录，不能根据视觉大小猜测；非均匀正缩放正确应用于顶点和法线，零值、负值与非有限缩放拒绝。

有 visual 的实体缺失 collision 时默认报错；纯坐标 link 可没有几何。允许用户显式开启 visual 到 collision 的替代，但兼容性报告必须列明替代 link 及性能影响。传感器表面按 `sensor_geometry` 覆盖配置选择，否则使用 visual；若 visual 缺失，可显式选择 collision，禁止无提示替代。

导入报告至少包含源文件与资源哈希、根 link、关节数量、支持类型、忽略扩展、缺失资源、几何边界、单位与缩放、碰撞替代和传感器绑定结果。错误必须指出文件与元素名称。

仿真器维护关节状态；robot_state_publisher 根据相同 URDF 和 `joint_states` 发布机器人内部 TF。固定关节使用静态 TF，活动关节根据状态更新；仿真器不得重复发布这些变换。[robot_state_publisher](https://github.com/ros/robot_state_publisher/blob/humble/README.md)

区分导入模型的 `root_link` 和运动参考 `base_link`。两者相同时，里程计发布 `odom → base_link`；例如根为 `base_footprint` 时，里程计发布 `odom → base_footprint`，URDF 发布 `base_footprint → base_link`。根位姿由运动参考位姿和内部变换换算，不能同时再给 base_link 增加一个 odom 父节点。里程计消息本身仍可用 base_link 作为 child_frame，但 TF 发布路径必须按实际树计算。

URDF 导入不等于任意机器人都能执行有效运动。根运动由差速或理想 Ackermann 模型控制；驱动轮及 mimic 关节更新，其他活动关节保持配置初值。不执行 URDF 中的插件或外部动力学控制器。

## 场景与几何

场景配置包含版本、单位、实体唯一标识、资源、世界位姿、显示几何、碰撞几何、传感器表面和可支撑表面属性。基本场景支持地面、墙、立柱、坡面、悬空物和网格。

静态几何建立空间索引并复用。射线返回量程内最近的有效交点；场景表面默认双面参与测距，避免薄墙因法线方向被漏掉。退化三角形、非法索引和非有限顶点要在导入时拒绝或按明确规则过滤并计数。

传感器默认仅排除雷达自身外壳 link，机器人其他结构仍可遮挡雷达。另提供整机排除或指定 link 列表模式，记录在运行清单。碰撞与感知可以使用不同精细度的几何，但必须来自同一实体、同一姿态和同一采样时刻。

用于射线的空间索引不能自动保证机器人不穿墙。碰撞检查需覆盖整个机器人包络在一个步长内的扫掠运动，包括旋转导致的角点移动。可以采用连续碰撞算法或有证明约束的自适应子步；只检查步末包围盒不足以通过薄墙测试。

接触对分为声明的支撑接触和阻挡接触。轮子或声明支撑点与当前有效地面在容差内接触是允许状态；车体穿地、轮子撞墙或接触非支撑表面仍属于碰撞。不能整体忽略地面实体的碰撞，也不能把正常支撑接触当作必须停车的障碍。

## 机器人运动

差速模型接收机体前向速度和偏航角速度，具有限速、加速及减速约束。轮半径与轮距由机器人仿真配置给定并与 URDF 校验。理想模型在平地上满足：

```text
dx/dt = v cos(yaw)
dy/dt = v sin(yaw)
dyaw/dt = omega
wheel_left  = (v - omega * wheel_separation / 2) / wheel_radius
wheel_right = (v + omega * wheel_separation / 2) / wheel_radius
```

平地恒速测试使用解析圆弧解，避免仅用与实现相同的积分方法生成期望值。差速模型收到非零侧向或垂向指令时拒绝该命令并诊断；NaN、Inf、错误坐标或过期带时间命令不更新最后有效命令时间。

碰撞时退到不穿透的位置并停止运动，记录接触事件，不计算冲击或反弹。碰撞产生的速度不连续不能用于声称 IMU 真实冲击响应；相关样本应带有独立诊断并从连续轨迹精度测试中排除。

M2 以支撑点和连续地表选择约束高度、横滚和俯仰。机器人前向轴沿地面切向，机体竖直轴与局部支撑平面法向一致；保持配置的离地距离。必须从当前支撑层选择连续可达表面，不能直接取最高表面或最近表面导致跳到桥面。

初始测试配置允许最大坡度 20°，垂直台阶默认不可通行。悬空、超坡度或无法建立稳定支撑时停止并诊断；楼梯和轮胎越障能力不在该地形模型内。坡面接缝的姿态变化要有连续性策略，IMU 精度测试使用至少二阶连续的参考轨迹。

## 三维激光模型

基准雷达为 32 线、每线 1024 个水平采样、10 Hz；垂直角逐线给出，水平角按配置范围采样，整圈扫描不重复 0° 与 360° 的同一列。另验证 16 线、64 线及非均匀垂直角。机械扫描以外还支持球面带、花瓣近似和 Mid-360 官方扫描表；具体时序、裁剪和近似范围见 [雷达配置说明](../../examples/wheel_car_4w/雷达配置说明.md)。

瞬时扫描以一个时刻的世界状态计算整帧，逐点相对时间为 0。M2 滚动扫描的第 i 点在 `t_i = t_start + offset_i` 采样；offset 由列时间与逐线发射延迟组成，必须满足 `0 <= offset_i < scan_period`。完整帧只能在其全部采样已经完成后发布。

默认原始滚动点云的每点坐标使用该点采样时刻的雷达局部坐标，表示未去畸变的原始扫描。`header.stamp = t_start`，`header.frame_id = lidar_link`；接收算法必须利用逐点时间处理扫描内运动，不能假定所有点都在帧起点采样。

仅用于验证的去畸变参考将点变换到帧起点雷达坐标：

```text
p_reference_i = inverse(T_WL(t_start)) * T_WL(t_i) * p_raw_i
```

参考计算使用独立解析轨迹。真值去畸变结果放在评测通道，不能默认为被测算法输入。动态障碍启用后，每个交点也必须使用 `t_i` 的障碍状态。

量程区间为闭区间 `[min_range, max_range]`。先判断最近物理表面：如果最近表面位于盲区内，则报告无有效回波，不能穿过它去返回更远表面。没有交点也报告无回波，不伪造最大量程处的障碍点。

## PointCloud2 布局

以下为本项目规范布局。PointCloud2 的 fields 数组描述实际二进制布局，标准消息本身没有规定 ring 或 time 的固定命名与单位。[PointCloud2 定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/PointCloud2.msg)

| 字段 | 类型 | 字节偏移 | 语义 |
| --- | --- | --- | --- |
| x | FLOAT32 | 0 | 米 |
| y | FLOAT32 | 4 | 米 |
| z | FLOAT32 | 8 | 米 |
| intensity | FLOAT32 | 12 | 简化归一化反射值，范围 0 至 1 |
| ring | UINT16 | 16 | 从 0 开始的线号 |
| 保留字节 | 不声明为字段 | 18 | 两字节置零 |
| time | FLOAT32 | 20 | 相对帧起点秒数 |

采用小端序，`point_step = 24`，默认有序点云 `height = 线数`、`width = 每线采样数`、`row_step = width * 24`，`data.size = height * row_step`。按 ring 为行、水平采样为列排列。每行的 time 单调，但跨行展开后的 time 允许重新从较小值开始，不能误测为全数组时间倒退。

无回波或丢点保留原槽位，xyz 为 NaN、intensity 为 0，ring 和 time 保留；存在任何无效点时 `is_dense = false`。所有点有效时可为 true。算法适配器可以移除 NaN 并改为无序点云，或者按时间排序，但必须保持字段、采样时刻和索引语义一致。

噪声先作用于有效物理距离，再判断输出是否仍位于量程；越界样本转无回波，不钳制成边界假障碍。噪声和随机丢点拥有独立随机流。初期高斯测距噪声、固定偏置与伯努利丢点足够；intensity 表示配置反射率的简化输出，不能用来宣称复现材料光学特性。

## 里程计与 IMU

测量里程计根据执行后的底盘运动与显式误差模型生成，理想模式可与真值重合，误差模式允许偏置、尺度误差与随机扰动。算法评测必须注明模式，不能用理想里程计的表现代表存在漂移时的效果。

`odom` 消息的 pose 在 `header.frame_id` 指定的 odom 坐标中，twist 在 `child_frame_id` 指定的机体坐标中；协方差与配置的测量模型匹配，保留交叉项的约定。[Odometry 定义](https://github.com/ros2/common_interfaces/blob/humble/nav_msgs/msg/Odometry.msg)

IMU 加速度输出为传感器坐标下的比力：

```text
specific_force_I = transpose(R_WI) * (acceleration_WI - gravity_W)
gravity_W = [0, 0, -9.80665] m/s²
```

角速度以 rad/s 表示，并转换到 IMU 坐标。安装位置不在旋转中心时，传感器加速度须包含角加速度和向心项。静止、z 轴朝上且无噪声时应测得约 +9.80665 m/s²；这与 REP 145 的比力约定一致，该 REP 当前标记为 Draft，项目将上述行为显式固定为自己的接口约定。[REP 145](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst)

默认 raw IMU 不提供姿态估计，`orientation_covariance[0] = -1`。已知噪声写入相应协方差，不能用全零表示“完美测量”；标准消息将全零协方差解释为未知。[Imu 定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/Imu.msg)

连续轨迹用于产生可验证的惯性数据。瞬移、重置和不连续接触点处应中断扫描、清空导数历史并报告不连续事件，不用数值微分生成无穷大或巨大伪脉冲。

## ROS 2 话题与责任

下列相对话题位于机器人命名空间，`/clock` 和 `/sim/*` 为仿真级接口。可配置重映射，但不得改变字段含义。

| 方向 | 话题 | 类型 | 责任与约束 |
| --- | --- | --- | --- |
| 输入 | cmd_vel | geometry_msgs/msg/Twist 或 TwistStamped | 配置二选一；带时间模式明确超时和 frame 规则 |
| 输出 | points_raw | sensor_msgs/msg/PointCloud2 | 雷达原始采样 |
| 输出 | imu/data_raw | sensor_msgs/msg/Imu | M2 原始惯性测量 |
| 输出 | odom | nav_msgs/msg/Odometry | 测量里程计 |
| 输出 | joint_states | sensor_msgs/msg/JointState | 仿真关节状态 |
| 输出 | /clock | rosgraph_msgs/msg/Clock | 整个仿真只有一个发布者 |
| 输出 | /sim/status | diagnostic_msgs/msg/DiagnosticArray | run_id、状态、丢帧、错误和性能摘要 |
| 输出 | /sim/ground_truth/robot_0/odom | nav_msgs/msg/Odometry | world 中的真值，仅评测可订阅 |
| 输出 | /sim/ground_truth/robot_0/contacts | `litesim3d_interfaces/msg/Contact` | 评测接触次数及真实最小距离 |

服务为 `/sim/pause`（SetBool）、`/sim/step`（Step）、单机 `/sim/set_pose`（SetPose）以及由 `sim_session` 提供的 `/sim/reset`（Reset）。单步和重置使用 request_id 保证相同载荷重试的幂等性；具体请求与响应以 [srv 定义](../../litesim3d_interfaces/srv) 为准。

M3 多机入口按机器人 ID 给命令、传感器和 odom 添加命名空间与 frame 前缀；支持 Twist/带时间戳命令、传感器可靠性选择、逐机器人外部 odom TF 接管及冲突检测。具体参数和诊断语义见 [M3 使用说明](M3使用说明.md)。Contact 的 header 为 world/仿真时间，附 run_id、robot_link、entity、clearance；接口原文见 [Contact.msg](../../litesim3d_interfaces/msg/Contact.msg)。协调重置接口见 [Reset.srv](../../litesim3d_interfaces/srv/Reset.srv)，由 M2 单机会话管理器提供。

传感器默认可采用 best effort、volatile、小深度队列，允许配置可靠模式以配合特定算法。控制使用 reliable 和有界队列；`/clock` 默认 best effort、volatile、深度 1；TF 使用 tf2 推荐配置。对可靠与尽力而为两侧不兼容的组合必须有诊断与测试，不能把无消息误判为传感器未产生数据。

里程计到机器人根的 TF 只能由仿真测量里程计或外部估计器之一发布，通过 `publish_odom_tf` 选择；根为 base_link 时即 `odom → base_link`，其他根遵循前述换算规则。机器人内部 link 变换由 robot_state_publisher 发布，`map → odom` 由定位或建图节点发布。节点命名空间不会自动为 TF frame 加前缀，启动配置必须同时处理 frame 名称。

启用估计器接管 TF 时，点云仍在传感器局部坐标产生，世界几何与评测继续使用仿真内部真值。默认关闭任何会将真值位姿直接写入算法 TF 的调试选项。
