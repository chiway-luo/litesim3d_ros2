# 配置文件

适用版本以仓库 [VERSION](../../VERSION) 为准。本文按当前源码整理；操作步骤见 [使用手册](../usage/README.md)。

## 配置入口与优先级

| 入口 | 机器人与传感器来源 | 场景/计时来源 |
| --- | --- | --- |
| 推荐：组合模型 + SDF | launch 的 robot_urdf 指定组合 URDF/Xacro；扩展声明选择插件 | SDF 世界；runtime 绑定碰撞/支撑与核心选项 |
| 组合模型 + YAML 场景 | 已展开 URDF 的插件声明 | 单机 YAML 的 entities/simulation |
| 兼容：无扩展的 URDF + YAML | robot.drive、odom、lidars、imus、cameras | 单机 YAML |
| 共享世界 YAML | config 引用同一单机配置，robots 提供各实例位姿 | 公共场景、统一时钟 |

插件优先级：实现 `defaults()` < 按声明顺序的参数文件 < 实例 overrides；映射递归合并，数组整体替换。插件完整参数与必填项见 [插件接口](插件接口.md#parameter-files)。下面的旧 YAML 默认值不替代插件 defaults。

URDF 声明 chassis 时禁止同时写旧 `robot.drive` / `robot.motion_model`；声明 odometry 时禁止旧 `odom`；声明任意 sensor 时旧 `lidars`、`imus`、`cameras` 必须全部为空或省略。没有 sensor 扩展的旧列表会转成标准传感器插件。配置拼错的字段、重复键和非法数值会报错。

<a id="noise-config"></a>
## 测量误差文件：`noise_config`

由通用/车型 launch 的 `noise_config:=` 或 `prepare_config --noise-config` 读取独立 YAML。默认空值，不追加覆盖；标准插件、车型默认配置和雷达预设的误差均为 0。文件可以使用 package URI 或文件路径；相对路径相对于 runtime/config YAML 所在目录，建议使用绝对路径。

顶层只接受 `odometry`、`sensors` 两个映射。`odometry` 对应唯一的标准差速、Ackermann 或全向轮里程计插件；无该插件时拒绝，旧模型应使用本页的 `odom` 节。`sensors` 是传感器实例名到误差参数的映射，支持标准插件及旧 `lidars/imus/cameras` 列表。不接受 link、topic、频率、enabled 等非误差字段。

应用次序：插件默认值 < 声明的参数文件 < 模型 overrides < 雷达预设 < `noise_config`。后者只覆盖列出的字段，不清空未列参数。数组整体替换，重复 YAML 键报错；未知实例或不属于该传感器类型的字段报错。数值约束由实际插件初始化校验，错误会导致启动失败。最终值进入展开后的模型/配置及运行 manifest。

| 目标 | 字段 | 默认 | 单位 / 约束 |
| --- | --- | --- | --- |
| `odometry` | `linear_scale_error` | `[0,0]` | 车体 x/y 速度相对误差，各项有限且 >−1；0.02 表示 +2% |
| `odometry` | `angular_scale_error` | 0 | yaw 速度相对误差，有限且 >−1 |
| `odometry` | `linear_bias_mps` / `linear_sigma_mps` | `[0,0]` / `[0,0]` | x/y 速度偏移与每次解算标准差，m/s；sigma ≥0 |
| `odometry` | `angular_bias_radps` / `angular_sigma_radps` | 0 / 0 | yaw 速度偏移与每次解算标准差，rad/s；sigma ≥0 |
| LiDAR | `range_bias_m` / `range_sigma_m` | 0 / 0 | 每点量程固定偏移与高斯标准差，m；sigma ≥0 |
| LiDAR | `dropout` | 0 | 人工额外丢点概率，[0,1] |
| IMU | `accel_bias` / `accel_sigma` | `[0,0,0]` / `[0,0,0]` | 传感器 xyz 加速度偏移与每样本标准差，m/s²；sigma ≥0 |
| IMU | `gyro_bias` / `gyro_sigma` | `[0,0,0]` / `[0,0,0]` | 传感器 xyz 角速度偏移与每样本标准差，rad/s；sigma ≥0 |
| RGB / RGB-D | `color_bias_dn` / `color_sigma_dn` | `[0,0,0]` / `[0,0,0]` | RGB 像素偏移与每像素标准差，DN；sigma ≥0，输出取整并裁剪到 [0,255] |
| Depth / RGB-D | `depth_bias_m` / `depth_sigma_m` | 0 / 0 | 深度偏移与每像素标准差，m；sigma ≥0，超量程变为 NaN |

偏移可正可负，所有数值必须有限。理想输出由实际运动/几何计算，再按 `测量 = 理想值 × (1 + 比例误差) + 固定偏移 + sigma × N(0,1)` 注入误差；比例误差目前只用于轮式里程计，其余传感器倍率为 1。里程计对扰动后的速度积分。雷达、深度相机仍执行量程/无效点规则；IMU 的量程裁剪另由其参数控制。

插件的旧 `linear_scale` / `angular_scale` 倍率继续兼容，理想值为 1；不可把旧倍率设为 0。非默认旧倍率不能与相应非零 `*_scale_error` 同时使用。独立误差文件只接受上表的新比例误差字段，旧倍率仅在原插件配置中维护。

完整操作与四轮车预设见 [传感器配置](../usage/传感器配置.md)。其他模型按实际实例名配置，例如包含深度相机的模型：

```yaml
sensors:
  depth_camera:                  # 替换为实际 sensor name
    depth_bias_m: 0.0
    depth_sigma_m: 0.0
  rgbd_camera:
    color_bias_dn: [0.0, 0.0, 0.0]
    color_sigma_dn: [0.0, 0.0, 0.0]
    depth_bias_m: 0.0
    depth_sigma_m: 0.0
```

<a id="sdf-runtime"></a>
## SDF runtime

来源：[示例 runtime](../../examples/wheel_car_4w/wheel_car_4w_sim/config/runtime.yaml)、[导入器](../../litesim3d_assets/src/sdf_import.cpp)。

`schema_version: 1`、`units: m_rad_s` 固定。源 runtime 的 `robot.urdf` 可留空，由 launch 的 `robot_urdf` 动态传入；也兼容 YAML 内已有的模型路径。下面所述的 `robot.urdf` 指准备器生成的运行配置中的最终值。`robot.id` 必须匹配受控 SDF 模型；有 `robot.urdf` 时组合模型提供完整机器人，同名 SDF model 提供 root 出生位姿。没有该字段时使用 SDF 机器人几何与旧 YAML 绑定。`entity_bindings` 以场景实体名配置 support、reflectivity 等绑定，不能创造新的场景实体。

组合模型已在 URDF 声明 mimic；此模式禁止 runtime 的 `mimic_joints`。不提供组合 URDF 的兼容 SDF 入口可用该映射绑定 mimic 关系。

runtime 不得重复写 `entities`、`robot.initial_pose`、`simulation.step_size`、`simulation.real_time_factor`；这些来自 SDF，目标倍速可由 launch 显式覆盖。参数冲突会拒绝导入。展开/导入产物是运行输入，不应回写到原模型。

<a id="core-robot"></a>
## 组合模型的 robot 核心字段

| 字段 | 默认 / 约束 |
| --- | --- |
| `id` | robot_0；单机诊断/真值标识，不自动创建 namespace |
| `urdf` | 运行配置必填（SDF 直接建模入口除外）；源 YAML 可留空，由 launch 的 `robot_urdf` 传入并经 prepare_config 展开 |
| `base_link` | base_link；必须存在且与 root 固连 |
| `continue_on_collision` | false；车体受阻时是否继续提交编码器位移 |
| `support_links` | 底盘支撑 link 列表，与实际轮子及 collision 一致 |
| `initial_joints` | 关节初值映射，满足限位和 mimic；SDF 初值以导入规则为准 |
| `visual_collision_fallback` | false；显式允许机器人缺 collision 时使用 visual |
| `sensor_geometry` | visual；可选 collision |
| `sensor_overrides` | link → visual/collision 覆盖 |

`continue_on_collision` 与 `support_links` 在新配置中直接位于 robot；旧配置允许放在 robot.drive 内，同一选项重复声明会拒绝。轮径、轮距、轮关节和限制属于插件参数，不写在本节核心字段中。

<a id="simulation"></a>
## `simulation`

| 字段 | 默认 | 单位/范围/说明 |
| --- | --- | --- |
| `control_mode` | `twist` | `twist` 接收原有车体速度；`ros2_control` 接收硬件适配器的关节/机体指令；轮式底盘实现 JointDrivenChassis，multicopter 使用机体 GPIO |
| `step_size` | 0.005 | 秒，[1e-9,0.1]；转换成整数纳秒，决定运动积分步长 |
| `seed` | 42 | uint64 随机种子；影响测量噪声和 dropout |
| `odom_rate` | 50 | Hz，(0,1000]，按仿真时间 |
| `command_timeout` | 0.5 | 正数，仿真秒；有效车体/关节命令看门狗 |
| `real_time_factor` | 1.0 | [0,100]；1 为目标实时，0 为尽快运行；ROS 节点的墙钟节拍 |
| `collision_budget_enabled` | false | 碰撞复杂度预算；SDF launch 可覆盖，关闭仍执行碰撞检测 |
| `threads` | 1 | 整数 1–4，射线工作线程预算 |
| `history_limit` | 8192 | 轨迹状态数，[4,65536]；rolling/多机按采样事件率预检所需历史 |
| `journal_limit` | 4096 | 最近命令/接触日志容量，[1,65536]；截断量另行计数 |

传感器频率是仿真频率。例如 RTF=0.5 时，10 Hz 雷达在墙钟每秒约有 5 帧；硬件过载时实际 RTF 还会下降。降低步长会提高运动积分开销，也会增加 rolling 历史需求。

<a id="legacy-robot"></a>
## 兼容 YAML：robot 与 drive

以下仅适用于未声明 chassis 插件的模型。根配置要求 `schema_version: 1`、`units: m_rad_s`、robot 和 entities；旧传感器路径要求非空 lidars。各参考值是解析器默认值，示例文件可能覆盖。

### `robot`

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `id` | `robot_0` | 单机真值/诊断标识；**不会自动创建 ROS namespace** |
| `urdf` | 必填 | URDF 路径或资源 URI |
| `base_link` | `base_link` | 运动参考 link，须存在并与 root 固连 |
| `motion_model` | `differential_drive` | 兼容路径另支持 `ackermann` 和 `multicopter`；全向底盘通过插件声明选择；无人机规则见 [无人机示例](../../examples/drone_3d/README.md) |
| `initial_pose.xyz` | `[0,0,0]` | 世界初始位置，米 |
| `initial_pose.rpy` | `[0,0,0]` | 世界初始姿态，弧度；关闭地形时必须水平 |
| `initial_joints` | `{}` | 关节名→初值，转动为弧度、移动为米；满足关节限位/mimic 约束 |
| `visual_collision_fallback` | false | 显式允许缺 collision 时用 visual 替代 |
| `sensor_geometry` | visual | 机器人被射线查询的几何：visual/collision |
| `sensor_overrides` | `{}` | link 名→visual/collision；按 link 覆盖 |
| `drive` | 见下表 | 与 URDF 驱动几何一致 |

### `robot.drive`

| 字段 | 默认 | 单位/约束 |
| --- | --- | --- |
| `wheel_radius` | 0.1 | m，>0，与两驱动轮半径一致 |
| `wheel_separation` | 0.5 | m，>0，与两轮原点距离一致 |
| `left_joint` / `right_joint` | left_wheel_joint / right_wheel_joint | 不同且存在的连续驱动关节 |
| `support_links` | `[left_wheel,right_wheel]` | 可作为支撑接触处理的 link 集合 |
| `max_v` | 1.0 | m/s，>0，线速度绝对值上限 |
| `max_w` | 2.0 | rad/s，>0，角速度绝对值上限 |
| `acceleration` | 0.5 | m/s²，>0 |
| `deceleration` | 1.0 | m/s²，>0 |
| `angular_acceleration` | 2.0 | rad/s²，>0 |
| `unlimited_acceleration` | false | true 时跳过加速度限幅；各加速度字段仍须为正 |
| `continue_on_collision` | false；小车示例为 true | 碰撞后车体停住，驱动轮、mimic 和平面轮式里程计继续累计；适用于差速/Ackermann，仍遵守限速、加减速、超时和暂停 |
| `wheelbase` | 1.0 | m，>0；Ackermann 轴距，差速模式下也检查合法性 |
| `max_steering_rad` | 0.6 | 弧度，严格在 (0,π/2) 内；Ackermann 最大转角 |

差速轮速按 `ω左=(v−ω×wheel_separation/2)/wheel_radius`、`ω右=(v+ω×wheel_separation/2)/wheel_radius` 计算。配置的半径和轮距同时影响运动与关节状态，应与模型匹配。

启用 `continue_on_collision` 后，`/odom`、odom TF 和里程计路径使用轮速积分，车体受阻时仍继续；真值里程计、激光、相机和 IMU 保持真实受阻状态。此时 `odom.mode: ideal` 只表示没有测量误差，碰撞造成的轮式里程计漂移仍存在。倒车可脱离障碍；地形失去支撑等错误仍停止驱动；新会话或 reset 清除累计漂移。参数示例见[四轮小车说明](../../examples/wheel_car_4w/README.md)。

Ackermann 修改 `robot.motion_model: ackermann`，并设置 drive 下的 wheelbase/max_steering_rad。输入仍是 v/ω，满足：

```text
|ω| ≤ |v| × tan(max_steering_rad) / wheelbase
```

允许倒车；v=0 时不能原地转向。这里采用理想后轴参考点自行车模型，随附 R01 是等效后轴示例，不会自动建立真实前轮转向关节或悬架。

<a id="terrain"></a>
## 地形与场景

### 实体配置

`entities` 是单机配置根节点下的列表；必须存在，可以是空列表，最多 10000 个实体。ID 非空且唯一。下面是追加到列表中的一个实体：

```yaml
- id: obstacle_box
  pose: {xyz: [2.0, 1.0, 0.5], rpy: [0.0, 0.0, 0.3]}
  geometry: {type: box, size: [0.6, 0.6, 1.0]}
  reflectivity: 0.7
  support: false
```

| 字段 | 默认/要求 |
| --- | --- |
| `id` | 必填、唯一 |
| `pose.xyz` / `pose.rpy` | 缺省 `[0,0,0]`；世界坐标，分别为米和弧度 |
| `reflectivity` | 0.5，范围 [0,1]，作为合成激光强度 |
| `support` | false；true 表示候选支撑面，不表示所有碰撞都忽略 |
| `geometry` | 一个形状同时用于显示、碰撞和雷达 |
| `visual`、`collision`、`sensor_geometry` | 不能再混用 `geometry`；旧 YAML 中缺 collision 时使用 visual 作为碰撞几何 |
| `motion` | 兼容旧配置：校验后忽略，障碍物始终固定，实体 ID 记录到 ignored_entity_motion |

支持的 geometry：

```yaml
{type: box, size: [1.0, 2.0, 0.5]}
{type: sphere, radius: 0.3}
{type: cylinder, radius: 0.3, length: 2.0}
{type: mesh, uri: ../meshes/room.obj, scale: [1.0, 1.0, 1.0]}
```

以上四行是四种**替代写法**，分别作为某个 geometry 的值，不要原样拼成一份根配置。尺寸、半径、长度、scale 必须是正数；圆柱轴沿实体局部 z。实体 pose 再把形状变换到世界坐标。

显示高精度网格、碰撞低成本包围盒的例子：

```yaml
- id: machine
  pose: {xyz: [4, 3, 1]}
  visual: {type: mesh, uri: ../meshes/machine.stl, scale: [1, 1, 1]}
  collision: {type: box, size: [2, 1, 2]}
  sensor_geometry: {type: mesh, uri: ../meshes/machine.stl, scale: [1, 1, 1]}
```

这个片段要求你提供真实存在的 `machine.stl`。简化 collision 会改变通行空间，应以实际需要选取。

### 平地与连续坡面

平地示例：box 大小 `[30,30,0.2]`，中心 `[0,0,-0.1]`，上表面 z=0，`support: true`。未启用 terrain 时，支撑必须是未旋转且上表面 z=0 的轴对齐 box。

启用连续坡面，在根配置中设置：

```yaml
terrain:
  enabled: true
  max_slope_deg: 20.0
  clearance_m: 0.0
  continuity_m: 0.02
```

| 参数 | 默认与范围 | 实际作用 |
| --- | --- | --- |
| `enabled` | 整个 terrain 缺省时 false | 若写了 terrain 映射但省略 enabled，解析器默认 **true**；建议总是显式填写 |
| `max_slope_deg` | 20，严格在 (0,90) 内 | 可通行支撑坡度上限，过陡会停住 |
| `clearance_m` | 0，≥0 | base 参考点相对支撑面的高度偏移，不是车体最低点间隙 |
| `continuity_m` | 0.02，(0,0.1] m | 连续层高度关联范围，不是允许攀爬的台阶高度 |

支撑来自 `support: true` 实体的 **collision**：箱体局部上表面，或朝上的 mesh 三角面。多层场景按前一支撑高度关联；桥底、立面等其他碰撞仍存在。网格三角形法向需朝上。

机器人支撑采样由 URDF 中 `drive.support_links` 对应的 collision 几何确定：圆柱轮检查轮宽中心及两侧边缘，所有声明轮子都必须有支撑。该列表不能遗漏前轮或 mimic 轮，也不能包含没有 collision 的 link；更改轮距后采样位置随模型变化。球形和其他形状的采样规则见 [坐标与模型约定](坐标与模型约定.md#terrain)。

测试单一斜面时，可以将原地面替换为下列 5° 倾斜 box，并开启 terrain。示例起点保留 `[0,0,0]`，不要同时保留原水平地面覆盖斜面：

```yaml
- id: slope_ground
  pose: {xyz: [0, 0, -0.1], rpy: [0, -0.0872664626, 0]}
  geometry: {type: box, size: [30, 30, 0.2]}
  support: true
```

实际道路使用连续坡面或平滑网格。机器人会跟随支撑高度和法向调整 z/roll/pitch；遇到空洞、台阶、坡度或连续性超限会停止，不会自由落体或自动爬阶。拼接处的不光滑加速度不能当作真实车辆悬架响应。

### 固定障碍物

所有通过场景配置加载的障碍物固定在声明的初始位姿，不计算障碍物移动、受力或反弹。旧 YAML 中的 `motion.linear_velocity` 和 `motion.yaw_rate` 校验后忽略；manifest 的 `config.ignored_entity_motion` 列出受影响实体，便于识别旧配置。SDF 中未绑定为受控机器人的模型也固定在初始位姿。

显式 collision 继续作为障碍碰撞几何；SDF 场景 link 缺少 collision 时使用该 link 的 visual 补齐，旧 YAML 的独立角色实体缺 collision 时使用 visual。使用高精度 visual 补齐会增加碰撞计算开销，可通过显式 collision 提供合适的简化模型。

当前 ROS 接口没有在线增删障碍或更换场景服务，修改配置后启动新会话。

<a id="lidars"></a>
## 兼容 YAML：lidars

插件模型请将对应字段放在 sensor 实例参数中，实例名来自 XML 的 name，不再使用独立 rings 或 point_layout 参数；标准雷达以 vertical_angles_deg 数组长度推导 rings。

每个配置必须有 1–16 个雷达。所有雷达、IMU 与相机的 name 和实际输出 topic 必须彼此唯一。多机时 topic 必须是相对名称，如 `points_raw`。

| 字段 | 默认 | 单位/约束 |
| --- | --- | --- |
| `name` | 必填 | 传感器标识，也参与确定性随机流 |
| `link` | 必填 | URDF 中实际存在的传感器 link，安装外参由 URDF 决定 |
| `topic` | points_raw | PointCloud2 输出话题 |
| `rate_hz` | 10 | Hz，(0,1000]，扫描帧率 |
| `columns` | 1024 | spinning为每线水平列数，其他模式为每帧点槽数；整数 1–65536 |
| `vertical_angles_deg` | spinning必填 | 按 ring 顺序给出角度，范围 [-90,90]°；其他模式只能省略或填 `[0]` |
| `rings` | 角度数组长度 | spinning与数组长度一致；非重复模式固定1，ring字段为兼容占位 |
| `min_range_m` | 0.1 | m，≥0 |
| `max_range_m` | 100 | m，严格大于最小量程 |
| `publish_range_boundary` | false | 开启后额外发布`<topic>/range_boundary`，用于显示无命中射线的最大量程终点；四轮车 Mid-360 预设默认关闭，其他预设见各自 YAML |
| `horizontal_start_deg` | -180 | 水平起点角度 |
| `horizontal_end_deg` | 180 | 严格大于起点，总跨度≤360°；采样区间左闭右开 |
| `scan_mode` | snapshot | snapshot / rolling |
| `scan_pattern` | spinning | spinning / spherical / rosette / livox_mid360；旧配置行为保持兼容 |
| `pattern_file` | 无 | 仅livox_mid360必填；package URI、绝对路径或相对配置路径 |
| `vertical_min_deg/max_deg` | spherical: -90 / 90；livox_mid360: -7 / 52 | −90≤下界<上界≤90；前者生成轨迹，后者只裁剪原始方向 |
| `cone_half_angle_deg` | 19.2 | 仅rosette，(0,90]，圆锥全张角为2倍 |
| `pattern_hz` | 100 | 仅spherical/rosette，(0,10000]；点率≥4×√2×基频；仿真假设，不是厂家镜片转速 |
| `point_layout` | xyzirt_v1 | 当前原始输出只支持这一布局 |
| `self_filter` | sensor_link | sensor_link / robot / links |
| `excluded_links` | `[]` | 额外排除的自身 link，必须存在 |
| `ring_delays_s` | `[]`，等价各线 0 | spinning非空时与rings等长；每项≥0且小于一个列周期；其他模式必须为空 |
| `range_bias_m` | 0 | m，有限的固定偏置，可正可负 |
| `range_sigma_m` | 0 | m，≥0，每点独立高斯标准差 |
| `dropout` | 0 | [0,1]，有效回波丢点概率 |

单雷达以及所有雷达合计点槽位不得超过4194304。每个雷达按`rings × columns`计数，开启`publish_range_boundary`时按两份计入；单步输出内存预算也包含辅助点云。实际负载约随点数×帧率×机器人数量增长。

`livox_mid360` 必须满足 `columns × rate_hz = 200000`，默认10 Hz/20000槽；20 Hz改为10000槽。官方表位于 `package://litesim3d_core/lidar_patterns/mid360.csv`，包含80万方向，4秒后循环；更改封帧频率不改变方向顺序。水平/垂直边界仅屏蔽原有方向，裁掉的槽位保留NaN与逐点时间。文件最大64 MiB、最多200万行，解析结果共享且只读；manifest记录实际哈希、行数及循环周期。[来源、MIT许可与建模限制](../../litesim3d_core/resources/lidar_patterns/README.md)

`sensor_link` 排除当前传感器 link；`robot` 排除整个自身机器人；`links` 只按 excluded_links 排除。多机下这不会让其他机器人消失，其他机器人按 collision 几何参与感知。

例如第二个雷达需要 URDF 中已有 `rear_lidar_link`，然后在 lidars 列表中追加独立 name、link、topic 和角度数组。仅改 YAML link 名不会创建安装坐标系。

示例 launch 选择 Mid-360 时默认仅将该雷达的 ROS 点云改为官方 `livox_ros_driver2/msg/CustomMsg`，话题 `/livox/lidar`；其他雷达与 IMU 不变。`xfer_format:=0` 选择官方 PointCloud2，`lidar_interface:=native` 保留原生有序槽位布局。字段、逐点时间和最远距离辅助话题见 [Mid-360 数据接口](传感器数据.md#livox)。

<a id="imus"></a>
## 兼容 YAML：imus

不写 imus 表示没有 IMU；最多 16 个。向根配置加入：

```yaml
imus:
  - name: imu
    link: base_link
    topic: imu/data_raw
    rate_hz: 200
    accel_bias: [0.01, 0.0, 0.0]
    gyro_bias: [0.0, 0.0, 0.001]
    accel_sigma: [0.02, 0.02, 0.02]
    gyro_sigma: [0.001, 0.001, 0.001]
```

| 字段 | 缺省 | 单位/说明 |
| --- | --- | --- |
| name / link / topic | imu / base_link / imu/data_raw | 多个 IMU 必须显式区分名称和话题 |
| accel_range_mps2 / gyro_range_radps | 0 / 0 | 可选对称量程；0 不裁剪；单位 m/s²、rad/s |
| rate_hz | 200 | (0,2000] Hz |
| gravity_mps2 | 9.81 | 世界 −Z 重力大小，m/s²，有限且 >0；启动时读取，与 FAST-LIO 默认值对齐 |
| accel_bias | `[0,0,0]` | m/s²，传感器三轴固定偏置 |
| gyro_bias | `[0,0,0]` | rad/s，传感器三轴固定偏置 |
| accel_sigma | `[0,0,0]` | m/s²，非负的每样本标准差 |
| gyro_sigma | `[0,0,0]` | rad/s，非负的每样本标准差 |

sigma 是每样本噪声标准差，不是噪声密度；当前没有 bias random walk 参数。输出考虑世界重力、安装旋转、角加速度和偏心向心项。零噪声、水平静止、安装轴一致时，线加速度应约为 `[0,0,9.81]`，角速度约为零。

raw IMU 不提供姿态估计，`orientation_covariance[0]=-1`；不要把消息中的占位单位四元数当作测得姿态。已知噪声方差填入加速度/角速度协方差对角线；全零协方差表示未声明不确定性，不应直接解释为真实无误差传感器。

<a id="odom"></a>
## 兼容 YAML：odom

仅适用于没有 odometry 插件的模型。插件轮式里程计的误差参数使用各自独立配置文件。

```yaml
odom:
  mode: noisy
  linear_scale_error: 0.01
  angular_scale_error: 0.0
  linear_bias: 0.0
  angular_bias: 0.001
  linear_sigma: 0.005
  angular_sigma: 0.002
```

| 字段 | 默认 | 单位/说明 |
| --- | --- | --- |
| mode | ideal | ideal / noisy |
| linear_scale_error / angular_scale_error | 0 / 0 | 有限且 >−1，无量纲；0.01 表示 +1% |
| linear_scale / angular_scale | 1 / 1 | 兼容旧倍率，正数；不能与相应非零 scale_error 混用 |
| linear_bias / angular_bias | 0 / 0 | m/s、rad/s 的速度偏置 |
| linear_sigma / angular_sigma | 0 / 0 | 非负的速度噪声标准差，m/s、rad/s |
| pose_covariance | 36 个 0 | 6×6 行主序，顺序 x,y,z,roll,pitch,yaw |
| twist_covariance | 36 个 0 | 同上，顺序 vx,vy,vz,wx,wy,wz |

`ideal` 模式不能配置非默认误差；要开启误差须同时改为 noisy。误差在里程计通道积分，世界真值、碰撞、激光和 IMU 的真实运动不随之改变。里程计协方差由用户显式声明，不会根据 sigma 自动传播成位置协方差。

两种协方差如提供，都必须有 36 个有限值，矩阵对称且半正定。可用下面代码构造仅对角线非零的 YAML 列表，再放入 `odom.pose_covariance` 或 `twist_covariance`：

```python
diagonal = [0.01, 0.01, 0.01, 0.001, 0.001, 0.001]  # 方差，按实际模型选择
covariance = [diagonal[row] if row == col else 0.0
              for row in range(6) for col in range(6)]
```

odom 的 pose 在局部 odom 坐标系中，twist 在机器人 base_link 中。world 初始位置与 odom 原点不相同，不能直接将二者坐标数值逐项比较；离线评测需先明确固定初始对齐。

<a id="cameras"></a>
## 相机参数

组合模型的类与参数文件分别选 RGB、Depth 或 RGB-D 包；插件参数没有 `type`，实例 name 来自声明。兼容 YAML 的 `cameras[]` 增加 `name` 和 `type` 字段，type 缺省 rgb；不允许与模型 sensor 声明混用。

| 字段 | 标准插件默认 | 范围 / 语义 |
| --- | --- | --- |
| link / topic | 必填 | 已有 optical link / 相对话题前缀 |
| enabled | true | 小车实例显式覆盖为 false |
| width / height | 640 / 480 | 各 [16,4096]；每台像素 ≤8294400 |
| rate_hz | 15 | (0,240] 仿真 Hz |
| horizontal_fov_deg | 70 | (0,180)° |
| near_clip_m / far_clip_m | 0.1 / 20 | 0 < near < far，米 |
| color_bias_dn / color_sigma_dn | [0,0,0] / [0,0,0] | RGB 三通道 DN；sigma 非负，仅彩色类使用 |
| depth_bias_m / depth_sigma_m | 0 / 0 | 米；sigma 非负，仅深度类使用 |

最多 8 个相机，启用相机合计像素 ≤16588800。即使 enabled=false 也校验配置和挂载。图像模型与噪声处理见 [传感器数据](传感器数据.md#camera)。

<a id="world"></a>
## 共享世界 YAML

```yaml
schema_version: 1
config: robot.yaml
robots:
  - {id: r0, xyz: [0, 0, 0], rpy: [0, 0, 0]}
  - {id: r1, xyz: [0, 2, 0], rpy: [0, 0, 0]}
```

config 是单机配置路径，可相对 world 文件或用 package URI。机器人 1–4 台，ID 唯一，匹配 `[A-Za-z][A-Za-z0-9_]*`。各初值覆盖公共配置的 initial_pose；每台机器人 odom 从自己的初始位姿开始计零。共用模型、传感器和驱动参数；传感器话题使用相对名称。初始碰撞会拒绝，模型 collision 几何总数上限为 256。启用相机不受此入口支持。

## 路径和加载限制

资源路径相对于声明它的 YAML/URDF 文件；package URI 从已加载的 ament 前缀解析。已知结构的未知键不能作为自定义元数据插入。复杂度预算表与 URDF/SDF 支持范围见 [坐标与模型约定](坐标与模型约定.md)。
