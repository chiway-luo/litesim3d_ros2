# 传感器插件阶段验证

2026-10-19，macOS arm64 / RoboStack ROS 2 Humble。本阶段在独立安装空间验证了五类传感器插件及旧 YAML 适配，不代表整个插件改造目标完成。原始四轮机械 URDF 保持未修改。

|---|---|
| 底盘、编码器及传感器插件契约 | 33/33 通过，其中 7 项覆盖五类传感器 |
| 核心回归 | 173/173 通过 |
| ROS 运动插件与新传感器挂载、频率、碰撞真值 | 6/6 通过 |
| 真实 Ogre 渲染、RGB/深度/RGB-D、多个实例、测量偏差、碰撞真值 | 修复渲染资源路径后 1/1 通过 |
| SDF 资源与导入回归 | 27/27 通过 |
| 标准插件参数文件与 defaults 一致性 | 12 个具体实现包全部通过 |
| 外部里程计插件独立构建 | 通过；核心程序、核心共享库和 API 共享库 SHA-256 均不变 |
| 包版本与依赖图 | 版本一致；26 个正常构建包无依赖环 |

五个传感器包分别为 `litesim3d_lidar`、`litesim3d_imu`、`litesim3d_rgb_camera`、`litesim3d_depth_camera`、`litesim3d_rgbd_camera`。核心不链接其实现，使用 pluginlib 按声明加载；原有 YAML 列表会转换为同一插件运行路径。

测试覆盖：完整参数文件的键集合与默认值、缺失插件和安装 link、非法参数、重复名称与话题、传感器预算、独立频率、停用实例、真实挂载变换、滚动雷达轨迹、确定性噪声及 reset、IMU 偏差/量程/协方差、RGB 裁剪、深度 NaN/端序、旧 YAML 与插件输出一致性。相机算法单元测试使用构造像素；另有真实 Ogre + ROS 进程测试，不将两者混为同一种证据。

真实渲染测试同时启动两个 RGB、一个深度和一个 RGB-D 实例。撞墙后：

- 编码器里程计 x 为约 1.6 m。
- 真实车体 x 为约 0.34999 m。
- 无偏差深度为约 0.20001 m，来自受阻后的真实位姿。
- 配置 +0.2 m 偏差的 RGB-D 深度为约 0.40001 m。
- RGB 的 +10 DN 偏差生效；5 Hz 与 7 Hz 的图像时间戳独立且准确。

第一次图形测试受沙箱图形会话限制；获得图形访问权限后，测试又暴露出已安装 RoboStack 渲染库内资源路径的 NUL 填充问题，深度材质查找失败并崩溃。修复只为当前渲染进程补充 SDK 提供的有效资源路径，保留调用方的环境覆盖，并在资源缺失时明确报错，没有修改 ROS 环境或全局库。底层支持这个环境入口，可见 [Ogre2RenderEngine 源码](https://github.com/gazebosim/gz-rendering/blob/ign-rendering6/ogre2/src/Ogre2RenderEngine.cc)。失败日志与修复后成功日志分别保留，不把失败运行计为通过。
