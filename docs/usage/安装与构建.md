# Linux 安装与构建

## 环境要求

本文提供 **Linux / Ubuntu 22.04 LTS + ROS 2 Humble + Bash** 的开发与运行流程。构建需要 CMake ≥ 3.20、C++17 编译器、Python ≥ 3.10 和 colcon。

本页使用 Ubuntu 22.04 / Humble；其他平台需另行适配依赖。

| 模块 | 主要依赖 |
| --- | --- |
| 仿真内核 | Eigen3、urdfdom、Assimp、FCL、yaml-cpp、tinyxml2、OpenSSL、nlohmann_json |
| ROS 桥接 | PCL、rclcpp/rclpy、ROS 消息包、launch、robot_state_publisher、PyYAML |
| SDF 导入 | libsdformat12 |
| 三维查看器与相机 | ignition-rendering6 / Ogre2、Qt 5 Widgets、Qt 5 SVG，以及可用的图形环境 |
| 工具与测试 | RViz、Xacro、GTest、pytest、launch_testing、psutil |

## 安装依赖

先按 [ROS 官方 Ubuntu 安装说明](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html)安装 ROS 2 Humble，再在 Bash 终端准备构建工具并初始化 rosdep：

```bash
source /opt/ros/humble/setup.bash
sudo apt update
sudo apt install -y git build-essential cmake pkg-config ninja-build \
  python3-colcon-common-extensions python3-rosdep
if [ ! -f /etc/ros/rosdep/sources.list.d/20-default.list ]; then
  sudo rosdep init
fi
rosdep update --rosdistro humble
```

获取源码后执行下一节的 `rosdep install`，按各包 `package.xml` 安装仿真与 ros2_control 依赖。系统工具只需准备一次。

在新 Bash 终端检查基础环境：

```bash
source /opt/ros/humble/setup.bash
command -v ros2 colcon cmake
python3 -c 'import rclpy'
```

## 推荐方式：仓库构建脚本

在已激活 Humble 的 Bash 终端运行：

```bash
source /opt/ros/humble/setup.bash
git clone --branch humble https://github.com/chiway-luo/litesim3d_ros2.git
cd litesim3d_ros2
rosdep install --from-paths . --ignore-src --rosdistro humble -y
bash scripts/build.sh
source "$(python3 scripts/paths.py install)/setup.bash"
ros2 pkg prefix litesim3d_core
ros2 pkg executables litesim3d_ros2
```

构建完成后按[启动并控制小车](../tutorials/启动与控制.md)启动默认示例。教程使用 domain 70；同一仿真会话的终端应保持相同值。优先选择 0–101，以避开 Linux 的默认临时 UDP 端口范围，见 [ROS 2 domain 说明](https://github.com/ros2/ros2_documentation/blob/humble/source/Concepts/Intermediate/About-Domain-ID.rst)。

构建结果应显示所有包完成，且没有 failed；可执行文件包括 `sim_node`、`sim_world_node`、`sim_session`、`sim_ouster_adapter` 和 `sim_cloud_probe`。后续新终端先加载 `/opt/ros/humble/setup.bash`，再进入源码目录加载项目安装环境；无需重复构建。

脚本为所有包统一使用 `RelWithDebInfo` 和 merged install，并默认构建测试。构建树放到 `/tmp` 下按源码路径区分的 ASCII 目录，以避开 Humble 消息生成工具对中文构建路径的兼容问题。实际位置通过下列命令查询：

```bash
python3 scripts/paths.py artifacts
python3 scripts/paths.py install
```

单独 clone 时，产物入口默认在源码旁的 `litesim3d_ros2-artifacts/`；放在工作空间 `src/` 下时，默认在工作空间 `artifacts/`。其中 `build/`、`install/`、`log/` 指向实际构建树，`evidence/` 保存运行证据。临时目录被清理后重新构建即可。

需要固定位置时，可设置两个项目级变量；构建路径选用 ASCII 路径，后续终端继续使用同一个 `LITESIM3D_ARTIFACTS_DIR`：

```bash
export LITESIM3D_ARTIFACTS_DIR="$HOME/litesim3d-artifacts"
export LWS_BUILD_ROOT="$LITESIM3D_ARTIFACTS_DIR"
bash scripts/build.sh
source "$(python3 scripts/paths.py install)/setup.bash"
```

这些变量只影响本项目。切换基础 ROS 环境或构建目录时使用新终端，避免叠加旧安装前缀。

## 在自己的包中使用核心库

在使用方的 `package.xml` 声明 `<depend>litesim3d_core</depend>`，并在 CMake 中链接已安装的目标：

```cmake
find_package(litesim3d_core REQUIRED)
add_executable(my_sim main.cpp)
target_link_libraries(my_sim PRIVATE litesim3d_core::litesim3d_core)
```

头文件入口是 `#include <litesim3d/sim.hpp>`。目标会传递 C++17、公开头文件和链接依赖；不需要引用本仓库源码目录。先 source ROS 与项目安装环境，再用 colcon 构建使用方包。

直接调用普通 CMake 时，需通过 `CMAKE_PREFIX_PATH` 同时提供核心库和依赖的安装前缀，例如 `-DCMAKE_PREFIX_PATH="/path/to/litesim/install;/opt/ros/humble"`。`AMENT_PREFIX_PATH` 供 ament 包索引使用，不能替代普通 CMake 的搜索路径。

## 不使用图形界面

已完成默认构建时，直接关闭窗口和相机即可在终端运行：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py gui:=false cameras:=false
```

不需要查看器或相机时，也可以在首次构建时跳过 `litesim3d_gui` 包。基础 ROS 环境仍需激活：

```bash
LWS_BUILD_GUI=0 bash scripts/build.sh
source "$(python3 scripts/paths.py install)/setup.bash"
export ROS_DOMAIN_ID=70 ROS_LOCALHOST_ONLY=1
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py gui:=false cameras:=false
```

这种构建不提供相机节点。需要 RGB/深度数据时，应使用默认完整构建和可用的 Ogre2 图形后端；关闭窗口不会消除相机的渲染依赖。

## 已有 ROS 工作空间：标准 colcon

也可以把仓库放入现有工作空间 `src/`，使用标准 colcon。以下是独立示例，和前一节的脚本构建任选一种；先准备同样的依赖。

```bash
source /opt/ros/humble/setup.bash
mkdir -p ~/litesim3d_ws/src
cd ~/litesim3d_ws/src
git clone --branch humble https://github.com/chiway-luo/litesim3d_ros2.git
cd ~/litesim3d_ws
rosdep install --from-paths src --ignore-src --rosdistro humble -y
colcon build --base-paths src --merge-install --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo -DBUILD_TESTING=ON
source install/setup.bash
```

此方式的安装目录就是工作空间 `install/`，不会生成脚本的安装前缀记录，因此不要调用 `scripts/paths.py install`。继续[启动教程](../tutorials/启动与控制.md)时使用本工作空间的安装环境。工作空间包含中文路径时，使用前面的构建脚本。

## 无 ROS 桥接的内核构建

先完成默认构建并加载安装环境，确保 `litesim3d_plugin_api` 及需要的插件包可被发现。此入口不启动 ROS 节点，也不依赖 Qt/Ogre，但需要 ROS 的插件加载基础库。从仓库根目录执行：

```bash
cmake -S standalone -B /tmp/litesim3d-core -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/litesim3d-core --parallel 2
/tmp/litesim3d-core/litesim3d_core/sim_headless \
  "$PWD/litesim3d_core/resources/config/demo.yaml" 200 /tmp/litesim3d-run.json 0.4 0
```

它直接执行 200 个 5 ms 仿真步并输出运行清单，不启动 ROS 节点或图形界面。
