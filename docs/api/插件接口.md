# 插件接口

底盘、编码器里程计和五类传感器使用独立包，通过 pluginlib 在启动时加载。四轮差速、阿克曼、三轮及四轮全向示例使用组合 Xacro；文件分层、启动命令和旧 YAML 迁移见 [模型组合与插件迁移](../usage/模型组合与插件迁移.md)，验收范围见 [架构与验收](../design/插件架构与验收.md)。

## 独立实现包

| 包 | pluginlib 类名 | 运动或估计模型 |
|---|---|---|
| `litesim3d_diff_drive` | `litesim3d_diff_drive/DifferentialDrive` | 左右两组普通轮，允许同侧多个独立轮或 URDF mimic 从轮 |
| `litesim3d_ackermann_drive` | `litesim3d_ackermann_drive/AckermannDrive` | 后轴中点参考，四个轮关节及两个独立转向关节 |
| `litesim3d_omni3_drive` | `litesim3d_omni3_drive/Omni3Drive` | 三个普通全向轮，平面三自由度 |
| `litesim3d_omni4_drive` | `litesim3d_omni4_drive/Omni4Drive` | 四个普通全向轮，平面三自由度 |
| `litesim3d_diff_odometry` | `litesim3d_diff_odometry/DifferentialOdometry` | 左右轮编码器均值恢复线速度与角速度 |
| `litesim3d_ackermann_odometry` | `litesim3d_ackermann_odometry/AckermannOdometry` | 后轮编码器和前轮实际转角恢复运动 |
| `litesim3d_omni_odometry` | `litesim3d_omni_odometry/OmniOdometry` | 三轮或四轮编码器约束的最小二乘解 |
| `litesim3d_lidar` | `litesim3d_lidar/Lidar` | xyzirt 点云；旋转、球面、rosette、Mid-360 图案；瞬时或滚动扫描 |
| `litesim3d_imu` | `litesim3d_imu/Imu` | 安装轴向上的比力/角速度、偏差/噪声/对称量程 |
| `litesim3d_rgb_camera` | `litesim3d_rgb_camera/RgbCamera` | RGB8 图像、RGB 三通道偏差/噪声 |
| `litesim3d_depth_camera` | `litesim3d_depth_camera/DepthCamera` | 32FC1 光学 z 深度、米制偏差/噪声 |
| `litesim3d_rgbd_camera` | `litesim3d_rgbd_camera/RgbdCamera` | 同安装位姿和内参的 RGB 与深度通道 |

每个具体实现都在 `plugins/对应包/` 内，具有独立的 `package.xml`、共享库、`plugins.xml` 与完整 `config/parameters.yaml`。公共 API/计算库位于 `litesim3d_plugin_api`；核心不链接上述具体实现库。外部插件范例在 [external_plugins](../../examples/external_plugins/README.md)。

普通全向轮通过被动滚子允许垂直于滚动方向的自由运动。每轮约束为：

```
r * wheel_rate = cos(a) * vx + sin(a) * vy + (x * sin(a) - y * cos(a)) * wz
```

`x,y` 是轮中心在 base 中的位置，`a` 是正向滚动方向相对 +x 的逆时针角，轮正轴为 `[-sin(a),cos(a),0]`。示例三轮沿圆周相隔 120°；四轮是角点沿切向滚动的 X 布局。位置、方向、半径逐轮配置，算法检查矩阵满秩。麦克纳姆轮具有不同的斜滚子约束，不能通过把四个普通轮设为平行方向来替代，需要独立实现。

阿克曼模型以实际内侧前轮的 `max_steering_rad` 为限制，计算左右不同的转角和四轮转速；反向行驶保持相同几何关系，零纵向速度不会产生原地旋转。转向采用理想位置执行器，在积分区间开始选定目标角；核心对转向几何做碰撞检查，不模拟舵机受力、惯性和延迟。

## 生命周期与数据

接口定义在 [api.hpp](../../litesim3d_plugin_api/include/litesim3d_plugin_api/api.hpp)，当前 ABI 版本为 1。所有插件具有虚析构、`defaults()`、`initialize()`、`step()` 和 `reset()`：

- 构造函数保持轻量。`defaults()` 返回全部参数的 JSON 默认值映射：`null` 表示必填，非空值表示真实默认值。
- `initialize(Initialization, parameters)` 解析参数并校验模型引用。`Initialization` 提供实例名、随机 seed、base 坐标系以及中立姿态下的关节位置、轴、父关节和限位，以及模型资源相对路径的基目录。
- `ChassisPlugin::step` 是无副作用预测：接收命令、上一时刻驱动速度、关节状态和整数 `dt_ns`，返回区间平均/末端车体速度、轮角增量、转向角及末端关节速度。核心决定碰撞后接受多少运动。
- `OdometryPlugin::step` 接收前后编码器角度、末端轮速及转向角，自己积分 odom 位姿。这个接口没有真实位姿、场景和速度命令，不能把 ground truth 直接当作轮式 odom。
- 连续轮角是未取模的 rad；速度为 rad/s；平移单位 m；`dt_ns` 必须为 1 ns 到 1 s。核心目前最大物理步长仍是 0.1 s。
- `reset` 清空 odom 积分和噪声序列，并校验初始编码器。新仿真会话重新创建实例；同一会话中暂停不会清空积分。
- 先销毁插件实例，再释放加载器。加载器返回的共享实例持有加载器生命周期，可以安全地比调用方的 `Loader` 对象存活更久。没有热卸载/热更换接口。

`continue_on_collision` 属于核心的碰撞策略。开启时，真实车体停止，但驱动轮增量完整提交，轮式 odom 可偏离真值；关闭时只提交碰撞前的轮角增量，末端轮速归零。全向 odom 的 `vy` 单独保存，不能使用被碰撞约束后的真实 `vy` 替代。

## 扩展标签和参数优先级

展开后的 URDF 内可以有多个 `<litesim3d version="1">` 块，方便由多个 Xacro include 组合。所有块共享实例名空间；底盘和里程计各一个，传感器可多个。当前核心中的新运动路径要求同时声明底盘和里程计。

```xml
<litesim3d version="1">
  <chassis name="drive" class="litesim3d_diff_drive/DifferentialDrive">
    <parameters file="package://litesim3d_diff_drive/config/parameters.yaml"/>
    <parameters file="package://my_robot/config/robot.yaml" section="wheel_geometry"/>
    <overrides>limits: {max_linear_speed_mps: 0.8}</overrides>
  </chassis>
  <odometry name="wheel_odom" class="litesim3d_diff_odometry/DifferentialOdometry">
    <parameters file="package://litesim3d_diff_odometry/config/parameters.yaml"/>
    <parameters file="package://my_robot/config/robot.yaml" section="wheel_geometry"/>
  </odometry>
</litesim3d>
```

`my_robot/config/robot.yaml` 中只维护一份机器人实际几何：

```yaml
wheel_geometry:
  wheel_radius_m: 0.12
  wheel_separation_m: 0.58
  left_joints: [rear_left_wheel_joint]
  right_joints: [rear_right_wheel_joint]
```

优先级是 **实现默认值 < 按声明顺序读取的参数文件 < 实例 overrides**。映射递归合并，序列整体替换。`section` 可用点号选择嵌套映射；省略时使用整个文件。`overrides` 必须最后出现且只能一个。所有最终参数均经过 `defaults()` 键集合检查，未知键、缺失必填项、错误类型和非法数值均报错；YAML 重复键也报错。

插件包中的参数文件包含完整参数及中文注释。它们是默认配置与必填示例；机器人实际尺寸在机器人自己的共享几何节里覆盖，底盘和里程计引用同一个节，避免各自维护一套标定值。新增参数必须同步修改 `defaults()`、配置文件、解析校验、文档和契约测试。

新运动配置的 YAML 只保留核心选项，例如：

```yaml
schema_version: 1
units: m_rad_s
robot:
  urdf: composed.urdf
  base_link: base_link
  continue_on_collision: true
  support_links: [left_wheel, right_wheel]
lidars: []
entities: []
```

声明 chassis 插件后，旧 `robot.drive`、`robot.motion_model` 会报冲突；声明 odometry 插件后，旧 YAML `odom` 会报冲突。核心碰撞选项迁到 `robot.continue_on_collision` 和 `robot.support_links`，重复声明同一选项也报错。没有扩展声明的旧 YAML 传感器列表会转换为对应的标准传感器插件。旧底盘/odom 保留原有兼容路径，以便重现旧实验；新车型使用扩展插件。旧理想 Ackermann 不具备新的真实双转向关节；迁移需按模型组合文档补齐关节和参考系。旧 multicopter 保持原有速度控制模型。

## 导出与安装

具体实现以 pluginlib 导出对应基类，在自己的包中安装共享库、plugins.xml 和参数文件。外部包构建步骤见 [插件开发](../development/插件开发.md)。升级核心后用对应 API 重新编译。


## 传感器接口与替换

公共上下文及测量数据定义在 [sensor_plugin.hpp](../../litesim3d_core/include/litesim3d/sensor_plugin.hpp)，由已安装的 `litesim3d_core` 导出；运动 API 不依赖几何与渲染类型。传感器包依赖已安装的核心 SDK 和 `litesim3d_plugin_api`，链接核心共享库以复用射线、随机流、几何等公共能力。核心不链接具体传感器实现。安装第三方传感器包时也不需要重新编译核心。

`SensorPlugin::description()` 声明实例名、安装 link、输出话题、频率、enabled、输出家族以及规范化 settings。支持的输出家族是 `lidar`、`imu`、`rgb`、`depth`、`rgbd`；自定义算法在这些标准 ROS 输出契约中工作。描述的 name 必须等于声明实例名，其余元数据必须与 settings 一致。自定义插件可以定义自己的输入参数；返回的 settings 要符合对应公共输出家族 schema，供调度、内存预算和 ROS 发布器使用。

核心按整数纳秒截止时间串行调用 `step(context, output)`：

- `context` 提供只读场景、真实运动学、base 到传感器的挂载变换、真实轨迹回调 `world_sensor(t)`、传感器坐标系内的自身几何、起止时间、采样编号和射线线程预算；没有里程计状态。引用和回调仅在此次调用期间有效。
- 雷达每次返回一帧 `Cloud`，采用固定 `xyzirt_v1` 字节布局。滚动扫描的 stamp 为帧起点，completion 不晚于调度截止时间。`rings` 由角度数组长度推导，不是独立插件参数。所有扫描图案参数都列在完整 YAML 中，不使用的参数保留默认值；Mid-360 需要非空 pattern_file 和固定点率约束。
- IMU 每次返回一条 `ImuSample`。加速度是含重力的比力；安装偏移的切向/向心加速度保留。先加偏差和高斯噪声，再按可选对称量程裁剪，量程 0 表示不限；不输出姿态估计。
- 相机每次请求渲染本实例。核心向现有渲染服务提交此时刻的真实 link 位姿，收到像素后调用 `processImage(ImageFrame&)`，再发布图像和 CameraInfo。ImageFrame 提供 stamp、尺寸、RGB8/32FC1 字节及深度端序；插件应保持尺寸、通道和字节布局。
- RGB 偏差和 sigma 单位为 DN，最后取整并限制到 [0,255]。深度偏差和 sigma 单位为 m，原有无效深度保持无效，噪声后超量程的值变为 NaN。默认均为零。RGB-D 使用同一光学 frame 与内参，两通道噪声独立。
- 标准传感器使用实例名、机器人 seed、采样编号/时间戳生成确定性噪声；添加另一传感器不会移动现有实例的随机流。新会话的采样编号从零开始，调用 reset 后可复现相同输入。

例子（放入 `sensors.xacro` 的扩展声明部分；挂载 link/joint 另按 URDF 规范定义）：

```xml
<litesim3d version="1">
  <sensor name="front_imu" class="litesim3d_imu/Imu">
    <parameters file="package://litesim3d_imu/config/parameters.yaml"/>
    <overrides>
link: imu_link
topic: imu/front
rate_hz: 100.0
accel_sigma: [0.01, 0.01, 0.01]
    </overrides>
  </sensor>
  <sensor name="front_rgbd" class="litesim3d_rgbd_camera/RgbdCamera">
    <parameters file="package://litesim3d_rgbd_camera/config/parameters.yaml"/>
    <overrides>
link: camera_optical_frame
topic: camera/front
depth_sigma_m: 0.005
    </overrides>
  </sensor>
</litesim3d>
```

增加多个同类传感器时分别声明 name、link 和输出话题。停用可将 `enabled` 设为 false，删除则移除整条声明；即使停用也校验参数及安装引用。相机类型由插件类决定，插件参数没有旧 YAML 的 `type` 字段。

旧 YAML 的 `lidars`、`imus`、`cameras` 继续可用，并在运行时转换为标准插件。如果 URDF 中已经声明任意 sensor，旧 YAML 三个列表必须全部为空或省略，否则明确报冲突；迁移时一次迁移完整传感器集合，避免两处配置互相覆盖。共享世界目前支持雷达和 IMU；启用相机仍需单机器人渲染入口。`sim_headless` 没有图像渲染服务，因此要求所有相机停用。


## C++ 方法契约

命名空间 `litesim3d::plugins`，`api_version=1`；Pose=Eigen::Isometry3d，Json=nlohmann::json。所有基类都有虚析构函数。

| 类 | 方法 | 调用约定 |
| --- | --- | --- |
| 三类插件 | `Json defaults() const` | 返回参数默认映射，null 表示必填 |
| 三类插件 | `initialize(const Initialization&, const Json&)` | 实例名、seed、中立模型和资源基目录；校验参数与绑定 |
| ChassisPlugin | `bool supportsLateral() const` / `supportsVertical() const` | 默认 false，声明输入自由度 |
| ChassisPlugin | `DriveStep step(const ChassisInput&) const` | 无副作用预测，不能提交真实运动 |
| ChassisPlugin | `reset(const JointState&)` | 校验/重建驱动初态 |
| OdometryPlugin | `OdometryOutput step(const EncoderInput&)` | 仅依据前后编码器状态积分，无真值/场景/控制命令 |
| OdometryPlugin | `reset(const JointState&)` | odom 回到单位位姿，重置噪声状态 |
| SensorPlugin | `SensorDescription description() const` | 输出 name/link/topic/kind/rate_hz/enabled/settings |
| SensorPlugin | `step(const SensorContext&, SensorOutput&)` | 此调用内有效的只读场景和轨迹；输出点云、IMU 或相机请求 |
| SensorPlugin | `processImage(ImageFrame&)` | 相机像素后处理，非相机默认空实现 |
| SensorPlugin | `reset(uint64_t stamp_ns)` | 重建该时刻的采样/随机状态 |
| Loader | `chassis(class_name)` / `odometry(class_name)` / `sensor(class_name)` | 返回对应 shared_ptr，实例持有加载器生命周期 |

ChassisInput 包含 dt_ns、command、drive_velocity、joints；DriveStep 包含 average、velocity、wheel_delta、steering_position、joint_velocity。EncoderInput 只有 dt_ns、previous、current。OdometryOutput 包含 odom→base 的 pose 与机体 velocity。Twist 的 vx/vy/vz/wz 使用 m/s、rad/s，连续轮角未取模。

SensorContext 包含 scene、body、body_sensor、world_sensor(t)、robot_in_sensor、stamp_ns、completion_ns、sample_index、threads。SensorOutput 提供 clouds/imus/cameras；ImageFrame 提供 stamp_ns、width/height、color/depth 字节和 depth_big_endian。不能保存调用期的引用或回调供以后使用，也不能改成其他 ROS 输出家族的字节布局。

参数辅助函数 `merge(base, overlay)` 递归合并映射；`parameters(defaults, overrides, path)` 检查未知键与必填值；`seconds(dt_ns)` 校验时间范围；`integrate(pose, twist, dt)` 提供运动学积分。声明解析函数见 [declarations.hpp](../../litesim3d_plugin_api/include/litesim3d_plugin_api/declarations.hpp)，支持按声明文件基目录解析资源。
