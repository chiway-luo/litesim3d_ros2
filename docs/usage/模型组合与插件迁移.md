# 模型组合、插件选择与旧配置迁移

底盘、轮式里程计和传感器分别按模型声明加载。插件在启动时选择；修改配置后启动新会话，不提供运行中热卸载。完整接口、独立包清单和参数见 [插件接口](../api/插件接口.md)，实现流程见 [插件开发](../development/插件开发.md)。

## 文件分层

四轮小车的文件职责如下：

| 文件 | 职责 |
|---|---|
| `wheel_car_4w_description/urdf/wheel_car_4w.urdf` | 原始机械模型；此次改造逐字节保留，可单独给 RSP/RViz 使用 |
| `wheel_car_4w_description/urdf/sensors.xacro` | 绑定已有雷达/IMU 安装帧，增加相机安装 link/joint，声明各传感器插件 |
| `wheel_car_4w_description/urdf/simulation.urdf.xacro` | include 原始机械模型和传感器文件，声明底盘与里程计插件 |
| 安装后的 `wheel_car_4w_description/config/geometry.yaml` | 构建时从原始机械 URDF 提取轮径、轮距及独立轮关节；底盘和里程计共用，不手工维护第二份尺寸 |
| `wheel_car_4w_description/config/motion.yaml`、`sensors.yaml` | 本车型对标准插件参数的少量覆盖 |
| `wheel_car_4w_sim/config/runtime.yaml` | 指向组合模型、碰撞策略、地形、SDF 环境绑定和运行设置 |
| 世界 `.sdf` | 固定环境的 visual/collision、灯光、出生位姿、步长和目标 RTF |

新增的 `ackermann_sim`、`omni3_sim`、`omni4_sim` 在各自 `config/geometry.yaml` 维护尺寸；机械 Xacro、底盘和里程计引用同一份数据。其 `mechanical.urdf.xacro` 也可单独展开用于 RViz。三轮与四轮示例都是普通全向轮，四轮采用角点切向 X 布局，不是麦克纳姆轮。

Xacro include 使用 `$(find 包名)/...`；插件参数使用 `package://包名/config/parameters.yaml`。URDF mesh/texture 与参数文件的相对路径相对顶层模型目录；include 中的跨目录资源应使用 ROS 包路径。准备器在移动展开文件前固定这些路径，以及标准雷达的相对扫描表路径。外部插件自行解释的资源参数应使用包路径或绝对路径，不能依赖临时目录或启动时的工作目录。

## 同一模型贯穿启动

公共 launch 调用 `litesim3d_bringup.model.prepare_config` 展开一次 Xacro，得到临时 `robot.urdf`。SDF 导入器、核心和 RSP 使用这同一份 XML，渲染器的机器人视觉几何、材质和 link 绑定也从它生成。RViz 读取 RSP 的 robot_description。正常退出时清理临时目录，不改写源文件或安装资源。

设置 `runtime.robot.urdf` 时，它是完整机器人的唯一来源；世界中同名 SDF model 只提供身份和 **URDF root 的出生位姿**，其 link/joint/几何不再叠加。允许只放一个空 link 的出生标记。世界仍必须包含匹配的 `robot.id`，且该机器人不能标为 static。`runtime.robot.initial_pose`、`entities`、重复 SDF 时钟参数仍报冲突。

省略 `runtime.robot.urdf` 时保留原有 SDF 转换路径：SDF 定义机器人，旧 YAML 提供运行绑定。已有无人机入口继续使用这一兼容路径。

内部 TF 只由 RSP 发布；仿真发布 `odom -> URDF root`。新增传感器使用对应固定关节 TF。碰撞空转时，odom 全局位置会与真实位置分离，传感器的安装外参仍完全一致；传感器测量和渲染始终使用真实车体/关节状态，而不是从 odom TF 反推真值。外部估计器若接管 odom TF，必须关闭仿真对应发布者。

## 启动与无界面运行

构建并 source 安装空间后，每次选择一个例子运行：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py gui:=false
ros2 launch ackermann_sim ackermann.launch.py gui:=false
ros2 launch omni3_sim omni3.launch.py gui:=false
ros2 launch omni4_sim omni4.launch.py gui:=false
```

省略 `gui:=false` 打开三维观察窗口；`rviz:=true` 增加 RViz。相机默认关闭，`cameras:=true` 开启已声明的标准相机，仍需要可用图形后端；`gui:=false` 只关闭观察窗口。

阿克曼用非零纵向速度配合 yaw 角速度转弯；三轮/四轮全向还接受横向速度：

```bash
ros2 topic pub -r 20 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.4}, angular: {z: 0.2}}'
# 全向底盘横移；差速与阿克曼不接受此自由度。
ros2 topic pub -r 20 /cmd_vel geometry_msgs/msg/Twist '{linear: {y: 0.3}}'
```

`model_arguments` 是 Xacro 参数的 YAML 映射，例如 `model_arguments:='{camera_enabled: true}'`。它先参与模型展开；之后 launch 的非空 `cameras:=true/false` 覆盖标准相机 enabled。`lidar_profile` 保留原有用法，要求恰好一个标准雷达；选择预设时保留 name/link/topic，轮数 `rings` 转成角度数组长度，核心内部布局固定为 xyzirt_v1；示例 launch 中 Mid-360 默认在 ROS 发布层转成官方 Livox 消息，其他雷达不变，详见 [雷达数据接口](../api/传感器数据.md#livox)。

核心 C++ 不直接解释 Xacro。需要纯命令行调用核心时，先用公共准备器生成文件；输出目录必须为空：

```bash
model_share="$(ros2 pkg prefix --share omni3_sim)"
ros2 run litesim3d_bringup prepare_config \
  "$model_share/config/runtime.yaml" /tmp/omni3-prepared \
  --world "$model_share/worlds/room.sdf" --assets-root "$model_share"
"$(ros2 pkg prefix litesim3d_core)/bin/sim_headless" \
  /tmp/omni3-prepared/scene/runtime.yaml 200 /tmp/omni3-run.json 0.3 0.1 0
```

此命令执行纵向/转弯运动，不发布 ROS。横移验收使用上述 Twist 接口。若配置本身已有 `entities` 而不使用 SDF，省略 `--world`，核心读取输出的 `model/config.yaml`。直接调用 `sdf_import` 仍可行，但 `robot.urdf` 必须已经展开；传入 `.xacro` 会提示先运行准备器。

## 替换插件与参数优先级

实例的最终参数按 **实现 defaults < 参数文件声明顺序 < `<overrides>`** 合并；映射逐层覆盖，数组整体替换。完整参数文件在每个具体插件包的 `config/parameters.yaml`，包含全部配置项的中文说明、必填示例和实际可选默认值。机器人文件只放实例差异，不复制完整默认参数。

替换里程计时，修改 `<odometry class="...">` 和它引用的参数文件即可，底盘不必一起替换。新实现须符合编码器输入接口。外部包单独 colcon 编译安装，source 其 overlay 后启动；不修改或重编核心。外部示例与构建前后核心共享库/可执行文件哈希验收见 [external_plugins](../../examples/external_plugins/README.md)。类似 Gazebo 仅指声明/组合方式，不支持 Gazebo 插件二进制。

新增传感器时，在 `sensors.xacro` 增加唯一 link/joint 和 sensor name，选择独立类，引用其参数文件，覆盖 link/topic/rate_hz 等。多实例必须使用不同名称和输出话题。由 RGB 改为 RGB-D 时，同时将类和完整参数文件换为 `litesim3d_rgbd_camera/RgbdCamera` 与对应包配置，不在新参数里添加旧 `type` 字段。

缺失类、缺失必填项、未知参数、无效量程、重复实例名、同类多个底盘/里程计、未知 link/joint、错误轮轴/布局都会在启动阶段报错。声明名称跨所有 `<litesim3d>` 块共享；`overrides` 只能一个且必须在参数文件之后。

## 旧 YAML 的兼容边界与迁移

无插件扩展的旧 YAML 仍可使用。传感器列表内部转换为标准传感器插件；旧 `robot.drive`/`odom` 保留原有运动兼容路径，避免无提示地改变旧实验。旧理想 Ackermann 没有真实双转向关节，不等同于新的 Ackermann 插件；新机器人应使用组合模型。旧 multicopter 继续保持速度控制运动学，不变成飞行动力学。

迁移步骤：

1. 保留机械文件，增加 `sensors.xacro` 和组合入口，并令 `robot.urdf` 指向组合入口。
2. 添加 chassis 和 odometry，两者必须成对声明。差速轮径、轮距、关节列表共享同一参数来源；阿克曼先补齐真实前轮转向关节与正确后轴参考系；全向轮逐轮配置位置、方向、半径。
3. 删除旧 `robot.drive`、`robot.motion_model`、`odom`。碰撞策略和支撑轮移到 `robot.continue_on_collision`、`robot.support_links`。新 odom 的噪声使用插件 `noise`，不直接沿用旧 YAML 的 scalar/字段命名。新插件路径目前 ROS 里程计 covariance 使用核心零默认值；旧自定义 covariance 不能直接复制到插件参数。
4. 所有传感器一次迁入扩展声明，删除或清空旧 `lidars`、`imus`、`cameras` 三个列表。新雷达省略 `rings`、`point_layout`；camera 的类型由类决定。安装姿态只在机械模型或 sensors.xacro 中定义。
5. 原 SDF 的 `mimic_joints` 绑定改为 URDF 自带 mimic；组合模型模式禁止再次声明该 YAML 扩展。

扩展与对应旧字段同时存在时明确报冲突，不静默选择其中一个。四轮小车旧入口仍可用：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  config:="$(ros2 pkg prefix --share wheel_car_4w_sim)/config/simulation.yaml" gui:=false
```

`continue_on_collision: true` 使真实车体受阻而编码器继续累计；false 只累计到接触前，停止末端轮速。固定障碍物不计算受力、位移或旋转。激光/视觉里程计算法若在外部运行，会根据真实受阻的传感器数据自行估计，不人为伪造其移动。
