# 使用 Docker 运行

只需 Git、Docker 和 Docker Compose v2，宿主机无需安装 ROS、Qt 或 X Server。Windows/macOS 使用 Docker Desktop 的 Linux 容器；Linux 使用 Docker Engine 和 Compose 插件。安装入口见 [Docker 官方文档](https://docs.docker.com/get-started/get-docker/)。

镜像内为 Ubuntu 22.04 + ROS 2 Humble，包含全部示例、RViz 和开发工具。构建按宿主机选择 amd64 或 arm64。建议给 Docker 分配至少 4 核、8 GB 内存，并预留 20 GB 磁盘空间；首次构建需要下载依赖并编译源码。

## 打开三维窗口

在终端执行；已有源码时直接进入仓库根目录：

```bash
git clone --branch humble https://github.com/chiway-luo/litesim3d_ros2.git
cd litesim3d_ros2
docker compose up --build desktop
```

构建完成、服务启动后，用浏览器打开 [LiteSim 3D 桌面](http://localhost:6080/vnc.html?autoconnect=1&resize=scale)。桌面会显示办公场景和四轮小车，鼠标可操作三维窗口。终端保持运行。

默认启用 VLP-16、IMU、里程计和 ros2_control，关闭相机与 RViz。图形使用 Mesa 软件渲染，复杂场景可能降低帧率。浏览器通过 [noVNC](https://novnc.com/noVNC/docs/EMBEDDING.html)显示容器内的窗口，无需配置宿主机显示转发。

第二个终端进入同一仓库目录，检查数据并让小车低速前进：

```bash
docker compose exec desktop litesim-env litesim-check --drive --linear 0.1 --angular 0.0 --duration 8 --require-imu --require-motion
```

返回 JSON 的 `success: true`、`checks.motion: true` 表示收到仿真数据，并观察到至少 1 cm 的里程计位移。检查程序退出前会发送零速度。

按 Ctrl+C 停止，再清理容器：

```bash
docker compose down
```

本地镜像保留，下次用 `docker compose up desktop` 启动。源码更新后重新加 `--build`。

## 使用终端、RViz 和其他示例

桌面运行时，打开已加载 ROS 和 LiteSim 环境的 Bash：

```bash
docker compose exec desktop bash
```

在容器终端内可以运行 `ros2 topic list`，也可以打开已配置好的 RViz：

```bash
dbus-run-session -- ros2 run rviz2 rviz2 -d /opt/litesim3d/install/share/wheel_car_4w_sim/rviz/wheel_car_4w.rviz --ros-args -p use_sim_time:=true
```

切换示例前先停止默认仿真。在另一个宿主机终端执行：

```bash
docker compose exec desktop supervisorctl -c /etc/litesim3d/supervisord.conf stop simulation
docker compose exec desktop litesim-env ros2 launch dual_mid360_bringup bringup.launch.py gui:=true rviz:=false
```

此时默认进程被手动停止，`docker compose ps` 会显示桌面 `unhealthy`；新示例的输出在当前终端查看。按 Ctrl+C 停止新示例后，用以下命令恢复默认小车：

```bash
docker compose exec desktop supervisorctl -c /etc/litesim3d/supervisord.conf start simulation
```

示例参数见[车型示例](../../examples/README.md)。容器内源码在 `/opt/litesim3d/src`，安装环境在 `/opt/litesim3d/install`。

## 无界面运行

停止桌面后，只启动无界面服务：

```bash
docker compose down
docker compose up --build headless
```

第二个终端检查数据和运动：

```bash
docker compose exec headless litesim-env litesim-check --drive --linear 0.1 --angular 0.0 --duration 8 --require-imu --require-motion
```

此模式不启动桌面、RViz 或相机，也不开放浏览器端口。按 Ctrl+C 停止后清理：

```bash
docker compose --profile headless down
```

## 保存文件与连接算法

算法可以在同一容器的另一终端运行。默认 `ROS_DOMAIN_ID=70`、`ROS_LOCALHOST_ONLY=1`，ROS 通信仅限该容器；不会自动连接宿主机或局域网中的 ROS 节点。

容器内文件会随 `down` 删除。将需要保留的结果写入 `/home/litesim`，删除容器前复制到宿主机，例如：

```bash
docker compose exec desktop litesim-env litesim-check --duration 5 --output /home/litesim/check.json
docker compose cp desktop:/home/litesim/check.json ./check.json
```

镜像以普通用户运行，不挂载宿主机源码、设备或 Docker socket。浏览器桌面没有登录密码，Compose 只将端口绑定到 `127.0.0.1`，用于本机体验。

## 调整端口和构建资源

在仓库根目录创建 `.env`，只填写需要修改的项：

```text
LITESIM3D_WEB_PORT=6081
LITESIM3D_BUILD_JOBS=1
```

端口改动后使用新端口打开浏览器。编译因内存不足被系统终止时，将构建并行数降为 1，并重新运行 `docker compose up --build desktop`。

查看启动失败的具体进程与输出：

```bash
docker compose ps
docker compose logs --tail=100 desktop
```
