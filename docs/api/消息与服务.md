# 消息与服务

适用版本以仓库 [VERSION](../../VERSION) 为准。操作步骤见 [使用手册](../usage/README.md)。

定义包是 `litesim3d_interfaces`。以下字段从仓库 IDL 直接列出；ROS 基础消息保持其原有含义。所有时间使用仿真时钟，长度为米、姿态为四元数。

| 服务 | 类型 | 提供者 / 条件 |
| --- | --- | --- |
| `/sim/pause` | std_srvs/srv/SetBool | 单机/多机；依赖就绪后暂停或恢复 |
| `/sim/step` | litesim3d_interfaces/srv/Step | 单机/多机；必须已暂停 |
| `/sim/set_pose` | litesim3d_interfaces/srv/SetPose | 单机；仅内核 Ready，尚未开始实验 |
| `/sim/reset` | litesim3d_interfaces/srv/Reset | sim_session；登记成员与根命名空间单机 |
| `/sim/render_cameras` | litesim3d_interfaces/srv/RenderCameras | SDF 相机渲染器，内部同步接口 |

ROS 2 导航 action、在线增删实体、关节力矩控制和运行中热切换插件不在当前对外接口内。

## 暂停与恢复

SetBool 请求 `bool data`：true 暂停，false 恢复；响应 `bool success`、`string message`。暂停不推进物理时间或采样，诊断仍按墙钟更新。未就绪、故障或退出状态的失败原因通过 message 返回。

<a id="step"></a>
## Step

定义：[Step.srv](../../litesim3d_interfaces/srv/Step.srv)。

```text
string request_id
uint32 steps
---
bool success
uint8 code
string message
uint64 time_ns
```

request_id 非空，按 C++ 字符串计最多 128 字节；steps 为 1–10000，还受约 512 MiB 的单次点云输出预算约束，多机合计计算。成功后仍保持 Paused，time_ns 是此次操作完成时的仿真时间，不保证消费者此时已收到全部话题。

| code | 单机含义 | 多机差异 |
| --- | --- | --- |
| 0 | 成功 | 相同 |
| 1 | 未就绪、未暂停、终止状态或执行异常 | 相同类别，以 message 为准 |
| 2 | ID、步数或输出预算非法 | 也用于请求缓存已满 |
| 3 | 4096 个成功请求的缓存已满 | 世界实现不单独使用此码 |
| 4 | 已成功使用的 ID 被换成不同 steps | 相同 |

相同 ID 与 steps 重试返回缓存结果，不再产生事件；相同 ID 换步数拒绝。缓存属于当前仿真实例，跨 reset 不去重，客户端须按 run_id 管理操作。服务端应答传输超时不表示动作未执行；同一 run_id 内用相同载荷重试。

C++ 服务应答发送超时最多在 2 秒内重试，每个服务最多保留 16 个待发应答；满时在执行新请求前拒绝并记错，客户端可能仍观察到超时。此传输层行为不适用于 Python reset 服务。

<a id="set-pose"></a>
## SetPose

定义：[SetPose.srv](../../litesim3d_interfaces/srv/SetPose.srv)。

```text
geometry_msgs/Pose pose
---
bool success
uint8 code
string message
uint64 time_ns
```

pose 为世界坐标的运动参考 base 位姿；零四元数、非有限值、非法模型初值、碰撞或缺支撑会拒绝。仅 Ready 可调用；正常 launch 完成依赖等待后已进入 Running/Paused，Paused 不能用此服务瞬移。success=true、code=0 表示完成；失败 code=1，message 给原因；time_ns 返回当前时间。此服务没有 request_id，也不协调消费端历史。

<a id="reset"></a>
## Reset

定义：[Reset.srv](../../litesim3d_interfaces/srv/Reset.srv)。

```text
# Only the session supervisor exposes this service; it restarts its owned processes.
string request_id
string expected_run_id
bool set_initial_pose
geometry_msgs/Pose initial_pose
---
bool success
string message
string run_id
```

expected_run_id 必须匹配当前会话；set_initial_pose=false 使用配置初值，true 使用 initial_pose。request_id 非空，当前 Python 实现限制 128 个字符，推荐使用 ASCII ID 以与 Step 一致。即使 set_initial_pose=false，请求载荷中的 initial_pose 仍参与幂等签名。

成功返回新 run_id，成员、仿真和 RSP 已重建且保持暂停。相同 ID 与完整载荷返回原成功结果；换载荷拒绝；缓存上限 4096 项。此服务**没有数字 code**，失败时读取 success、message、run_id。常见 message 包括 stale or missing expected_run_id、uncoordinated participants、request_id reused with different payload、session not ready。

请求/参与者/新初值预检失败时保留旧会话；停止旧进程后若重建失败，会话标为失败，不能假定已回滚。管理器只操作自己创建的进程组。首次启动等待 session.jsonl 的 ready，reset 等待成功响应；仅 `/sim/status` 中内核 ready 不等于成员全部就绪。成员须具备参数服务、响应 executor、输入订阅类型/QoS 和 DDS 匹配。详细登记方法见 [会话与重置](../usage/会话与重置.md)。

<a id="contact"></a>
## Contact

定义：[Contact.msg](../../litesim3d_interfaces/msg/Contact.msg)。

```text
std_msgs/Header header
string run_id
string robot_link
string entity
float64 clearance
```

发布到 `/sim/ground_truth/<robot_id>/contacts`，header.frame_id 为 world，stamp 为接触时刻，run_id 关联实验。robot_link 是机器人碰撞 link，entity 是阻挡实体标识，clearance 是几何间距（米）。它不包含接触力、冲量或材料响应，不用作动力学测量。

<a id="camera-frame"></a>
## CameraFrame

定义：[CameraFrame.msg](../../litesim3d_interfaces/msg/CameraFrame.msg)。

```text
string camera_name
sensor_msgs/Image color
sensor_msgs/Image depth
sensor_msgs/CameraInfo info
```

内部批量渲染结果，用 camera_name 对应请求实例。color/depth/info 自带 header；仅当前类型需要的图像通道有内容。外部算法订阅标准 Image/CameraInfo，通常不直接消费此封装。

<a id="render-cameras"></a>
## RenderCameras

定义：[RenderCameras.srv](../../litesim3d_interfaces/srv/RenderCameras.srv)。

```text
# Internal synchronous rendering request. Poses are exact world truth at header.stamp.
std_msgs/Header header
string scene_id
string run_id
string[] camera_names
string[] link_names
geometry_msgs/Pose[] link_poses
---
bool success
string message
litesim3d_interfaces/CameraFrame[] frames
```

header.stamp 为严格正的采样仿真时间；scene_id 必须匹配加载场景，run_id 非空。link_names 与 link_poses 一一对应，包含完整场景 link 快照，名称不得重复；pose 为该时刻世界真值。一个 run_id 内时间戳必须严格递增，重复请求不幂等。渲染完成返回 frames；失败返回 success=false 和 message。

桥接按采样批次调用并在渲染完成后发布图像，最多一个批次在途。外部调用可能破坏时间顺序，本接口属于桥接与渲染器之间的内部协议。服务端实现见 [camera_node.cpp](../../litesim3d_gui/src/camera_node.cpp)。

## ros2_control 内部指令与反馈

这些消息连接硬件适配器与仿真，不替代算法侧的标准控制器接口。

### JointCommand

定义：[JointCommand.msg](../../litesim3d_interfaces/msg/JointCommand.msg)。

```text
# Private simulator hardware transport. Public controllers use standard ROS interfaces.
uint8 HOLD=0
uint8 POSITION=1
uint8 VELOCITY=2
std_msgs/Header header
string run_id
string[] name
uint8[] mode
float64[] command
# Optional kinematic body resource; only supported by multicopter mode.
# linear.xyz in base_link, angular.z in rad/s; angular.xy must be zero.
bool body_velocity_control
geometry_msgs/Twist body_velocity
```

### JointFeedback

定义：[JointFeedback.msg](../../litesim3d_interfaces/msg/JointFeedback.msg)。

```text
string run_id
bool operational
sensor_msgs/JointState state
# Capability handshake and collision-accepted body state at state.header.stamp.
bool body_command_supported
geometry_msgs/Pose body_pose
geometry_msgs/Twist body_velocity
```

指令的 name/mode/command 必须等长且名称唯一，run_id 必须等于当前仿真会话，header.stamp 使用仿真时间且不可来自未来或超过 command_timeout。mode 为 HOLD/POSITION/VELOCITY；空指令集表示保持所有关节当前位置。固定、mimic、未知关节和非有限目标会被拒绝，越界位置目标拒绝，速度按 URDF 限幅。每个物理步开始应用最近的一条有效指令，省略的关节停止移动。

反馈包含实际积分并经过约束后的全部可动关节状态；position 是累计角度/位移，velocity 是对应实际速度。operational=false 表示仿真故障或退出。适配器检测会话变化、反馈超时或非法数据后进入硬件错误；重新配置和激活后才能恢复。接口详情见 [ROS 2 接口](ROS2接口.md)。

`body_velocity_control=true` 时还携带机体系 XYZ 速度和偏航角速度，当前仅 multicopter 接受，angular.x/y 必须为 0；省略此部分即将机体目标速度归零。`body_command_supported` 用于硬件激活前确认能力；`body_pose` 是世界坐标系中的实际位姿，`body_velocity` 是碰撞与限速后机体系的实际速度，均对应 state.header.stamp。它们是理想硬件反馈，不能当成带噪声的定位估计。内部消息发生扩展时，仿真桥接、接口包和硬件适配器应一起重新构建。
