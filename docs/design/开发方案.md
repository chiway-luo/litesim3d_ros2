# litesim3d_ros2 开发方案

版本：0.1 开发草案。更新日期：2026-10-17。

2026-10-18 实施补充：M1/M2/M3 已实现的功能按本机 macOS / Humble 验收；最新的文档对照、补全结果和逐项证据见 [文档对照与补全报告](../testing/文档对照与补全报告.md)。Linux、外部建图导航算法及 8 小时长稳按用户决定延期。下表保留原始阶段设计，延期项不计 PASS；M3 未启用的可选扩展继续列在路线图。

目标是实现可导入 URDF、产生三维激光数据、支持 ROS 2 算法闭环的轻量化三维仿真工具。本方案以地面移动机器人为起点，优先保证几何、坐标、时间和传感器数据正确，并以可重复的实验衡量算法表现。

用户明确的需求为轻量化、借鉴 stage_ros2、用于算法验证、支持 URDF 导入、支持三维激光数据，以及完整测试。本文中的技术选型、默认参数、阶段和数值目标是开发建议，需在 D0 基线记录中锁定。

## 产品范围

Stage 使用简单、计算成本较低的模型，其官方定位为 2.5D 仿真；stage_ros2 提供 ROS 2 桥接。项目借鉴场景配置、设备模型、ROS 2 接口和无界面运行方式，并为三维几何与三维传感器建立独立内核。[Stage](https://playerproject.github.io/stage/)、[stage_ros2](https://github.com/tuw-robotics/stage_ros2)

机器人状态采用三维位置和四元数姿态。首期运动模型为差速底盘，后续加入连续坡面上的地形约束。可用等效底盘验证机器狗的上层导航，但步态、足端受力、轮胎滑移机理和碰撞冲击不属于本运动学模型的有效验证范围。

仿真计算支持 CPU 和无界面模式。RViz2 作为初期可视化入口，显示机器人、场景、点云、碰撞体与轨迹。图形窗口的刷新不能决定仿真时间，也不能成为核心运行条件。

## 交付阶段

| 里程碑 | 交付内容 | 必须验证的结果 |
| --- | --- | --- |
| M1 可运行原型 | URDF 导入、平地三维场景、差速运动、基础三维碰撞、瞬时三维激光、ROS 2 接口、RViz2 | 机器人能运行完整控制链路，几何和字段测试通过 |
| M2 算法验证版 | 连续坡面、扫描畸变、误差模型、IMU、协调重置、一个三维建图或定位算法、一个导航闭环、评测与性能 | 对应功能测试、算法基线、性能和稳定性测试全部通过 |
| M3 扩展版 | 动态障碍、多机器人、更多底盘和扫描模式 | 对每个启用的扩展分别执行集成、性能和隔离测试 |

M1 可以演示功能，但不能宣称已经适合所有三维 SLAM 或激光惯性算法。M2 的“算法兼容”只覆盖实际测试的算法版本与参数。M3 未启用的扩展允许保留在路线图中；已对外宣称支持的扩展必须经过测试。

## 模块划分

以下是逻辑模块，不要求开始时就拆成多个进程或引入动态插件体系。

| 模块 | 职责 | 主要依赖方向 |
| --- | --- | --- |
| core | 仿真时钟、事件调度、实体状态、控制输入、随机流和运行状态 | 不依赖 ROS 2、RViz2 |
| geometry | 场景加载、网格处理、射线查询、碰撞、地形支撑 | 被运动与传感器共用 |
| robot | URDF 导入、关节树、底盘运动学、碰撞体与外参 | 依赖 core、geometry |
| sensors | 激光、里程计、IMU、噪声与采样历史 | 读取指定时刻的世界状态 |
| ros_bridge | 话题、服务、时间、消息布局和命名空间适配 | 将核心数据转换为 ROS 2 接口 |
| evaluation | 输入录制、实验调度、真值对比和报告 | 不向被测算法注入真值 |
| bringup | 示例 URDF、场景、启动文件和 RViz2 配置 | 用于可运行交付 |

内部仿真状态由一个确定的更新顺序推进；射线计算可以并行，但按稳定的索引写回结果。ROS 2 回调先进入输入队列，不能在任意时刻直接改动几何树或当前帧。

## 技术选择

| 项目 | 建议 | 确定条件 |
| --- | --- | --- |
| 语言 | C++17 核心，Python 实验与集成测试 | D0 固定编译器和依赖版本 |
| ROS 2 | 优先匹配现有算法使用的发行版 | 可用 Ubuntu 22.04 与 Humble 作候选基线，实际组合写入基线记录 |
| URDF | 复用 urdfdom，Xacro 在导入前展开 | 明确接受的 URDF 版本、关节和资源类型 |
| 射线 | 先以解析几何建立正确性参考，再评估 CPU BVH 实现或 Embree | 比较依赖体积、加载时间、射线吞吐与目标平台支持 |
| 碰撞 | 复用适当的几何碰撞库或限定形状实现；避免把射线库当作完整碰撞引擎 | 通过三维包络与扫掠测试后锁定 |
| 配置 | 版本化 YAML 场景与机器人仿真配置 | 非法字段、单位和资源必须校验 |
| 可视化 | RViz2 | 关闭可视化后仿真结果不变 |
| 测试 | CTest 或 GoogleTest；pytest 与 launch_testing；独立性能运行器 | 执行结果必须有机器可读报告 |

urdfdom 提供 URDF 的数据结构与解析能力；Embree 提供射线计算内核。二者都不自动解决本项目的运动、碰撞响应、传感器时序或算法适配。[urdfdom](https://github.com/ros/urdfdom)、[Embree](https://www.embree.org/)

## 开发步骤与阶段出口

| 阶段 | 工作 | 交付物 | 出口条件 |
| --- | --- | --- | --- |
| D0 基线 | 锁定首个机器人、算法、系统版本、硬件和资源预算；评估几何后端 | 基线清单、依赖清单、选型记录、测试数据清单 | 无影响实现的接口歧义；每项范围有需求编号 |
| D1 内核 | 时间、事件、随机流、状态机、无界面入口、最小 ROS 2 时钟 | 可运行空场景、核心单元测试 | 内核和时间测试通过；GUI 不影响时间 |
| D2 模型 | URDF、关节、网格、资源路径、显示与碰撞模型 | 至少两种有效模型和异常模型集合 | 几何尺寸、关节和 TF 对照测试通过 |
| D3 场景 | 基本几何、网格、空间索引、最近交点和三维碰撞 | 解析场景与复杂场景 | 遮挡、薄墙、悬空物和包络碰撞正确 |
| D4 原型 | 差速运动、瞬时多线雷达、PointCloud2、里程计与 RViz2 | M1 运行示例与功能测试 | M1 必测集全部通过；可重复安装和运行 |
| D5 传感器 | 坡面约束、逐点时序、畸变、噪声、IMU、重置协调 | M2 模型与误差配置 | 解析轨迹、噪声统计和缓存清理测试通过 |
| D6 算法 | 三维建图或定位、导航、真值隔离和评测 | 固定版本算法配置、结果报告 | 算法基线、失败统计和外部输入记录完整 |
| D7 发布 | 性能、稳定性、干净环境安装、CI 和文档 | M2 发布候选包 | 所有适用门禁通过，未执行项不能算通过 |
| D8 扩展 | 动态障碍、多机器人、更多模型 | 逐项扩展包 | 每项扩展通过 M3 测试并回归已有功能 |

每个功能同时提交实现、有效测试和文档说明；基础正确性测试随开发执行，不集中到最后。性能优化必须保持解析几何和消息语义测试通过。

## 首次验收的演示流程

1. 从安装目录加载示例 URDF、场景和雷达配置。
2. 发布速度指令，观察机器人沿解析轨迹移动及撞墙停止。
3. 验证三维激光对立柱、低矮障碍和悬空物产生正确回波。
4. 在 RViz2 查看机器人、点云、TF 和轨迹，并与无界面运行结果对比。
5. 完成一个不使用真值的算法闭环，生成与真值对照的指标。
6. 暂停、单步、重新开始实验，检查旧控制和旧传感器数据未混入新实验。

步骤 1 至 4 属于 M1，步骤 5 至 6 的完整算法协同属于 M2。截图和视频可作为辅助证据，不能替代数值断言及测试报告。

## 开发前必须锁定的事项

| 项目 | 当前建议 | 记录位置 |
| --- | --- | --- |
| 首个机器人 | 差速地面机器人；一个几何模型和一个含网格的实际模型 | D0 基线清单 |
| 目标算法 | 一个三维建图或定位实现；一个导航实现 | 固定仓库版本、参数与数据适配说明 |
| 系统 | M1 按 2026-10-18 用户确认使用本机 macOS / Humble；后续 Linux 与目标算法环境另行验证 | [M1 基线](../testing/M1基线.md)、环境清单 |
| 基准机器 | 固定 CPU 型号、核心预算、内存及电源模式 | 性能测试 B0 记录 |
| 几何后端 | 射线和碰撞分别选择，可共享场景源数据 | 性能原型与选型记录 |
| 验收阈值 | 采用测试规范中的初始目标，执行前冻结 | 测试计划版本与变更记录 |

以上选项不阻碍文档和接口设计完成；在相应实现、性能或算法验收开始前必须补齐。任何阈值调整都应记录原因并重跑相关用例，不能测试失败后仅通过降低阈值获得通过。
