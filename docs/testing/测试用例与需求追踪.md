# litesim3d_ros2 测试用例与需求追踪

版本：0.1 开发草案。更新日期：2026-10-18（M1 验收平台调整）。

本清单包含 140 条测试规格，覆盖开发方案中的 36 项需求。数量表示设计覆盖，不表示通过。M1 历史证据见 [M1 测试报告](M1测试报告.md)，M2/M3 历史映射及本轮补全的统一索引见 [文档对照与补全报告](文档对照与补全报告.md)。未执行的用例仍不得计为 PASS。

2026-10-18 用户确认 M1 以本机 macOS / Humble 验收，Linux 留作后续验证。T-DEL-01 的平台条件据此调整，其他判据不变；原平台要求与变更依据见 [M1 基线](M1基线.md)。

同日用户确认 M2 也以 macOS / Humble 验收，并要求直接开发仿真器。本轮将 T-E2E-01 至 T-E2E-07 的外部算法项列为 DEFERRED；Linux 检测器后续验证。本地数值、统计、性能与 8 小时墙钟要求保留，见 [M2 基线](M2基线.md)。

用户随后要求“长时间稳定测试先不做”：T-ROB-01 同样列为 DEFERRED，本轮不以此阻塞关闭，也不记为 PASS；用例原始判据继续保留。

测试输入编号、容差、统计标准、算法与性能配置见[测试与验收规范](测试与验收规范.md)，被测行为见[坐标与模型约定](../api/坐标与模型约定.md)。每个参数化输入都须产生子结果，任一必测子结果失败即为该用例失败。

M1 是原型必测，M2 是算法验证版新增必测，M3 是对应扩展启用后的必测。M2 包含 M1，M3 包含已有功能回归。E2E 地图用例只有在预先确定所选算法不提供地图时才可记为 NOT_APPLICABLE；其余已纳入能力不得用跳过代替验收。

每条用例的证据以 run_id 和测试 ID 关联：UNIT 保存输入、期望与实际数值；COMPONENT 保存导入报告或状态序列；ROS 保存日志、graph/TF 和消息记录；E2E 保存轨迹、rosbag2 与指标；PERF/SOAK 保存原始资源采样；STATIC/DOC 保存诊断和检查记录。具体路径填入[测试报告](测试报告模板.md)，没有证据不得记 PASS。

| 用例与名称 | 需求 阶段 层级 | 输入与操作 | 通过判据 |
| --- | --- | --- | --- |
| T-COR-01 无界面核心 | REQ-001；M1；COMPONENT | 对同一控制录制分别关闭和开启 RViz2，推进 60 s 仿真时间。 | 核心可独立运行；按事件序号对齐后的状态和传感器输出一致。 |
| T-COR-02 固定步长与初始时钟 | REQ-002, REQ-023；M1；UNIT | 从 1 ns 起运行 100000 步，dt=5000000 ns。 | 末时刻恰为 1+100000×5000000 ns；没有墙钟抖动引入的积分变化。 |
| T-COR-03 非整数倍采样 | REQ-002；M1；UNIT | dt=0.005 s，同时调度 7、10、50、200 Hz 传感器，运行 60 s。 | 各事件按精确计划出现；计数只允许端点约定的 1 次差异，无累计漂移。 |
| T-COR-04 暂停与继续 | REQ-003；M1；COMPONENT | 运行中暂停，等待 2 s 墙钟，再继续。 | 暂停期状态、仿真时间和采样序号不变；继续后从原时刻推进，不补采暂停墙钟期间数据。 |
| T-COR-05 单步与幂等 | REQ-003；M1；COMPONENT | 暂停后请求 step 10，再发送同一个 request_id；运行态请求 step。 | 第一次只推进 10 dt；重复请求不重复推进；运行态拒绝单步并保持状态。 |
| T-COR-06 输入生效顺序 | REQ-004；M1；UNIT | 记录 1000 个命令的接收顺序和生效步号，按同一记录重放 3 次。 | 生效顺序和状态哈希相同；同一步多个命令按固定规则选择，不依赖线程完成顺序。 |
| T-COR-07 随机流独立 | REQ-004；M1；UNIT | 同种子运行 3 次，再更换种子；在机器人旁增加一个不参与交互的传感器。 | 同种子复现；不同种子产生不同随机序列；增加无关传感器不改变已有传感器序列。 |
| T-COR-08 非法时间与参数 | REQ-005；M1；UNIT | 输入 dt=0、负频率、NaN、Inf、越界线程数、缺失必填字段及未知关键字段。 | 启动前拒绝，指出字段；不创建半初始化世界或无限循环。 |
| T-COR-09 变换与四元数 | REQ-006；M1；UNIT | 对随机刚体变换、近零角、接近 π 的旋转以及 q/-q 进行组合和逆变换。 | 相消误差满足变换容差；q/-q 同义；无非法归一化或非有限结果。 |
| T-COR-10 运行清单完整 | REQ-004；M1；COMPONENT | 运行固定场景后读取清单，逐项对照配置、资源与输入记录。 | 软件、资源、种子和生效步号完整；算法版本在启用算法时必填；资源变更会改变相应哈希。 |
| T-COR-11 倍速与模型时间分离 | REQ-001, REQ-002, REQ-004；M1；COMPONENT | 相同输入在 0.5 倍、1 倍和无节拍模式各运行相同仿真时长。 | 模型状态与按采样索引排列的输出一致，只有墙钟耗时不同。 |
| T-COR-12 状态迁移与事务性 | REQ-003, REQ-005；M1；COMPONENT | 按加载、就绪、运行、暂停、故障顺序操作；在运行时提交一个失败的重新加载请求。 | 非法迁移被拒绝；失败请求不部分修改已运行实体，错误状态与诊断一致。 |
