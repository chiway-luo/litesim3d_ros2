# SDF 导入与独立三维窗口改造方案

日期：2026-10-18<br>
状态：实施前设计留档；核心功能已落地，逐项结果见 [SDF 实现验证](../testing/SDF实现验证.md)。下文保留原始目标，不代表所有规划项已验收。

采用 Gazebo 风格的资源目录和 SDF 文件组织世界、机器人与环境模型，增加纯查看的独立三维窗口。窗口完整显示兼容范围内的材质和贴图，仅允许通过缩放、平移和旋转调整观察视角，自动显示仿真速率。保留现有轻量运动学、碰撞和传感器计算内核，继续通过 ROS 2 向算法发布数据。

独立窗口取代 RViz2 成为默认查看入口。RViz2 仍可由用户单独启动，用于检查点云、TF、地图和算法结果。碰撞预算仅由一个布尔参数启用或禁用，默认禁用；碰撞检测继续正常工作。模型资源目录定为 `examples/wheel_car_4w/litesim_models`，安装后通过 ROS 2 包 share 路径动态定位。该段记录实施前方案；当前用法和明确兼容边界以 [SDF 与独立窗口](../usage/SDF与独立窗口.md) 为准。

## 一 主要设计决定

| 项目 | 建议方案 |
| --- | --- |
| 模型和世界入口 | 统一使用 SDF；世界通过 `<include>` 引用模型目录 |
| 模型资源目录 | `examples/wheel_car_4w/litesim_models`，规划为纯资源 ROS 2 包，通过包 share 路径定位 |
| 环境变量 | launch 在本次进程树中设置 `GZ_SIM_RESOURCE_PATH`，不要求用户修改 shell 配置 |
| SDF 解析 | 使用 libsdformat 处理格式、include、坐标语义和版本转换，再生成内部场景描述 |
| 三维窗口 | 独立 `litesim3d_gui` 进程，采用 Qt 和 Gazebo Rendering 的 Ogre2 后端；只允许缩放、平移、旋转查看 |
| 计算与显示 | 仿真进程拥有时钟和世界状态；GUI 读取场景和状态快照，不推进仿真 |
| 几何角色 | 显示、传感器射线和碰撞分开管理；限制碰撞复杂度不修改外观 |
| 碰撞预算开关 | 唯一对外参数 `collision_budget_enabled`，默认 false；true 时启用内部预算规则 |
| 超限行为 | 仅启用预算时执行碰撞复杂度限制；加载超限明确报错，不自动减面或关闭碰撞 |
| 仿真速率 | 分别显示目标 RTF、实际 RTF 和 GUI FPS；允许实际 RTF 低于 100% |
| 配置职责 | SDF 定义场景；运行配置定义预算、ROS 绑定及本项目专有算法参数 |

Gazebo Rendering 提供渲染能力，仍需本项目实现 SDF 到渲染场景的映射、状态同步和观察视角操作。它不会自动把现有仿真器变成 Gazebo。Ogre2 支持 PBR，但 Gazebo Classic 的材质脚本与新 Gazebo 的渲染体系存在差异，需要单独处理兼容性。[Gazebo 渲染能力对照](https://gazebosim.org/docs/fortress/comparison/#rendering)

## 三 目录与 launch 入口

模型目录按用户指定位置设置，并规划为不含 C++ 的纯资源 ROS 2 包：

```text
src/litesim3d_ros2/examples/wheel_car_4w/
├── litesim_models/
│   ├── package.xml
│   ├── CMakeLists.txt
│   ├── models/
│   │   ├── wheel_car_4w/
│   │   │   ├── model.config
│   │   │   ├── model.sdf
│   │   │   ├── meshes/
│   │   │   │   ├── body_visual.dae
│   │   │   │   └── body_collision.stl
│   │   │   └── materials/textures/
│   │   └── warehouse/
│   │       ├── model.config
│   │       ├── model.sdf
│   │       ├── meshes/
│   │       └── materials/textures/
│   └── worlds/
│       └── warehouse.sdf
├── wheel_car_4w_description/
└── wheel_car_4w_sim/
```

`model.config` 是模型元信息和 SDF 版本入口，不承担第二套场景定义。DAE、OBJ、STL 是 SDF 引用的底层网格，统一 SDF 不意味着把顶点和图片全部写进 XML。

`litesim_models` 使用 ament 安装 `models` 和 `worlds` 到 `share/litesim_models`，并注册包资源索引。示例 launch 使用 `get_package_share_directory("litesim_models")`（即 get_share 获取包路径的方式），得到安装资源根目录，再设置本次子进程的环境变量。路径查询依靠包安装索引，资源目录与哪个 `src` 同级本身不决定是否可被查询。

拟议路径解析如下，仅说明后续实现方式，本轮不修改安装规则或 launch：

```python
resource_root = Path(get_package_share_directory("litesim_models"))
model_path = resource_root / "models"
world_path = resource_root / "worlds" / world_name
```

保留四轮车的启动入口，内部调用新增的通用 `sim.launch.py`。默认关闭碰撞预算的拟议用法：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  world:=warehouse.sdf gui:=true
```

需要启用碰撞预算时，仅增加一个参数：

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  world:=warehouse.sdf gui:=true collision_budget_enabled:=true
```

launch 将包 share 下的 `models` 和 `worlds` 加入本次子进程的 `GZ_SIM_RESOURCE_PATH`，保留已有搜索路径并去重。Gazebo 的 `model://模型名` 同样通过模型父目录查找资源。[Gazebo 世界与模型目录说明](https://gazebosim.org/docs/harmonic/sdf_worlds/#adding-models)

示例默认无需填写绝对模型路径。通用 launch 接受示例传入的资源根目录，不自行依赖某个示例包；需要自定义资产时可显式覆盖根目录。不得通过当前工作目录或安装目录向上猜测 `src` 的位置，因为本项目当前构建产物可能位于临时目录。安装测试同时覆盖复制安装和符号链接安装；隐藏源码的验收使用实际复制资源的安装产物。

| 拟议 launch 参数 | 含义 |
| --- | --- |
| `assets_root` | 示例默认由 `get_package_share_directory("litesim_models")` 取得；通用 launch 接收该值 |
| `world` | `worlds` 下的 SDF 文件名，或显式绝对路径 |
| `runtime_config` | 运行预算、ROS 绑定、底盘与传感器扩展配置；可使用安装的默认配置 |
| `gui` | 默认 true；false 时启动无界面仿真，不初始化图形后端 |
| `paused` | 默认 false；GUI 模式仍需完成场景就绪握手后才开始推进 |
| `rtf` | 目标速率覆盖；未提供时采用 SDF 的目标速率 |
| `collision_budget_enabled` | 唯一碰撞预算参数，布尔值，默认 false；true 才执行预算限制 |
| `render_fps` | 窗口帧率上限，初始建议 30，与仿真步长独立 |

资源解析规则：

1. 相对 URI 按声明它的 SDF、网格或材质文件所在目录解析；嵌套 include 不能丢失原始基准目录。
2. `model://` 使用统一资源解析器；`file://`、绝对路径和用于 ROS 资源迁移的 `package://` 均有明确处理。
3. 明确路径优先；搜索路径中出现同名模型时默认报告冲突，用户调整搜索路径后再加载，避免误用另一个模型。
4. 首期加载本地资产。Fuel 模型先放入资源目录；在线下载不混入启动流程。
5. 输出资源清单，记录 SDF、网格、材质和贴图的来源、哈希、大小、缩放与解析结果。缓存放在 artifacts，不修改用户原始模型。

## 四 SDF 导入范围与内部结构

### 统一入口和配置职责

世界和机器人都由 SDF 提供，不要求用户再手工维护同一机器人的 URDF。原有 URDF 和 YAML 场景通过独立迁移工具生成 SDF，保留旧文件作为回归输入。新入口不同时接受两份互相覆盖的几何定义。

SDF 中的模型位姿、link、joint、visual、collision、灯光及标准传感器参数是相应属性的唯一来源。运行配置只补充本项目需要的机器人控制绑定、Mid 系列扫描模式、误差模型、话题与资源预算。绑定使用 SDF 的完整实体名称；重名、缺失或重复定义报错。

仿真步长采用 SDF `<physics><max_step_size>`，目标速率采用 `<real_time_factor>`；launch 的 `rtf` 是明确的最高优先级覆盖。旧配置中的步长、目标速率由迁移工具写入 SDF，不长期保留两套默认值。

建议以 SDF 1.9 为首个规范版本，使用与目标平台兼容的 libsdformat。旧版本通过库提供的转换并逐项验证；比已验证范围更新的版本应报告不兼容。库版本和 SDF 规范版本分别记录，不能混用版本号。

### 解析流程

```text
SDF 世界和模型
  → libsdformat 解析 include 与坐标关系
  → 统一资源解析和兼容性检查
  → SceneDescription 内部场景描述
      ├── VisualAsset：网格、材质、UV、贴图、灯光
      ├── RayGeometry：激光查询几何与 BVH
      ├── CollisionGeometry：碰撞体与 FCL 结构
      └── RobotDescription：关节树、传感器和驱动绑定
  → 校验完成后提交世界
```

SDF 的 `pose relative_to`、`frame attached_to`、嵌套模型及关节轴 `expressed_in` 交给 libsdformat 的语义解析处理；不能只按 XML 父子关系累加位姿。[SDF 坐标语义](https://sdformat.org/tutorials/specification/pose_frame_semantics/1.7/)

显示、碰撞和射线查询使用同一套已解析的单位、缩放与变换。缓存区分资源内容、子网格选择、缩放和构建用途；原始顶点可以共享，FCL 和射线 BVH 按需建立。预加载失败时不发布半个世界，不启动运动。

### 首期兼容目标

| 内容 | 处理方式 |
| --- | --- |
| world、model、include、嵌套静态模型 | 正确解析名字、位姿、资源和重复实例 |
| box、sphere、cylinder、STL、DAE、OBJ | 保留现有几何能力，增加视觉资源信息 |
| plane | 增加显式平面几何；显示范围与碰撞／射线的平面语义分别定义，不能悄悄用小方块代替无限平面 |
| 多 visual、多 collision、子网格 | 保留每个部件的材质和位姿，支持选取子网格后的统一变换 |
| fixed、revolute、prismatic 关节树 | 映射现有运动学；连续转动通过 SDF 关节与限位语义转换 |
| 标准激光、IMU 参数 | 映射到现有传感器内核；本项目专有扫描模式通过绑定配置补充 |
| 机器人与移动障碍 | 必须绑定可执行的运动学控制或轨迹；不把未绑定的动态模型无提示冻结 |
| 地形支撑 | 通过运行配置选择 SDF collision 的完整名称，沿用现有可通行地形约束 |
| inertial、摩擦、接触力参数 | 保留来源和兼容性报告；现有运动学内核不由此产生刚体动力学 |
| Gazebo 插件 | 不装载外部插件库；报告未执行行为，必要控制由本项目显式绑定 |
| 闭环关节、骨骼动画、任意 shader、粒子和未适配地形格式 | 首期不作为可运行兼容资产；明确报错并输出离线兼容性报告 |

只含装饰性 visual 的实体可以无 collision，导入报告必须标明“不参与碰撞”；被指定为机器人碰撞体、支撑面或障碍物的实体缺少 collision 时拒绝加载。默认不把复杂 visual 自动补成 collision。碰撞预算开关不改变这些模型有效性规则。

### 保持 ROS 2 接入能力

SDF 不是 robot_state_publisher 的直接输入。首期为已支持的树状机器人从同一内部关节描述生成派生 URDF，供 RSP 和可选 RViz RobotModel 使用；这份 URDF 是缓存产物，不能反向覆盖 SDF。环境模型无需转换成 URDF，完整材质也不经过该转换链路。

内核继续拥有机器人状态，RSP 继续负责机器人内部 TF，保持单一发布责任。独立窗口读取世界真值状态，不依赖算法估计的 odom／map 显示真实位置，也不向算法 TF 树额外注入全局真值。不同 SDF 机器人实例逐个绑定模型和 ROS 命名空间，保留现有 1–4 台的运行限制。

## 五 独立三维窗口与材质显示

### 渲染方案

采用 Qt 窗口加 Gazebo Rendering 的 Ogre2 后端；GUI 和内核分进程，图形依赖仅属于 GUI 包。窗口中的三维场景由 `SceneBuilder` 从已校验的 SceneDescription 建立，随后按实体 ID 更新位姿，不逐帧重新加载模型。

界面为三维画面加固定的只读速率信息，不设置模型树、选择面板、控制栏或菜单。仅允许鼠标／触控板缩放、平移和旋转观察视角；这些输入只改变本地相机，不改变模型或仿真状态。

不提供运行、暂停、单步、重置、改速率、机器人控制、模型选取或拖拽、跟随、图层切换等交互，也不设置对应快捷键。目标速率、初始观察视角等在启动参数或配置中确定。原有 ROS 2 控制接口由外部算法或命令行使用，窗口不创建控制发布者或控制服务客户端。

显示链路需要保留：

- 每个子网格的材质绑定、UV、法线、切线、正缩放与坐标变换。
- DAE 内部材质、OBJ 配套 MTL 及其相对纹理路径；STL 没有贴图时采用 SDF 材质。
- SDF 基础颜色、透明度、自发光、双面、阴影及方向光、点光、聚光灯。
- PBR metallic／roughness 流程中的颜色、法线、粗糙度、金属度、AO 和自发光贴图。其他贴图及 specular／glossiness 流程逐项进入兼容矩阵，不能仅因 XML 能解析就视为已显示。
- 明确的材质覆盖顺序、颜色空间、法线贴图方向和多 UV 通道；用校准资产验证，避免贴图存在但方向或亮度错误。

SDF 同时定义基础材质和 PBR 属性，具体可用工作流依赖渲染器。完整显示的验收依据应是版本化材质兼容矩阵和样例资产，而非“支持 SDF”四个字。[SDF 1.9 材质定义](https://github.com/gazebosim/sdformat/blob/sdf12/sdf/1.9/material.sdf)

### 完整显示的验收边界

完整显示表示：对纳入兼容矩阵的资产，模型部件、材质槽、所用贴图及相关显示属性全部生效，无丢贴图、统一灰模或未声明的材质替换。对超出兼容范围的资产，加载报告明确指出具体字段和所需转换；不能显示一个简化结果后标为完整兼容。

Gazebo Classic 的任意 `.material` 脚本、自定义 shader 和视觉插件不能保证直接映射为 Ogre2 PBR。常见纯色／漫反射贴图脚本可增加显式迁移工具，生成副本并记录转换；复杂脚本列为不支持。与 Gazebo 比较时固定模型、相机、灯光和曝光，检查几何和材质一致性，不承诺跨渲染版本逐像素相同。

默认 `strict_visuals: true`：缺贴图、无法识别的材质或转换失败，会阻止 GUI 就绪，并将具体问题写入导入报告和日志。无界面模式仍检查资源引用，GPU 渲染验收另行记录。模型检查使用离线报告，不增加窗口交互模式。

### 平台验证顺序

先做小型技术验证：在 Ubuntu 22.04／ROS 2 Humble 与当前 macOS／RoboStack 环境各加载一个带普通贴图的模型和一个 PBR 模型，检查 Qt、图形上下文、Ogre2、窗口缩放及关闭重开。先确认依赖可用，再锁定库版本。GUI 可以采用独立依赖前缀，不混用不兼容的 Qt 和 Ogre 动态库。

macOS 的渲染能力不能从已有 RViz2 运行结果推断；Gazebo 官方也列出过该平台的渲染窗口问题。若完整渲染受阻，应记录具体平台和功能限制，再调整依赖路线，不能自动退回灰模并称完成。[平台能力说明](https://gazebosim.org/docs/fortress/comparison/#platforms)

## 六 碰撞模型预算与性能控制

### 唯一预算参数

仅公开一个碰撞预算参数 `collision_budget_enabled`，取值为布尔值，默认 `false`。该参数在启动时读取，优先级为显式 launch 参数、运行配置、默认 false；同一名称贯穿 launch 和内核，不再提供预算 profile 或一组公开阈值参数。

| 参数值 | 行为 |
| --- | --- |
| `false` 或未指定 | 禁用碰撞性能预算；不因可选的碰撞面数、数量、内存预算或候选对阈值拒绝模型或暂停仿真。碰撞检测、防穿透和碰撞响应语义保持启用 |
| `true` | 启用统一的内部预算规则；加载超限明确失败，运行中超限在当前步提交前暂停并报告，不能跳过碰撞检测继续运动 |

关闭预算时仍检查模型合法性、有限数值、有效尺寸和内存分配失败等实际错误；它不表示物理资源无限，也不表示允许损坏模型。关闭预算不会自动减面、丢弃碰撞体或把碰撞模型替换为显示模型。现有硬编码面数、加载计数及碰撞体数量限制需要逐项分类：属于碰撞性能预算的检查必须受此开关控制，不能在关闭后由另一处旧检查重新限制。

### 启用后的内部规则

面数只是性能因素之一。内部规则覆盖网格复杂度、实例数量、碰撞体数量和受控内存，并记录候选碰撞对与查询耗时。以下数值是待基准测试校准的实现建议，全部仅在开关为 true 时执行，不作为额外的用户参数。

| 内部检查项 | 建议阈值 | 计数和行为 |
| --- | --- | --- |
| 单碰撞网格三角面数 | 10,000 | 三角化后计数 |
| 世界碰撞网格总面数 | 200,000 | 按实例累加，共用网格的多个实例仍各计一次 |
| 动态碰撞网格总面数 | 20,000 | 机器人和移动障碍合计，属于世界总额的子集 |
| 世界碰撞体数量 | 1,024 | 同时计入网格和基本几何 |
| 单动态模型碰撞体数量 | 64 | 每个机器人或移动障碍分别统计 |
| 碰撞受控内存 | 256 MiB | 资源、BVH 和工作区的分配预算；另行测量实际内存 |
| 每步候选碰撞对 | 20,000 | 在该步提交前检查，不以截断碰撞对列表来完成运动 |

每个模型的 visual／sensor／collision 统计、世界总额、开关值及内部规则版本写入诊断和运行清单。窗口只读显示“碰撞预算关闭”或“碰撞预算启用”，不提供选择模型查看详情或修改预算的入口。缓存占用按实际存储计，工作量按实例计。

SDF `<collision>` 使用人工提供的简化网格、基本几何或凸体组合。启用预算后出现超限，用户可以换碰撞网格，或下次启动将该参数设为 false。自动减面、凸分解或包围盒替代不在启动中隐式执行；整个厂房也不能被一个凸包封住内部通道。

### 其他资源限制

碰撞预算不代表总 CPU 或 GPU 上限。其他路径独立处理，不能借用这些路径的检查把已关闭的碰撞预算重新启用：

| 路径 | 限制内容 | 超限原则 |
| --- | --- | --- |
| 雷达计算 | 射线网格总量、每仿真秒射线数量、传感器数量、线程数 | 加载拒绝或显式修改配置；不偷偷改变雷达输出 |
| 图形显示 | 纹理解码大小、GPU 资源估计、显示网格量、帧率 | 默认保留资产内容；超预算报错，降低帧率不删贴图 |
| 导入 | include 深度、资源数、单文件大小、解码峰值、加载超时 | 完整场景通过检查后再提交 |
| 状态传输 | 快照频率、队列长度、静态资源缓存 | GUI 可以合并旧显示帧，算法数据链路保持独立 |

当前 Assimp 导入期间及 FCL 内部可能出现额外分配，加载计数器不能宣称是硬性 RSS 限制。需要导入前预检、峰值实测和明确的失败处理；碰撞专用的性能预算检查仅在开关开启时执行。可使用独立 worker 隔离导入失败；不能在默认关闭预算时仍按固定碰撞内存阈值终止 worker。相同网格还用于雷达或显示时，相应用途的限制及失败原因要单独标明。

计算耗时超出一个目标墙钟周期时，保持固定仿真步长，实际速率下降。不能为追赶 100% 跳过碰撞、跳过传感器事件或增大时间步长。预算关闭时不因超过可选性能阈值暂停仿真；真实运行故障仍停在最后一个完整提交状态，避免部分机器人已经推进。

## 七 仿真速率只读显示

实际实时因子 RTF 定义为一段墙钟时间内提交的仿真时间增量：

```text
实际 RTF = Δ已提交仿真时间 / Δ单调墙钟时间
显示百分比 = 实际 RTF × 100%
```

例如墙钟经过 1 秒、仿真推进 0.63 秒，显示 `实际 63%`。目标设为 `50%` 时，稳定运行的实际值应接近 `50%`，不能用“完成目标的比例”把它显示成 `100%`。`GUI 30 FPS` 只代表画面刷新，与这两个值分开。

窗口底部拟显示：

```text
运行中 | 仿真 12.50 s | 目标 100% | 实际 63% | 画面 30 FPS | 碰撞预算关闭
```

示例数值只用于说明界面，不是性能测量结果。

状态栏自动刷新，无按钮、下拉框或可编辑字段。详细计算耗时和资产统计写入 ROS 诊断及运行清单，不增加交互面板。统计规则：

1. 仿真进程用单调时钟计算，采用约 1 秒滚动窗口，每 200 ms 发布一次。启动样本不足显示“统计中”，不先显示虚假的 100%。
2. 全世界只统计一份 RTF，多机器人共享仿真时间，不累计各机器人的时间。
3. 暂停显示“已暂停”和 0%；加载、故障、无进展及统计连接中断分别显示。GUI 以墙钟刷新，不能随 `/clock` 暂停而冻结。
4. 外部接口引起暂停恢复、重置，或进程重启、重连时重新建立统计基线。使用 run ID、epoch 和序号排除旧数据，避免时间回跳产生负速率。
5. GUI 显示样本年龄。统计消息超过 2 秒未到，显示“状态连接中断”；有心跳但仿真未推进则显示“无进展”，不能混为正常暂停。
6. 状态发布使用独立定时执行路径，只读取一致性快照，避免重计算阻塞时连告警都无法刷新；该线程不能修改仿真世界。
7. 目标速率在 SDF 或 launch 中设置，例如 0.25、0.5、1.0、2.0；沿用 `0 = 不限速` 的内部语义，窗口显示“不限速”。窗口不负责暂停、单步或运行时改速率，本次不新增改速率服务。
8. 保留有限的追赶批次，避免长时间忙于追赶而阻塞已有命令和诊断。观察视角输入完全留在 GUI，不触发仿真调度修改。
9. 固定种子和按仿真时间记录的同一输入，在不同目标速率和 GUI 开关下应保持相同仿真结果；按墙钟发出的人工操作不据此承诺轨迹相同。

## 八 GUI 与内核通信

复用 ROS 2 通信，GUI 只订阅场景、状态和统计，不建立仿真控制通道。拟新增专用于显示和统计的接口，保持现有算法话题语义。

| 接口 | 作用与建议策略 |
| --- | --- |
| `/sim/scene_description` | 静态资源清单和实体层级；可靠、transient local，带场景版本和资源哈希 |
| `/sim/scene_state` | 已提交的世界位姿、关节与动态实体状态；有界队列，GUI 取最新完整快照 |
| `/sim/stats` | 世界级 RTF、阶段耗时、预算与运行状态，5 Hz 墙钟发布 |

已有 `/sim/pause`、`/sim/step` 等后端接口保持原有用途，由外部算法或命令行调用；GUI 不调用它们。本方案不新增 `/sim/set_rate`。

具体消息定义在接口实现阶段冻结。场景与状态都携带 run ID、epoch、场景版本和实体 ID；GUI 重连先取得相同版本的完整场景，再应用状态。ROS executor 和 GUI 渲染线程使用有界快照交接，不能在回调中直接操作图形对象。

首期 GUI 和仿真在同一台机器，读取同一资产目录。跨机器显示需要资源分发或可重定位包，不把服务端绝对路径当作远程可用地址。

GUI 可以按启动配置限制显示帧率并合并旧位姿帧，这些优化只作用于视图，不修改仿真输出。本窗口仅承担场景查看和只读统计，不增加点云、轨迹、碰撞体图层开关。此类算法或几何检查继续通过可选 RViz2 和离线测试完成。

首次带 GUI 启动时，由 launch 的就绪管理在模型和材质加载成功后放行运行，无需界面确认。运行中窗口关闭或崩溃不改变仿真运行状态，仿真继续且允许 GUI 重连。操作系统的窗口关闭只结束查看器；整体 Ctrl+C 负责清理两端进程及导入 worker。

## 十二 首期范围

首期交付包括统一 SDF 导入、指定位置的 litesim_models 资源包及 share 路径查找、纯查看独立三维窗口、约定范围内的完整材质和贴图、默认关闭的单参数碰撞预算、实际 RTF 只读显示以及现有 ROS 2 接口回归。

窗口不承担仿真控制、模型操作或场景编辑。在线 Fuel 浏览下载、Gazebo 外部动力学插件执行、任意模型格式与任意 shader 全兼容不列入首期。原有后端控制能力继续供外部程序使用，多机完整会话重置仍按现有能力单独规划。

本方案新增的主要成本在 SDF 语义接入、渲染适配和几何资源分离。独立窗口解决了 RViz2 渲染集成的限制，但图形依赖和 GPU 占用仍需实测。下一步应从 P0 的小型验证开始，再按通过条件推进。
