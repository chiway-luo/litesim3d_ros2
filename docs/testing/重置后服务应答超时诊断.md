# 重置后服务应答超时诊断

日期：2026-10-19。范围：Ubuntu 22.04 / ROS 2 Humble，单机与多机 C++ 服务端。

## 原始失败与根因

提交 `8bcdbff563b35f53e12acf8bdb58cce7ad1247d8` 的 [CI 39227953101](https://github.com/chiway-luo/litesim3d_ros2/actions/runs/39227953101) 中，`m1_m3` 在第 99 个会话（完成 98 次重置后）的首次 `/sim/step` 失败；同提交的独立分包任务通过。这是间歇性失败，不能用另一个任务的通过覆盖。

原始 `epoch-0099/litesim3d.log` 出现 `client will not receive response`。消费者已经收到点云、IMU 和里程计，说明请求已执行；客户端却未收到服务结果，最终触发原有 6 秒超时。

Humble 的 [rmw_fastrtps 应答实现](https://github.com/ros2/rmw_fastrtps/blob/humble/rmw_fastrtps_shared_cpp/src/rmw_response.cpp) 会等待客户端的应答订阅者与服务端写者匹配。请求通道可用不代表应答通道已完成发现；等待超过 writer 的 blocking time 时返回 `RMW_RET_TIMEOUT`，该分支尚未写出应答。[rclcpp 的默认处理](https://github.com/ros2/rclcpp/blob/humble/rclcpp/include/rclcpp/service.hpp) 只警告、清除错误并返回，没有保留应答。新建客户端与重启服务端使这条发现竞态更容易出现。

这与先前的 Lima 系统时间回拨/点云旧帧问题不同；本次修改不调整系统时间、DDS 全局配置或传感器队列。

## 实现与边界

[service_responses.hpp](../../litesim3d_ros2/src/service_responses.hpp) 使用 rclcpp 延迟应答回调与公开的 RCL 发送接口，供两个节点的 pause、step 和单机 set_pose 共用：

- 业务回调执行一次，保存原始请求 GUID、序号及响应对象；仅发送超时才进入重试。
- 使用单调时钟保留最多 2 秒，每个服务最多 16 个待发应答；队列满时在业务回调之前拒绝请求，写出明确错误。
- 50 ms 墙钟定时器每次最多尝试一个应答；RMW 单次发送本身仍可能按其中间件 QoS 阻塞。服务和定时器使用同一个默认互斥回调组。
- 超期记录失败并释放响应；非超时错误继续抛出；退出时不等待队列排空。状态没有跨进程或跨 reset 保留。
- 不重发请求，不增加客户端的 6 秒等待，不修改原来的 100 次完整重置检查。

这是有界的暂态发送故障恢复，不能保证已离线客户端收到结果。客户端最终超时仍需按结果未知处理。Step 的应用级去重缓存也仅在当前仿真实例有效。

## 可重复验证

[新增回归](../../litesim3d_ros2/test/test_service_responses.py) 在 pytest 临时目录编译 Linux 动态库，仅给测试子进程注入 `rcl_send_response` 返回值。故障库不安装，不链接进产品，也不修改系统 ROS 库。

```bash
source /opt/ros/humble/setup.bash
source "$(python3 scripts/paths.py install)/setup.bash"
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q \
  litesim3d_ros2/test/test_service_responses.py
```

6 项故障注入测试覆盖单机/多机连续 3 次发送超时后恢复、同一请求身份和精确步数、持续超时后的清理、队列满时不执行新命令、永久错误不重试，以及有待发应答时退出。macOS 不支持该 Linux 注入方式，只跳过这些注入用例，普通 ROS 回归仍执行。

在原 ARM64 安装上，恢复用例确实失败于 6 秒超时；修复后 6 项全部通过。完整 ROS/launch 回归及当前提交 CI 的最终状态以对应运行记录为准。

证据位于外部 `evidence/reset-step-response-20261019/`，包含旧版失败对照、构建日志、JUnit、每次发送的请求身份与结果，以及后续 CI 记录。旧 CI 原始证据保留在 `evidence/fastdds-old-frame-20261019/ci-39227953101/`。
