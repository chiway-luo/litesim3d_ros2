# 文档维护与构建

读者入口分为入门教程、任务手册、接口参考、原理说明和版本状态。历史设计与测试报告保留在原目录，当前行为以当前源码、接口和教程为准。

## 内容的唯一来源

| 内容 | 维护位置 | 检查方式 |
| --- | --- | --- |
| 消息/服务字段 | `litesim3d_interfaces` 的 `.msg/.srv` | 接口页代码块逐字匹配 IDL |
| launch/节点参数名称 | launch 声明、节点 declare_parameter | 检查参考文档是否覆盖声明 |
| 插件参数说明、单位、范围 | 各实现包 `config/parameters.yaml` 的相邻注释 | 生成逐插件表格，检查是否过期 |
| 插件必填项/默认值 | 实现 `defaults()` | 静态核对必填注释；安装后契约测试核对默认文件 |
| 教程命令 | `docs/tutorials` 标记代码块 | 教程检查器直接读取并执行，不另写一套命令 |
| 当前验证结果 | 对应运行的报告和证据 | 平台、提交、脏工作树、文件哈希与未测范围一起记录 |

启动参数的**值与语义**仍需维护者审阅；名称覆盖检查不能证明全部语义正确。图示源文件为 `docs/images/*.dot`，对应 SVG 与 Markdown 一同维护。

## 修改后检查

在准备了 Python 3 和 PyYAML 的环境，从源码根目录执行：

```bash
python3 scripts/docs/generate_plugin_reference.py --write
python3 scripts/checks/check_repository_docs.py
python3 scripts/checks/check_api_docs.py
python3 -m unittest discover -s scripts/checks -p test_documentation_checks.py
```

生成器只写自己负责的插件参数页。更改实现默认值时同步更新参数文件，并运行现有插件契约测试；静态检查不会替代编译和动态加载验证。

在已构建并加载 Humble 的环境执行教程检查：

```bash
python3 scripts/checks/check_documented_tutorials.py --domain-id 91
```

默认创建新的临时证据目录；也可以传入尚不存在的 `--output` 目录。检查器先拒绝已在使用的仿真 domain，仅清理自己启动的进程组。它覆盖无界面教程，不测试 GUI、外部导航或真实设备。

CI 中这组教程位于构建成功之后，证据随原回归产物上传。只有对应 workflow run 真正成功，才能写该提交的 Ubuntu 验证通过。

## 构建可搜索文档站

文档站使用 [Sphinx 项目](../../sphinx-docs/README.md)，从当前 Markdown 生成独立预览。每次输出到新的空目录，转换前后核对源文件哈希；不会用站点副本覆盖原文。

构建依赖与命令、搜索限制、发布快照方式见该项目说明。发布或推送需单独授权；本地 HTML 生成不代表站点已上线。

## 教程编写模板

每篇教程至少说明：目标、前置条件、完整文件位置、逐步命令、预期输出、成功判据、退出方法、常见失败和下一步。无需网络下载或额外设备的最小示例优先进入自动检查。

新命令需要自动运行时，使用现有 `tutorial-command` 标记格式并显式加入检查器；检查器不会执行任意文档代码块。负例必须声明预期非零返回码，不能因输出里出现某个词就判定通过。
