# 安装与构建

## 环境要求

使用 ROS 2 Humble、CMake ≥ 3.20、C++17 编译器、Python ≥ 3.10、colcon。核心依赖 Eigen3、urdfdom、Assimp、FCL、yaml-cpp、tinyxml2、OpenSSL、nlohmann_json；ROS 桥接另需 PCL、rclcpp/rclpy、ROS 消息包、launch、robot_state_publisher 和 PyYAML。SDF 导入依赖 libsdformat12，独立三维窗口依赖 ignition-rendering6、Qt5 Widgets 和 Qt5 SVG（应用图标）；RViz 用于可选算法可视化，Xacro 用于模型预展开，GTest/pytest/launch_testing 用于测试。

Ubuntu 22.04 的 Humble 安装与项目 apt 依赖命令见 [README](../../README.md#准备环境)。Ubuntu Jammy 是 Humble 二进制发行目标，安装方式见 [ROS 官方文档](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html)。这里描述可复现的目标环境，具体版本的实测记录见 [测试文档](../testing/README.md)。其他 ROS 发行版尚未验证。

macOS 使用自行配置并激活的 RoboStack Humble 环境，需在该环境内提供上述依赖和 Python ROS 模块。构建脚本会仅为这次构建选择 Xcode Clang 与 SDK，需要已安装 Xcode Command Line Tools。仓库不提供本机别名或个人环境包装器；`ros2`、`colcon`、`python3 -c 'import rclpy'` 应在激活后可用。避免把另一 Python 环境的 ROS 模块混入当前环境。

## 推荐方式：仓库构建脚本

在已激活 Humble 的 Bash 终端运行：

```bash
git clone https://github.com/chiway-luo/litesim3d_ros2.git
cd litesim3d_ros2
bash scripts/build.sh
source "$(python3 scripts/paths.py install)/setup.bash"
ros2 pkg prefix litesim3d_core
ros2 pkg executables litesim3d_ros2
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py
```

私密仓库需要 GitHub 访问权限及 Git 认证。成功构建发现 9 个包；可执行文件包括 `sim_node`、`sim_world_node`、`sim_session`、`sim_ouster_adapter` 和 `sim_cloud_probe`。在 Zsh 中加载 `setup.zsh`，Bash 加载 `setup.bash`。后续新终端先激活基础 Humble 环境，再进入该源码目录执行 `source`；无需重复构建。

脚本为所有包统一使用 `RelWithDebInfo` 和 merged install，并默认构建测试。构建树放到 `/tmp`（macOS 为 `/private/tmp`）下按源码路径区分的 ASCII 目录，以避开 Humble 消息生成工具对中文构建路径的兼容问题。实际位置通过下列命令查询：

```bash
python3 scripts/paths.py artifacts
python3 scripts/paths.py install
```

单独 clone 时，产物入口默认在源码旁的 `litesim3d_ros2-artifacts/`；放在工作空间 `src/` 下时，默认在工作空间 `artifacts/`。其中 `build/`、`install/`、`log/` 指向实际构建树，`evidence/` 保存运行证据。临时目录被清理后重新构建即可。

需要固定位置时，可设置两个项目级变量；构建路径选用 ASCII 路径，后续终端继续使用同一个 `LITESIM3D_ARTIFACTS_DIR`：

```bash
export LITESIM3D_ARTIFACTS_DIR="$HOME/litesim3d-artifacts"
export LWS_BUILD_ROOT="$LITESIM3D_ARTIFACTS_DIR"
bash scripts/build.sh
source "$(python3 scripts/paths.py install)/setup.bash"
```

这些变量只影响本项目。切换基础 ROS 环境或构建目录时使用新终端，避免叠加旧安装前缀。

## 已有 ROS 工作空间：标准 colcon

也可以把仓库放入现有工作空间 `src/`，使用标准 colcon。以下是独立示例，和前一节的脚本构建任选一种；先准备同样的依赖。

```bash
source /opt/ros/humble/setup.bash
mkdir -p ~/litesim3d_ws/src
cd ~/litesim3d_ws/src
git clone https://github.com/chiway-luo/litesim3d_ros2.git
cd ~/litesim3d_ws
colcon build --base-paths src --merge-install --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo -DBUILD_TESTING=ON
source install/setup.bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py
```

此方式的安装目录就是工作空间 `install/`，不会生成脚本的安装前缀记录，因此不要调用 `scripts/paths.py install`。运行仓库测试脚本时，在源码根目录设置 `LWS_INSTALL_PREFIX` 为该安装目录的绝对路径；测试说明见 [测试入口](../testing/README.md)。中文路径或 macOS 编译器适配优先采用前面的构建脚本。

## 无 ROS 桥接的内核构建

在已提供核心依赖、CMake 与编译器的环境，从仓库根目录执行：

```bash
cmake -S standalone -B /tmp/litesim3d-core -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/litesim3d-core --parallel 2
/tmp/litesim3d-core/litesim3d_core/sim_headless \
  "$PWD/litesim3d_core/resources/config/demo.yaml" 200 /tmp/litesim3d-run.json 0.4 0
```

它直接执行 200 个 5 ms 仿真步并输出运行清单，不启动 ROS 节点或图形界面。
