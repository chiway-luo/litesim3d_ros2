# 传感器数据

适用版本以仓库 [VERSION](../../VERSION) 为准。操作步骤见 [使用手册](../usage/README.md)。

本文集中定义二进制布局、单位、时间和无效值；话题及 QoS 见 [ROS 2 接口](ROS2接口.md)，参数见 [配置文件](配置文件.md)。以下布局不能只靠 remap 相互替代。

<a id="native"></a>
## 原生点云 xyzirt_v1

PointCloud2 为小端，`height=rings`，`width=columns`，`point_step=24`，`row_step=columns×24`。按 ring 行、column 列组织；ring 是角度数组的零基索引，不保证按仰角大小排序。

非重复模式height=1，ring恒为0，不能当成真实机械线号；原生接口仍输出相同 24 字节 PointCloud2；Mid-360 可另选下节的 Livox 消息，仿真不模拟 UDP 设备协议。rosette用圆锥半角定义视场，不能混用水平/垂直矩形边界；spherical的两个角范围形成球面带，不表示固定空间中的点云球壳。

| 字段 | 字节偏移 | 类型 | 单位 |
| --- | --- | --- | --- |
| x/y/z | 0/4/8 | float32 | m，传感器局部坐标 |
| intensity | 12 | float32 | 合成归一化反射率 [0,1] |
| ring | 16 | uint16 | 线号，从 0 开始 |
| 保留字节 | 18–19 | 两个零字节，无 PointField | 不作数据解释 |
| time | 20 | float32 | 相对 header 的秒 |

无回波、丢点、噪声后越界点保留槽位，xyz 写 NaN、intensity 为 0，ring/time 仍保留；存在无效点时 `is_dense=false`。算法先过滤非有限 xyz；不能把 NaN 当作原点或把所有强度为 0 的点都认为无效，因为实体可设反射率 0。

可选的`<topic>/range_boundary`使用相同布局、帧时间、ring/time和QoS：在最大量程内没有几何命中的方向，xyz为`单位方向×max_range_m`；其他槽位为NaN，intensity为0。它是最大范围可视化，不是回波，也不用于建图。视场裁剪、盲区遮挡、随机丢点和噪声后越界不生成最远点；辅助topic与其他雷达/IMU topic不能重名。四轮示例用淡蓝色单独显示，详见雷达配置说明。

当前 intensity 是命中实体的固定 reflectivity，不含真实光功率、入射角衰减或材料标定。随机种子和相同输入可复现噪声；改变线程数不会靠共享随机引擎重新打乱点槽位。

### 时间与滚动畸变

`header.stamp` 是扫描开始的仿真时刻。snapshot 所有点 `time=0`；rolling 第 r 线、第 c 列的相对时间为：

```text
time(r,c) = c / (rate_hz × columns) + ring_delays_s[r]
```

内部采样时间四舍五入到整数纳秒，原始 `time` 字段用 float32 秒。ring 延迟必须落在一个列周期内，最后一个采样必须在本扫描周期结束前；snapshot 不允许非零 ring 延迟。

rolling 坐标在**该点采样时刻的雷达局部坐标系**中，整帧只在最后一个点采完后发布。这就是运动畸变来源；消费者不能把它当作已经对齐到扫描起点的去畸变云。需要去畸变时，用每点时间及 IMU/估计运动插值完成，时间单位转换要与目标算法一致。

<a id="livox"></a>
## Mid-360 的 Livox 输出

在示例 launch 中，lidar_interface=auto 仅将 scan_pattern=livox_mid360 的雷达转换；native 保留上节布局；livox 要求存在 Mid-360。每台机器人最多一个 Livox 输出雷达。无效 xyz 被过滤，因此点数可能小于原始槽位数。

### CustomMsg（xfer_format=1）

定义来自随仓库的 [CustomMsg.msg](../../livox_ros_driver2/msg/CustomMsg.msg) 和 [CustomPoint.msg](../../livox_ros_driver2/msg/CustomPoint.msg)。

| 字段 | 类型 | 仿真输出语义 |
| --- | --- | --- |
| header | std_msgs/Header | stamp 为帧起点，frame_id 为带前缀雷达 link |
| timebase | uint64 | 帧起点，绝对仿真纳秒 |
| point_num | uint32 | 过滤无效点后的 points 长度 |
| lidar_id | uint8 | livox_lidar_id 参数 |
| rsvd | uint8[3] | 零 |
| points[].offset_time | uint32 | 相对帧起点的纳秒；由扫描时序直接计算 |
| points[].x/y/z | float32 | 采样时刻雷达坐标，米 |
| points[].reflectivity | uint8 | 原合成强度限制 [0,1] 后乘 255 并取整 |
| points[].tag | uint8 | 0，合成普通回波，不模拟设备置信度 |
| points[].line | uint8 | 全局原始槽号 mod 4；过滤后不重排线号 |

CustomMsg 模式同时提供 `livox/lidar/pointcloud`，用于标准 PointCloud2 消费者。

### Livox PointCloud2（xfer_format=0 或辅助显示）

小端，height=1，point_step=26，row_step=width×26，is_dense=true；有效点按原始槽顺序保留。此处 timestamp 是 **float64 绝对纳秒**，不能按秒或相对偏移解释。

| 字段 | 偏移 | 类型 | 单位 / 语义 |
| --- | --- | --- | --- |
| x/y/z | 0/4/8 | FLOAT32 | 米 |
| intensity | 12 | FLOAT32 | 0–255 的整数反射值，以 float 存放 |
| tag | 16 | UINT8 | 0 |
| line | 17 | UINT8 | 原始全局槽号 mod 4 |
| timestamp | 18 | FLOAT64 | 帧起点纳秒 + 本点偏移纳秒 |

显式启用的 range_boundary 使用同一 26 字节布局，仅供显示，不能当作障碍回波。原生 xyzirt、Livox PointCloud2 和 CustomMsg 的强度/时间单位不同；Ouster 适配器只接受原生 xyzirt_v1。

来源：[Livox 转换实现](../../litesim3d_ros2/src/livox_outputs.cpp)。

<a id="ouster"></a>
## Ouster original 适配布局

| 输出字段 | 偏移 | 类型 | 语义 |
| --- | --- | --- | --- |
| x/y/z | 0/4/8 | float32 | 米 |
| intensity | 16 | float32 | 原归一化合成强度 |
| t | 20 | uint32 | 相对 header 的纳秒，由原 time 秒值四舍五入 |
| reflectivity | 24 | uint16 | 有效点 intensity×65535 四舍五入，非真实标定反射率 |
| ring | 26 | uint16 | 原线号 |
| ambient | 28 | uint16 | 0，未建模 |
| range | 32 | uint32 | 距离毫米，无效点 0 |

小端、48 字节 point_step，偏移 12 是 PCL 齐次坐标 1，其余填充为 0。无回波 xyz 保留 NaN。布局、长度、时间或范围越界时拒绝整帧，并在 adapter_status 记录 rejected/error。

适配器保留 header/frame、组织尺寸、点坐标；输出 intensity 仍为原生 [0,1] 合成强度。它只做字段兼容，不模拟型号专属回波。操作见 [点云适配](../usage/点云适配.md)。

<a id="imu"></a>
## IMU

标准 sensor_msgs/msg/Imu，header 使用采样时刻和配置的安装 link。角速度单位 rad/s，加速度为安装坐标下的比力：

```text
specific_force_I = transpose(R_WI) * (acceleration_WI - gravity_W)
gravity_W = [0, 0, -9.80665] m/s²
```

包含安装偏心的切向/向心项；水平、静止、无噪声且安装轴一致时输出约 [0,0,9.80665]。先加三轴固定偏差和每样本高斯噪声，再按可选对称量程裁剪。sigma 不是噪声密度；没有随机游走姿态估计。

orientation_covariance[0]=-1，orientation 是占位值；已知噪声方差写加速度/角速度协方差对角线，全零不等于实际无误差。碰撞/重置等运动不连续不代表真实冲击测量。

<a id="odometry"></a>
## 测量里程计与关节

odom 使用 nav_msgs/msg/Odometry，pose 在局部 odom 坐标，twist 在 child_frame_id 指定的 base 坐标。每台机器人以初始位姿作为局部原点。组合模型的里程计由编码器插件独立积分；旧 YAML 保留兼容实现。

continue_on_collision=true 时车体受阻、编码器仍累计，理想轮式 odom 也可能偏离真值；激光、IMU、相机继续按真实车体采样。ideal 仅表示未增加测量噪声。当前插件运动路径的 ROS 里程计协方差仍使用核心的零默认值，不能通过旧 YAML odom 节给插件设置协方差。兼容路径的协方差使用 36 个元素的行主序矩阵，顺序 x/y/z/roll/pitch/yaw（twist 为对应速度）；不会自动把速度 sigma 传播成位置协方差。

joint_states 使用 sensor_msgs/msg/JointState，与同一展开 URDF 中名称一致，转动关节为 rad、rad/s，移动关节为 m、m/s；连续轮角未取模。RSP 负责据此计算内部 TF。

<a id="camera"></a>
## RGB、深度与 CameraInfo

| 通道 | 编码 | 语义 |
| --- | --- | --- |
| color/image_raw | rgb8 | 三通道彩色字节，来自 visual 几何、材质与贴图 |
| depth/image_raw | 32FC1 | float32 光学 z 方向深度，米；无效值 NaN |
| color/camera_info、depth/camera_info | CameraInfo | 与图像同时间、同 optical frame、同分辨率 |

光学坐标 +z 前、+x 右、+y 下。RGB-D 为同位姿、同分辨率、同内参的逐像素注册输出。内参 fx=fy=width/(2 tan(horizontal_fov/2))，cx=(width−1)/2、cy=(height−1)/2；D 为五个零、R 为单位阵。深度不是欧氏射线长度。

标准相机插件可加 RGB DN 偏差/噪声及米制深度偏差/噪声。RGB 取整并裁剪到 [0,255]；已有无效深度保持无效，噪声后超出裁剪范围转 NaN。默认偏差/噪声为零；不模拟曝光、滚动快门、真实双目基线和 ToF 多径。

相机使用仿真采样时刻的真实位姿；同一时刻批次完成渲染后发布，渲染变慢会降低实际 RTF。暂停停止采样；没有额外深度点云或压缩图像输出。使用入口见 [车载相机](../usage/SDF与独立窗口.md#车载-rgb-与深度相机)。
