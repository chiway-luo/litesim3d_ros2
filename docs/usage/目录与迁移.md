# 目录与迁移

本项目以一个多包源码仓库发布，核心与 ROS 桥接共同版本管理。与 [stage_ros2](https://github.com/tuw-robotics/stage_ros2) 单独桥接 [Stage](https://github.com/tuw-robotics/Stage) 内核的方式相比，这里将内核、接口与桥接放在同一仓库，便于同时修改内核、消息与桥接并运行集成验证。

| 目录 | 职责 |
| --- | --- |
| `litesim3d_core/` | 不依赖 ROS 运行时的计算、几何、传感器、资源和核心测试 |
| `litesim3d_interfaces/` | 消息与服务生成；避免接口依赖仿真实现 |
| `litesim3d_ros2/` | ROS 节点、launch、RViz 与跨进程会话管理 |
| `litesim3d_assets/` | SDF 导入与包内资源测试夹具 |
| `litesim3d_gui/` | 独立查看器、RGB/深度相机与图像预览 |
| `litesim3d_bringup/` | 通用 SDF/旧式 YAML 启动流程，只接收模型与配置参数 |
| `litesim3d_test_support/` | 共享 DDS/进程测试辅助库，仅供测试依赖 |
| `examples/wheel_car_4w/` | wheel_car_4w_models 小车资源、四轮 description 和 sim 示例包 |
| `examples/drone_3d/` | drone_3d_models 无人机资源，以及 drone_3d_sim 配置、启动与测试 |
| `standalone/` | 普通 CMake 构建入口，`COLCON_IGNORE` 防止 colcon 重复发现 |
| `docs/usage/` | 当前安装、操作、配置流程与排障 |
| `docs/api/` | 话题、消息/服务、参数、数据布局与开发接口 |
| `docs/development/` | 外部插件实现、安装和验证流程 |
| `docs/testing/` | 测试入口、门槛、历史结果与证据说明 |
| `docs/design/` | 开发设计和阶段规划 |
| `docs/examples/` | 手册配套 YAML 和 Python 程序 |
| `scripts/` | 构建、测试、检查、夹具、性能与报告工具 |

源码根目录没有 `CMakeLists.txt`，因此 colcon 能继续向下发现各个 ROS 包。构建产物在仓库外：源码可独立 clone，历史日志和旧构建树不混入 Git，也不作为正常启动的输入。

## 从旧包名迁移

| 原名称 | 当前名称 |
| --- | --- |
| `lightweight_sim_ros` | `litesim3d_ros2` |
| `lightweight_sim_core` | `litesim3d_core` |
| `lightweight_sim_interfaces` | `litesim3d_interfaces` |
| `lightweight_sim/sim.hpp` / C++ 命名空间 `lws` | `litesim3d/sim.hpp` / `litesim3d` |
| ROS 节点 `/lightweight_sim`、`/lightweight_world` | `/litesim3d`、`/litesim3d_world` |
| `litesim_models` 小车模型与场景 | `wheel_car_4w_models`，位于 `examples/wheel_car_4w/` |
| `litesim_models` 无人机模型与场景 | `drone_3d_models`，位于 `examples/drone_3d/` |

重新构建并加载新安装环境；同步修改外部程序的包依赖、消息导入、`package://` URI 和按节点名匹配的参数 YAML。可执行文件名、话题/服务路径及 `LWS_*` 环境变量保留。历史报告中的旧名称和源码指纹仍表示原执行版本。

模型包拆分后，默认小车与无人机启动命令不变。自行设置 `assets_root` 或查询 `litesim_models` share 路径的程序需改用对应模型包。旧 merged install 可能残留原包的安装文件；迁移时使用新的构建目录并加载新安装环境，目录设置见 [安装与构建](安装与构建.md)。

## 模块依赖边界

核心不读取仓库父目录；SDF 导入器不依赖小车或无人机；公共 bringup 只依赖仿真模块和 ROS 组件。两套示例分别提供自己的模型、配置及启动默认参数。共享测试类从已安装的 `litesim3d_test_support` 导入，不能通过 `sys.path` 引用其他包的测试源码。

旧的小车与无人机 launch 命令继续有效。自定义模型可直接使用 `litesim3d_bringup` 的 `simulation.launch.py`，显式传入 `assets_root`、`world`、`runtime` 和 `params`；使用命名雷达预设时再传入 `lidar_profiles_dir`。
