# 版本与验证状态

本文面向 **0.4.0 开发树**，版本号的唯一来源为 [VERSION](../VERSION)。开发分支为 `humble`；版本号本身不表示已经创建发布标签，也不表示当前改动全部通过验收。发布记录见[开发日志](../CHANGELOG.rst)。

## 确认自己使用的源码和文档

安装、示例和文档应来自同一份检出；不要用当前分支的接口说明推断旧安装包的行为。在源码根目录保存：

```bash
cat VERSION
git rev-parse HEAD
git status --short
git describe --tags --exact-match
```

最后一条只在当前提交恰好有标签时成功；没有标签时按开发快照使用。工作区不干净时，提交 SHA 不能唯一标识运行内容，验证报告还须保留涉及文件的哈希。文档站构建记录源文件哈希，页眉展示版本、基础提交及是否存在本地修改。

## 接口兼容范围

| 接口 | 使用约定 |
| --- | --- |
| ROS 消息与服务 | 以同一检出中的 IDL 为准；字段、类型或语义变化须记录迁移说明 |
| 标准插件参数 | 未知键与非法组合拒绝；类型、必填项和默认值见[参数参考](api/plugins/README.md) |
| C++ 与插件 ABI | `api_version=1` 不是跨版本二进制兼容承诺；升级核心后按对应公开头文件重新编译插件 |
| JSON 诊断/manifest | 容忍新增字段；字段语义以对应源码版本为准 |
| 旧 YAML | 保留的兼容入口见[兼容配置](usage/兼容配置.md)，不与组合模型的重复声明混用 |

## 发布时怎样冻结文档

1. 完成当前提交的文档、教程和相关功能检查，保存运行环境及证据。
2. 将用户可见变化整理到版本说明，包含破坏性变化、迁移方法和未验证范围。
3. 在明确发布授权后，为代码和文档使用同一版本标签；从该标签生成独立站点快照。
4. 新开发文档继续标记开发版，不覆盖已发布版本。没有发布标签时，不提供虚假的版本切换选项。

维护与构建命令见[文档维护](development/文档维护.md)。
