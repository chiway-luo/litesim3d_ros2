# M2 使用与复现

本文介绍坡面、滚动扫描、噪声、IMU 和单机会话重置。首次使用先完成 [安装与构建](安装与构建.md)，并在每个终端加载相同环境。

## 构建与运行

从仓库根目录、已激活 Humble 的终端执行：

```bash
source "$(python3 scripts/paths.py install)/setup.bash"
export ROS_DOMAIN_ID=160 ROS_LOCALHOST_ONLY=1
prefix="$(ros2 pkg prefix litesim3d_core)"
ros2 launch litesim3d_ros2 demo.launch.py config:="$prefix/share/litesim3d_core/config/m2.yaml" rviz:=true
```

`demo.yaml` 保持 M1 的 snapshot/平地/无 IMU 默认值。`m2.yaml` 开启连续地形、rolling 激光、200 Hz raw IMU 和 4 个射线线程。默认场景仍是基础几何；性能夹具通过 `scripts/fixtures/generate_m2_fixtures.py` 单独生成，不能用基础场景成绩代替 B1。

## 新增配置

| 字段 | 默认值及语义 |
| --- | --- |
| `simulation.threads` | 1，允许 1–4；稳定槽位索引和计数式随机数保证线程数不改变数据 |
| `simulation.history_limit` | 8192 条轨迹状态；按扫描周期和采样事件预算预检，运行时仍检查上界 |
| `simulation.journal_limit` | 4096 条最近命令、接触记录；总数及截断数单独记录 |
| `terrain.enabled` | false；启用支撑高度、坡度和层连续性检查 |
| `terrain.max_slope_deg` | 20，超限停车 |
| `terrain.clearance_m` | 0，base 基准相对支撑面高度 |
| `terrain.continuity_m` | 0.02，支撑层关联范围；不自动跨越台阶和空洞 |
| `lidars[].scan_mode` | snapshot 或 rolling |
| `lidars[].ring_delays_s` | 缺省全零；非空时数量必须等于 rings，每个值在一个列周期内 |
| `lidars[].range_sigma_m / range_bias_m` | 0；对物理有效量程叠加高斯噪声/固定偏置 |
| `lidars[].dropout` | 0；0–1，丢点保留槽位并写 NaN |
| `imus[]` | 缺省为空；name、link、topic、rate_hz、accel/gyro_bias、accel/gyro_sigma |
| `odom.mode` | ideal 或 noisy；noisy 支持 linear/angular_scale、bias、sigma |

IMU 的偏置与 sigma 是三轴向量；加速度单位 m/s²，角速度 rad/s。输出 `sensor_msgs/Imu`，没有估计姿态，`orientation_covariance[0]=-1`。已知噪声方差填对角线；全零表示未声明协方差。

激光 header 是扫描起点，`time` 是每点相对起点的秒偏移。坐标仍在该点采样时刻的雷达坐标系中，不能直接当作已经去畸变。扫描整帧只在最后一个采样完成后发布。暂停保留当前扫描区间；重置通过新进程丢弃旧区间。

地形使用碰撞角色中标记 `support: true` 的箱体上表面或朝上的网格面；桥底、立面和其它碰撞仍生效。按上一次支撑高度关联连续层，遇到过陡坡、空洞或台阶停车。该模型是运动学地形跟随，不含悬架、接触力或自由落体。连续坡面应使用足够细的平滑网格；非光滑拼接不能用于声称解析加速度精度。

支撑位置从 URDF 和 `robot.drive.support_links` 获取。圆柱轮检查轮宽中心及两侧边缘，四轮模型会检查所有声明的轮子；球形支撑检查中心投影，其他形状检查保守包围框的投影角点。所有采样点都必须有连续支撑，每个支撑 link 都必须包含 collision 几何。初始加载、启动前设置位姿和步进使用相同规则。

随机流以机器人、传感器、类型、帧/样本、槽位寻址；测距与 dropout 不共享可变随机引擎。里程计误差改变测量通道，不改变 world 真值、碰撞或传感器运动。

## 协调重置

需要在线重置时，用会话管理器代替直接 launch：

```bash
evidence_dir="$(python3 scripts/paths.py evidence)"
mkdir -p "$evidence_dir"
ros2 run litesim3d_ros2 sim_session \
  --config "$prefix/share/litesim3d_core/config/m2.yaml" \
  --output "${evidence_dir}/manual-m2-session"
ros2 service call /sim/pause std_srvs/srv/SetBool '{data: false}'
```

会话启动及重置完成后都保持 paused，便于确认新 run_id 后再下发控制。通过 `/sim/status` 读取当前 run_id，调用：

```bash
ros2 service call /sim/reset litesim3d_interfaces/srv/Reset \
  '{request_id: "reset-1", expected_run_id: "填当前run_id", set_initial_pose: false}'
```

`set_initial_pose: true` 时使用请求中的 `initial_pose`；新姿态先通过独立核心预检，预检失败保留旧会话。一个 request_id 不得换载荷；重发相同请求只返回原结果。直接 `/sim/set_pose` 仍只负责实验开始前初始化，运行后的瞬移通过协调 reset 创建新实验段。

`--members members.json` 明确登记需要重启的消费/控制进程，格式为 `[ {"name": "实际ROS节点名", "argv": ["绝对可执行路径", "参数"]} ]`。管理器只停止自己创建的进程组，先停消费/控制端，再停仿真和 robot_state_publisher，然后创建新 run_id 并重新启动全部成员。成员必须以登记名称出现；该入口当前面向根命名空间的单机器人会话。

成员需要启用标准 ROS 参数服务，并在创建输入订阅后开始处理 executor。管理器通过空 `get_parameters` 请求确认 executor 已响应，等待 ROS 图补齐节点/端点归属和新仿真器的状态更新，再核对输入订阅的类型、QoS 与发布端的 DDS 匹配数。只有这些条件满足后，才记录会话 `ready` 并返回 reset 成功；仅有节点名称或 `/sim/status` 中的仿真内核 `ready` 不代表消费端已经就绪。启动阶段应等待 `session.jsonl` 中当前 epoch 的 `ready`，重置阶段等待 `/sim/reset` 成功响应，然后再发送单步或继续运行命令。

成员可额外声明 `"ready_topics": ["/points_raw", "/imu/data_raw", "/odom"]`，列出必须就绪的输入。支持配置中的雷达/IMU 话题以及 `/clock`、`/odom`、`/joint_states`。未声明时会自动记录已发现的这些输入，并在重置时保留旧 epoch 的订阅要求；异步初始化或延后创建订阅的节点应显式列出输入。缺失订阅、QoS 不兼容、executor 未响应或成员退出都会使启动/重置失败，日志记录具体成员和话题。等待上限仍为 `--timeout`，没有固定预热休眠或额外仿真步。

未登记的传感器、odom、TF、clock 消费节点会阻止 reset；只读观察节点可用 `--observer 节点名` 显式豁免。豁免不会允许未管理的 cmd_vel 发布者存活跨越重置。GUI 若需要保留，必须作为只读观察端处理并自行清理显示缓存；正式 TF/算法历史重置验收应把这些消费端登记为成员。

`session.jsonl` 保存每轮 run_id、子进程 PID、启动、退出及重置结果。每轮拥有独立目录和 manifest。成员异常退出会终止会话并返回非零；不会只因管理器仍存活就报告通过。

## 资源与测量边界

`/sim/status` 包含 IMU/点云生成计数、BVH 构建数、轨迹/日志容量、不连续事件数、最近 4096 帧计算及桥接延迟 p99。射线 BVH 在加载或显式实体更新时构建；静态帧不会重建。

传感器 DDS 是 keep_last 5，默认 best effort。内部扫描不会为维持表面频率而跳过；过载会真实减慢仿真。DDS 接收丢包无法由发布端完整获知，状态明确写为 unknown，测试从消费端时间戳检测缺口。命令与接触内存记录截断会写计数；需要完整外部输入回放时，另行记录命令 ROS bag，不能把截断的 manifest 当作完整记录。

暂停后只发一帧、要求首帧可靠接收的会话，应给 `sim_session` 加 `--sensor-reliable`，并让点云和 IMU 消费端也请求 reliable。若使用 `sim_ouster_adapter`，其 argv 增加 `--ros-args -p sensor_reliable:=true`，适配后话题的消费者同样使用 reliable，并在单步前等到发布端匹配。仅发布端设为 reliable、消费端仍为 best effort，不能获得可靠传输。此设置保持 KEEP_LAST 5；消费者长时间阻塞或超出缓存仍须单独测量。

加载预算及取消使用 C++ `LoadControl`，覆盖字节、三角形、取消检查和确定性分配故障注入；候选场景成功后才替换输出。未知字段、非法噪声、超出历史预算和过大单步输出在使用前拒绝。

测试命令、阶段结果与边界集中记录在 [测试文档](../testing/README.md)。
