# 三维雷达型号、扫描方式与参数

本页介绍 `wheel_car_4w` 的雷达预设与参数。先按 [安装与构建](../../docs/usage/安装与构建.md) 准备 ROS 2 Humble 环境；测试记录另见 [测试文档](../../docs/testing/README.md)。

## 1. 静态场景中的点云为什么重合

固定多线扫描中，如果车和环境都不动、测距噪声为 0，每次射线都打在相同位置，所以虽然消息持续更新，点云坐标仍然重合。`rolling` 表示帧内逐点采样时间，不会把整片场景点云转起来；它与扫描轨迹属于两个不同参数。

机械旋转雷达对静态场景的整周点云本来就可能基本重合。真实设备还存在测距波动、相位差和缺失回波；非重复扫描雷达的方向随时间变化，同一场景的单帧点分布也会变化。所有预设默认测距偏移、噪声和额外丢点概率为 0；非重复模式仍有跨帧变化的采样方向。需要误差时通过 [noise_config](../../docs/usage/传感器配置.md) 显式注入。

圆柱外壳、球形外壳并不能唯一确定点云样式。本项目按**线束排列、扫描轨迹和有效视场**建模：环扫形成多层线束，球面带模式覆盖全周的指定仰角范围，花瓣模式覆盖前向圆锥。实际回波来自物体表面；另有可选的最大量程边界图层，显示没有命中物体的射线能够延伸到哪里。

## 2. 一条命令切换预设

先按 [示例 README](README.md) 构建并 source 安装环境。关闭同一 ROS domain 的旧 launch 后，选择其中一条启动：

```bash
# 机械多线环扫：16线，水平360°，垂直±15°。
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=vlp16

# Mid-360：Livox官方逐点扫描表，360°全周，垂直-7°~52°；4秒序列循环。
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid360

# Mid-40规格参考：朝+x的38.4°圆形视场，非重复花瓣扫描近似。
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid40

# 使用 simulation.yaml 中的原始雷达段；默认值。
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=config
```

`lidar_profile` 是**启动参数**，当前需要重启该 launch，不能通过 `ros2 param set` 热切换。`config` 不做覆盖；其他预设整体替换唯一雷达的采样配置，保留原 `name/link/topic`。纯后台运行时追加 `gui:=false rviz:=false cameras:=false`。

各预设都使用同一 URDF 安装外参和示例外壳；切换的是数据模型，未替换成厂家 CAD，也不会自动修改 IMU。VLP-16、Mid-40 和普通旋转雷达仍输出 `/points_raw` PointCloud2；Mid-360 在示例 launch 中默认使用官方 Livox 点云接口，详见下节。

### Mid-360 官方点云接口

示例 launch 的 `lidar_interface:=auto` 只为 `scan_pattern: livox_mid360` 选择 Livox 接口。
其他雷达保持原有话题、24 字节布局与 QoS。独立 IMU 仍为 `/imu/data_raw`、`imu_link`、m/s²；里程计、TF、碰撞、扫描参数和机械模型均不变。不会新增或改成 `/livox/imu`。

| 启动选项 | 算法话题 `/livox/lidar` | RViz 回波预览 |
| --- | --- | --- |
| `xfer_format:=1`（默认） | `livox_ros_driver2/msg/CustomMsg` | `/livox/lidar/pointcloud`，PointCloud2 |
| `xfer_format:=0` | 官方字段布局的 `sensor_msgs/msg/PointCloud2` | 直接显示 `/livox/lidar` |

Mid-360 预设默认 `publish_range_boundary: false`，只发布实际命中回波；调试时可显式开启 `/livox/lidar/range_boundary` 辅助层，它不混入算法回波。示例 launch 会同步 RViz 模板话题；自行打开 RViz 时按上表选择。保留真实安装坐标系 `lidar_link` 及可选前缀，不把已有 TF 改名为 `livox_frame`。共享 world 的话题加机器人命名空间。

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid360
# 同一雷达，改用官方 PointCloud2 格式：
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid360 xfer_format:=0
# 需要旧版有序槽位布局的程序，可显式选择：
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py lidar_profile:=mid360 lidar_interface:=native
```

CustomMsg 与 Livox PointCloud2 的字段、纳秒时间、强度范围、通道编号和无效点处理见 [Livox 数据接口](../../docs/api/传感器数据.md#livox)。

本仓库的 [livox_ros_driver2](../../plugins/litesim3d_mid360/interfaces/livox_ros_driver2/README.md) 仅构建未经修改的官方消息定义，保留相同 ROS 类型名，不安装设备驱动或 SDK。[固定上游源码](https://github.com/Livox-SDK/livox_ros_driver2/tree/21445540f0d100dc86a7e6df312dd70bbdb4afdf)。已有官方包时按该包 README 选择单一来源。每台仿真机器人支持一个 Mid-360 官方输出，可与其他类型雷达共存。

直接启动低层 `sim_node` / `sim_world_node` 时为兼容既有配置仍默认 `lidar_interface=native`；通过 ROS 参数 `lidar_interface=auto`、`xfer_format=0/1`、`livox_lidar_id=0..255` 启用同一输出。

## 3. 厂家数据与仿真取值

| 预设 | 扫描模型 | 视场 | 本例量程 | 本例每帧槽位 / 帧率 |
| --- | --- | --- | --- | --- |
| [vlp16.yaml](wheel_car_4w_sim/config/lidars/vlp16.yaml) | 固定16线机械环扫 | 水平360°，垂直−15°~15° | 1~100 m | 16×1800 / 10 Hz，即288000槽/s |
| [mid360.yaml](wheel_car_4w_sim/config/lidars/mid360.yaml) | Livox官方80万方向扫描表，按原序发射 | 水平360°，垂直−7°~52° | 0.1~40 m | 1×20000 / 10 Hz，即200000槽/s |
| [mid40.yaml](wheel_car_4w_sim/config/lidars/mid40.yaml) | 连续双频花瓣近似 | 圆锥总张角38.4°，半角19.2° | 1~90 m | 1×10000 / 10 Hz，即100000槽/s |

VLP-16 使用指定型号的历史规格，不能拿 VLP-32 或型号家族介绍页混用。0.2°水平步进和10 Hz是本例选值，点率接近手册单回波约289344次/s；未模拟实际UDP发射时序或双回波。[VLP-16 Rev-F 手册](https://data.ouster.io/downloads/velodyne/user-manual/vlp-16-user-manual-revf.pdf)

Mid-360 的厂家量程带条件：100 klx环境下，10%反射率40 m，80%反射率70 m。本例选40 m；0.1~0.2 m区间厂家不保证精度。默认测距噪声为 0，测试噪声应独立配置。[Mid-360官方规格](https://www.livoxtech.com/mid-360/specs)

Mid-40的量程同样带反射率条件：10%为90 m，20%为130 m，80%为260 m；本例选90 m。近距过滤采用1 m，默认测距噪声为 0。[Mid-40官方规格](https://www.livoxtech.com/mid-40-and-mid-100/specs)、[官方快速指南](https://www.livoxtech.com/3296f540ecf5458a8829e01cf429798e/downloads/20190121/Livox%20Mid-40%20QSG.pdf)

Mid-360 现在使用 [Livox 官方开源仿真的 mid360.csv](https://github.com/Livox-SDK/livox_laser_simulation/blob/1cce1073633a062b92e30243a4c2920e45551bb5/scan_mode/mid360.csv)，替换此前的通用双频正弦轨迹。保留原始角度、顺序和每 5 μs 一个方向的时序，10 Hz 仍为 20000 槽/帧，未增加发射点率。CSV 的 `Time/s` 列实际为序号；天顶角按 `仰角=90°−天顶角` 转换。80万方向在4秒后循环，因此是有限参考序列，不是无限非重复模型。来源版本、SHA-256 和 MIT 许可见 [扫描表说明](../../litesim3d_core/resources/lidar_patterns/README.md)。

官方表略超标称边界（约−7.2123°~52.164°）；本例按−7°~52°裁剪，影响全表的0.21775%。裁剪只使对应槽位无效，不把边缘压平，也不把剩余点重新均匀排布。RViz单帧密度改善来自正确的方向分布，`Decay Time=0` 即可比较；累积多帧属于另一个显示选项。

通用 `spherical` 和 `rosette` 仍使用双频近似，100 Hz的 `pattern_hz` 属于仿真假设。各模式均未复刻逐台标定、光束发散、材质/天气衰减、多回波或厂家覆盖率测量方法；固定高斯噪声也是简化。反射率目前影响合成 intensity，不自动决定探测距离。

## 4. 配置自己的视场和有效距离

复制一种预设，修改后通过绝对路径启动。例如裁剪 Mid-360 到车前方120°、垂直−5°~35°，有效距离0.3~25 m：

```bash
mkdir -p config/local
cp examples/wheel_car_4w/wheel_car_4w_sim/config/lidars/mid360.yaml config/local/my_lidar.yaml
```

编辑 `config/local/my_lidar.yaml` 中的 `lidar` 段：

```yaml
lidar:
  scan_pattern: livox_mid360
  pattern_file: package://litesim3d_core/lidar_patterns/mid360.csv # 官方顺序，随包安装。
  scan_mode: rolling
  rate_hz: 10.0
  columns: 20000                  # 与rate_hz相乘必须为200000；裁剪不向小视场补点。
  rings: 1
  horizontal_start_deg: -60.0    # 前向视场左/右边界，0°为传感器+x。
  horizontal_end_deg: 60.0
  vertical_min_deg: -5.0         # 俯仰角裁剪下界。
  vertical_max_deg: 35.0         # 俯仰角上界。
  min_range_m: 0.3               # 近距过滤。
  max_range_m: 25.0              # 最大距离。
  publish_range_boundary: true   # 无命中时在25 m处生成辅助边界，独立话题，不用于建图。
  range_sigma_m: 0.01            # 1 cm随机测距标准差。
  range_bias_m: 0.0              # 固定偏差。
  dropout: 0.01                  # 人工模拟1%的额外丢点；非厂家指标。
  ring_delays_s: []
  point_layout: xyzirt_v1
  self_filter: robot
  excluded_links: []
```

```bash
ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  lidar_profile:="$PWD/config/local/my_lidar.yaml"
```

也可以把 `lidar` 内这些字段放到完整 `simulation.yaml` 的 `lidars[0]`，补上 `name/link/topic` 后以 `lidar_profile:=config config:=...` 启动。这样核心 headless 和多机器人 world 也能使用新增扫描模式；预设选择快捷参数仅由本例 launch 提供。

圆形视场选 `rosette`，只用 `cone_half_angle_deg` 控制张角。它围绕 `lidar_link` 的+x轴，朝向通过URDF安装关节的rpy设置；不能再混用水平/垂直矩形边界。球面带 `spherical` 可以设置水平与垂直角范围，设−90°~90°可覆盖整个高度方向，但这不代表Mid-360实际有如此大的视场。

`livox_mid360` 扩大视场参数不会生成原始表没有的方向；缩小则屏蔽原有射线。`pattern_file` 支持绝对路径、package URI，或相对自定义预设文件的路径；直接放入完整配置时相对于该配置文件。不要为此模式设置 `pattern_hz` 或圆锥半角。

## 5. 接口与显示参考

本页负责预设选择与运行检查。字段默认值和约束见 [雷达配置参考](../../docs/api/配置文件.md#lidars)，原生点云、Livox 和 Ouster 的布局、时间单位、无效点和强度语义见 [传感器数据](../../docs/api/传感器数据.md)。

### 空旷方向与最远距离点

有最大测距范围，不等于设备在没有回波时必然输出该最大值。输出编码取决于型号和驱动，例如Livox对Horizon的官方说明是：没有目标或超量程时，笛卡尔坐标输出零点，球坐标距离为0；这不是关于Mid-360编码的声明。[Livox官方点云说明§3.3](https://livox-wiki-en.readthedocs.io/en/latest/introduction/Point_Cloud_Characteristics_and_Coordinate_System%20.html)

本例启用 `publish_range_boundary: true` 后，RViz同时显示两层。下表为 native 模式；Mid-360 默认模式使用前述 `/livox/lidar/pointcloud` 和 `/livox/lidar/range_boundary`：

| 图层 / 话题 | 有效点含义 |
| --- | --- |
| **3D Lidar** / `/points_raw` | 测到物体的回波；无有效回波的槽位仍为NaN，供算法使用 |
| **Max Range Boundary (Synthetic)** / `/points_raw/range_boundary` | 当前视场内、最大量程以内没有几何命中的射线，其终点为`单位方向×max_range_m` |

因此空场和超量程目标的方向能看到最远距离点。Mid-360参考配置的这些点距离雷达原点为40 m，且仅位于−7°~52°仰角内，形成球面带而非完整球壳。已有物体的方向不补点；视场裁剪、盲区内遮挡、随机dropout和噪声越界也不补点。

辅助点云仅供显示，不能接入 SLAM/导航。完整数据布局和 QoS 见 [传感器数据](../../docs/api/传感器数据.md#native) 与 [ROS 2 接口](../../docs/api/ROS2接口.md)。如果只需原始回波，关闭 publish_range_boundary 后重启；只隐藏显示时取消 RViz 对应图层勾选。

## 6. 检查输出与帧间变化

使用 `lidar_profile:=mid360 rviz:=true` 时，四轮车入口自动选择 [Mid-360 点云视图](wheel_car_4w_sim/rviz/mid360.rviz)：2 像素点、仅当前帧、按 odom 高度 0~3 m 固定着色；关闭最大量程层、实体场景、TF 和轨迹，避免遮挡点云。独立三维窗口仍显示场景和车辆。其他雷达的默认视图保持不变，显式 `rviz_config:=/路径/自定义.rviz` 优先。

需要查看 Livox PointCloud2 输出时，可这样启动：

```bash
ROS_DOMAIN_ID=70 ros2 launch wheel_car_4w_sim wheel_car_4w.launch.py \
  lidar_profile:=mid360 xfer_format:=0 gui:=true rviz:=true
```

该视图使用单帧点云和固定高度着色：仍使用现有扫描表、10 Hz 和每帧 20000 个发射槽位，未增加点率或改变射线求交。有效点数量取决于命中场景；安装高度、倾角和环境不同，地面覆盖与墙面轮廓也会不同。显示配置不改变雷达测量、车辆或其他传感器。

RViz选择 **3D Lidar**，`Decay Time=0` 显示最新帧，适合看非重复扫描的帧间变化；增加到0.5~1秒可观察多帧累积，但会掩盖单帧变化。`Style=Points/Squares`、点大小和颜色只改变显示，不改变雷达发射轨迹。原始点云不会随着机械扫描整片旋转。

最大量程边界通常比场景大很多：Mid-360为40 m，而默认相机距离只有7 m。将Views中的Distance调到约60~100 m或滚轮缩小，便于看完整边界；需要看小车细节时再放大。边界半径始终是雷达坐标下的`max_range_m`，不是相机距离，也不是世界原点到点的距离。

在相同环境和 domain 的另一个终端检查原生接口；使用 Livox 输出时将 /points_raw 换为上文对应的 PointCloud2 话题：

```bash
ros2 topic hz /points_raw
ros2 topic echo /points_raw --once --field header --qos-reliability best_effort
ros2 topic echo /sim/status --once
```

如果时间戳不变，检查是否暂停；时间戳变、固定环线基本重合，则可能是静态机械扫描的正常现象。想看车运动时的变化，按示例README发布 `/cmd_vel`。RViz的Fixed Frame为odom时，固定环境应基本稳定，运动的是小车及其相对传感器采样。

扫描方向、时序、裁剪和共享 world 遮挡的历史验证集中记录在 [四轮车与雷达测试](../../docs/testing/四轮车与雷达测试.md)。
