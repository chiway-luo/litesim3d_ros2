# 场景与地形

适用版本以 [VERSION](../../VERSION) 为准，环境为 Ubuntu 22.04 + ROS 2 Humble。命令在源码仓库根目录执行，每个终端先加载相同安装环境。

新世界优先使用 SDF：编辑 world 的 include、模型位姿和环境资源，再通过 runtime 的 entity_bindings 标记支撑与反射率。小车的 SDF 加载操作见 [SDF 与独立窗口](SDF与独立窗口.md)。本页演示教学单机 YAML 场景的修改。

## 实体配置

`entities` 是单机配置根节点下的列表；必须存在，可以是空列表，最多 10000 个实体。ID 非空且唯一。下面是追加到列表中的一个实体：

```yaml
- id: obstacle_box
  pose: {xyz: [2.0, 1.0, 0.5], rpy: [0.0, 0.0, 0.3]}
  geometry: {type: box, size: [0.6, 0.6, 1.0]}
  reflectivity: 0.7
  support: false
```

实体字段、单位和角色约束见 [配置文件](../api/配置文件.md#terrain)。

支持的 geometry：

```yaml
{type: box, size: [1.0, 2.0, 0.5]}
{type: sphere, radius: 0.3}
{type: cylinder, radius: 0.3, length: 2.0}
{type: mesh, uri: ../meshes/room.obj, scale: [1.0, 1.0, 1.0]}
```

以上四行是四种**替代写法**，分别作为某个 geometry 的值，不要原样拼成一份根配置。尺寸、半径、长度、scale 必须是正数；圆柱轴沿实体局部 z。实体 pose 再把形状变换到世界坐标。

显示高精度网格、碰撞低成本包围盒的例子：

```yaml
- id: machine
  pose: {xyz: [4, 3, 1]}
  visual: {type: mesh, uri: ../meshes/machine.stl, scale: [1, 1, 1]}
  collision: {type: box, size: [2, 1, 2]}
  sensor_geometry: {type: mesh, uri: ../meshes/machine.stl, scale: [1, 1, 1]}
```

这个片段要求你提供真实存在的 `machine.stl`。简化 collision 会改变通行空间，应以实际需要选取。

## 平地与连续坡面

平地示例：box 大小 `[30,30,0.2]`，中心 `[0,0,-0.1]`，上表面 z=0，`support: true`。未启用 terrain 时，支撑必须是未旋转且上表面 z=0 的轴对齐 box。

启用连续坡面，在根配置中设置：

```yaml
terrain:
  enabled: true
  max_slope_deg: 20.0
  clearance_m: 0.0
  continuity_m: 0.02
```

terrain 各字段默认值与允许范围见 [配置文件](../api/配置文件.md#terrain)。显式填写 enabled，避免省略时出现与预期不同的默认行为。

支撑来自 `support: true` 实体的 **collision**：箱体局部上表面，或朝上的 mesh 三角面。多层场景按前一支撑高度关联；桥底、立面等其他碰撞仍存在。网格三角形法向需朝上。

机器人支撑采样由配置 `robot.support_links`（旧配置为 `robot.drive.support_links`）引用的 URDF link 的 collision 几何确定：圆柱轮检查轮宽中心及两侧边缘，所有声明轮子都必须有支撑。该列表不能遗漏前轮或 mimic 轮，也不能包含没有 collision 的 link；更改轮距后采样位置随模型变化。球形和其他形状的采样规则见 [支撑规则](../api/坐标与模型约定.md#terrain)。

测试单一斜面时，可以将原地面替换为下列 5° 倾斜 box，并开启 terrain。示例起点保留 `[0,0,0]`，不要同时保留原水平地面覆盖斜面：

```yaml
- id: slope_ground
  pose: {xyz: [0, 0, -0.1], rpy: [0, -0.0872664626, 0]}
  geometry: {type: box, size: [30, 30, 0.2]}
  support: true
```

实际道路使用连续坡面或平滑网格。机器人会跟随支撑高度和法向调整 z/roll/pitch；遇到空洞、台阶、坡度或连续性超限会停止，不会自由落体或自动爬阶。拼接处的不光滑加速度不能当作真实车辆悬架响应。

## 固定障碍物

所有通过场景配置加载的障碍物固定在声明的初始位姿，不计算障碍物移动、受力或反弹。旧 YAML 中的 `motion.linear_velocity` 和 `motion.yaw_rate` 校验后忽略；manifest 的 `config.ignored_entity_motion` 列出受影响实体，便于识别旧配置。SDF 中未绑定为受控机器人的模型也固定在初始位姿。

显式 collision 继续作为障碍碰撞几何；SDF 场景 link 缺少 collision 时使用该 link 的 visual 补齐，旧 YAML 的独立角色实体缺 collision 时使用 visual。使用高精度 visual 补齐会增加碰撞计算开销，可通过显式 collision 提供合适的简化模型。

当前 ROS 接口没有在线增删障碍或更换场景服务，修改配置后启动新会话。

## 修改后的检查

重新启动前检查资源路径、单位、机器人初始碰撞和支撑层。先以低速验证可通行空间，再检查传感器看到的几何是否与 visual/sensor_geometry 一致。manifest 可核对实际资源哈希和被忽略的旧 motion。运行时不提供在线增删场景服务，修改配置后开始新会话。
