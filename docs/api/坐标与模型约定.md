# 坐标与模型约定

适用版本以 [VERSION](../../VERSION) 为准。本文描述当前运动学内核；字段接口见 [传感器数据](传感器数据.md)，配置见 [配置文件](配置文件.md)。

## 坐标与时间

右手系，机体 x 前、y 左、z 上；长度米、角度弧度、速度 m/s 和 rad/s。名称带 `_deg` 的参数在输入时使用度。位姿使用双精度与归一化四元数。相机 optical frame 为 x 右、y 下、z 前。

世界真值属于 world；算法使用 map → odom → URDF root → base_link → sensor_link。root 与 base_link 可相同，否则两者必须固定连接。里程计 TF 发布到 root，消息 child_frame_id 是 base_link，禁止同时给 base_link 建立第二个父节点。真值不自动注入算法 TF。

仿真从 1 ns 开始，步长转整数纳秒累加；传感器按自身截止时间采样，非整数倍频率不依赖显示帧率。rolling 云用帧起点作 header.stamp，完成全部采样后才能发布。不同 DDS 话题无统一到达顺序，接收方按测量时间等待 TF。

real_time_factor 控制墙钟节拍，不能修改固定积分步长；计算不足时真实推进变慢。暂停停止时间/采样，不停止墙钟诊断。重置创建新 run_id，重建消费进程与历史，不能仅将 clock 调小。

同一构建和运行条件下，固定 seed 与已按生效步记录的输入用于重复实验；改变线程数不改变槽位随机流。跨平台比较使用数值容差，外部 ROS 算法闭环需要独立记录控制输入，不承诺自动确定性。

## URDF 导入

使用与目标 ROS 2 发行版匹配的 urdfdom。接受 URDF 1.0 兼容内容；Xacro 作为预处理步骤生成 URDF，并将展开结果及其资源哈希写入运行清单。[urdfdom](https://github.com/ros/urdfdom)

| 元素 | 当前行为 |
| --- | --- |
| link、joint、origin、axis | 构建单根无环关节树，统一处理旋转与平移 |
| fixed | 固定变换 |
| revolute、continuous、prismatic | 运动学更新；适用的位置和速度限制生效 |
| mimic | 支持倍率与偏移，拒绝循环依赖 |
| floating、planar | 报告不支持并拒绝作为可运行模型导入 |
| visual | 显示几何，可作为默认传感器表面来源 |
| collision | 碰撞几何，支持同一 link 的多个碰撞元素 |
| inertial | 可解析和保存；运动学模式不据此计算动力学 |
| box、sphere、cylinder | 检查正尺寸，转换为可查询几何 |
| mesh | 支持 STL、DAE、OBJ；通过 Assimp 导入并校验网格 |
| `<litesim3d version="1">` | 解析底盘、里程计与传感器插件声明 |
| Gazebo 或其他扩展 | 记录为未执行扩展；不自动执行外部仿真插件 |

资源支持 `package://`、本地文件路径和相对路径。相对路径以 URDF 文件所在目录为基准；Xacro 模型使用展开时记录的资源解析基准。安装后必须通过包资源索引定位，不依赖源代码目录。网格单位按导入规范显式记录，不能根据视觉大小猜测；非均匀正缩放正确应用于顶点和法线，零值、负值与非有限缩放拒绝。

URDF 规模上限为 4096 个 link、4095 个 joint，关节链深度受 128 层预算约束。初始关节值必须满足限位及 mimic 关系；非驱动活动关节保持初值。

有 visual 的实体缺失 collision 时默认报错；纯坐标 link 可没有几何。允许用户显式开启 visual 到 collision 的替代，但兼容性报告必须列明替代 link 及性能影响。传感器表面按 `sensor_geometry` 覆盖配置选择，否则使用 visual；若 visual 缺失，可显式选择 collision，禁止无提示替代。

导入报告至少包含源文件与资源哈希、根 link、关节数量、支持类型、忽略扩展、缺失资源、几何边界、单位与缩放、碰撞替代和传感器绑定结果。错误必须指出文件与元素名称。

仿真器维护关节状态；robot_state_publisher 根据相同 URDF 和 `joint_states` 发布机器人内部 TF。固定关节使用静态 TF，活动关节根据状态更新；仿真器不得重复发布这些变换。[robot_state_publisher](https://github.com/ros/robot_state_publisher/blob/humble/README.md)

区分导入模型的 `root_link` 和运动参考 `base_link`。两者相同时，里程计发布 `odom → base_link`；例如根为 `base_footprint` 时，里程计发布 `odom → base_footprint`，URDF 发布 `base_footprint → base_link`。根位姿由运动参考位姿和内部变换换算，不能同时再给 base_link 增加一个 odom 父节点。里程计消息本身仍可用 base_link 作为 child_frame，但 TF 发布路径必须按实际树计算。

URDF 导入不等于任意机器人都能执行有效运动。根运动由声明的底盘插件或兼容运动模型控制；驱动、转向及 mimic 关节按模型更新，其他活动关节保持配置初值。不执行 URDF 中的插件或外部动力学控制器。

## 场景与几何

场景配置包含版本、单位、实体唯一标识、资源、世界位姿、显示几何、碰撞几何、传感器表面和可支撑表面属性。基本场景支持地面、墙、立柱、坡面、悬空物和网格。

静态几何建立空间索引并复用。射线返回量程内最近的有效交点；场景表面默认双面参与测距，避免薄墙因法线方向被漏掉。退化三角形、非法索引和非有限顶点要在导入时拒绝或按明确规则过滤并计数。

传感器默认仅排除雷达自身外壳 link，机器人其他结构仍可遮挡雷达。另提供整机排除或指定 link 列表模式，记录在运行清单。碰撞与感知可以使用不同精细度的几何，但必须来自同一实体、同一姿态和同一采样时刻。

用于射线的空间索引不能自动保证机器人不穿墙。碰撞检查需覆盖整个机器人包络在一个步长内的扫掠运动，包括旋转导致的角点移动。可以采用连续碰撞算法或有证明约束的自适应子步；只检查步末包围盒不足以通过薄墙测试。

接触对分为声明的支撑接触和阻挡接触。轮子或声明支撑点与当前有效地面在容差内接触是允许状态；车体穿地、轮子撞墙或接触非支撑表面仍属于碰撞。不能整体忽略地面实体的碰撞，也不能把正常支撑接触当作必须停车的障碍。

## 兼容驱动轮约束

以下仅适用于无 chassis 声明的旧 YAML 路径；新插件按自己的几何与参数契约校验。

| 项目 | 当前要求 |
| --- | --- |
| 左右关节 | 两个不同的 continuous 关节，不是 mimic，从 YAML 指定名称读取 |
| 轮轴 | 在 base 坐标系中指向 **+y**；左右轮都采用该方向 |
| 轮子 collision | 居中、与关节共轴的圆柱，半径与 `wheel_radius` 相差小于 1e-6 m |
| 轮距 | 两轮 link 原点距离与 `wheel_separation` 相差小于 1e-6 m，左轮 y 大于右轮 y |
| 关节树 | 两个驱动轮 link 必须是叶节点，不能再挂子 link |
| 速度 limit | 至少覆盖 `(max_v + max_w × wheel_separation / 2) / wheel_radius` rad/s |
| 支撑 link | `support_links` 中的名称必须存在，只列实际作为轮面支撑的 link |

## 运动模型与碰撞

| 模型 | 当前实现 |
| --- | --- |
| 差速插件 | 左右轮组，允许同侧多个独立轮及 mimic 从轮 |
| Ackermann 插件 | 后轴中点参考、四个轮与两个转向关节；理想位置转向，无舵机动力学 |
| 三轮/四轮全向插件 | 普通全向轮约束，平面 vx/vy/wz；不是麦克纳姆轮模型 |
| 旧差速/理想 Ackermann | 旧 YAML 几何约束，保留兼容计算路径 |
| multicopter | 保持水平的 vx/vy/vz/wz 运动学速度模型，无飞行动力学 |

插件运动关系和编码器估计定义见 [插件接口](插件接口.md)。URDF inertial 不用于刚体求解；不计算悬架、摩擦、打滑力、自由落体或接触冲击。

场景障碍固定在初值。旧 YAML motion 校验后忽略，受影响 ID 写入 `config.ignored_entity_motion`，`config.obstacles_fixed=true`；多机器人中的其他受控机器人仍按各采样时刻的真实轨迹参与感知与碰撞。

碰撞在运动区间内检查并限制车体位姿。continue_on_collision=false 仅提交碰撞前可接受的轮角；true 可继续提交驱动编码器位移，轮式 odom 因而偏离真实车体。超时、暂停及零命令仍生效。碰撞不产生真实冲击 IMU。

<a id="terrain"></a>
## 地形支撑

支撑来自 support=true 的 collision：箱体上表面或朝上网格面。按上一支撑高度关联连续层，不能跳到桥面；桥底与立面仍参与碰撞。超坡、缺支撑、台阶或空洞停止运动，不执行悬架/自由落体。

支撑 link 从模型及配置取得。圆柱轮检查宽度中心和两侧边缘；球形检查中心投影；其他形状使用保守包围框投影角点。每个支撑 link 必须有 collision，所有采样点都须连续支撑。初始化、设置初值和运动步骤采用相同规则。平滑 IMU 评测应使用连续光滑道路，不以拼接折角模拟真实悬架。

## SDF 资源兼容范围

| 内容 | 当前行为 |
| --- | --- |
| SDF 1.9、include、嵌套静态模型 | 使用 libsdformat12，解析 relative_to、attached_to、expressed_in |
| 单个受控机器人 + 固定场景 | robot.id 必须匹配受控模型；其余场景模型固定在初始位姿，忽略其 static=false 的运动含义；缺 collision 的 link 使用 visual 补齐 |
| box、sphere、cylinder、STL、OBJ、DAE | 支持正缩放；DAE 必须明确 Z_UP，保留节点变换和单位 |
| 多 visual/collision、多材质槽 | 显式 collision 独立保留；场景 link 完全缺少 collision 时由 visual 补齐，支撑角色同样生效；机器人仍按自身碰撞导入规则处理 |
| OBJ/MTL、DAE 漫反射纹理 | 保留每个材质槽、UV、颜色和纹理；缺失法向量按三角面补齐 |
| SDF 基础材质 | 颜色、透明度、自发光、双面、阴影；世界 ambient/background 和三种灯光 |
| SDF PBR metal | albedo、normal、roughness、metalness、emissive、light map 映射到 Ogre2；逐项验证范围见测试报告 |
| 不支持的视觉特性 | Classic material 脚本、任意 shader、specular 工作流、AO map、嵌入式图片明确拒绝；网格内非 diffuse 贴图需移到 SDF PBR 定义 |
| 其他不支持输入 | plane、heightmap、polyline、submesh 选取、骨骼 actor、外部 plugin、嵌套关节机器人、原生 SDF sensor：报错，不悄悄忽略 |

平面请在资产中**显式**改用所需范围的薄 box；原生 SDF 传感器需转换为 runtime 中的 LiteSim 参数。这不是任意 Gazebo 世界或动力学插件的直接替代。旧多机世界仍走原 `world.launch.py`，不支持多种 SDF 机器人的混合世界。

支持格式不代表全部资产已做视觉验收；文件能解析、贴图能解码、图形属性校准是不同验证层次。材质不支持或缺文件会报出具体资源，不以灰模作为成功结果。当前使用 Qt 支持的纹理图片解码格式；建议 PNG/JPEG。

## 碰撞预算与速率

预算关闭时，碰撞检测、防穿透和碰撞响应照常执行，仅不实施可选复杂度上限。开启时执行以下内部规则，超限在加载时拒绝，不删面、不丢弃碰撞体、不替换成包围盒：

| 检查 | 内部阈值 |
| --- | --- |
| 单碰撞 mesh | 10,000 三角面 |
| 世界碰撞 mesh（按实例） | 200,000 三角面 |
| 动态碰撞 mesh（按实例） | 20,000 三角面 |
| 单机器人碰撞体 | 64 个 |
| 世界碰撞体 | 1,024 个 |
| 固定拓扑潜在碰撞对 | 每次查询保守上界 20,000 对 |
| 碰撞结构估算内存 | 256 MiB；不是进程 RSS 硬上限 |

本版采用固定拓扑的加载预检，没有运行时添加模型，也没有实现通用的每步耗时/内存强制限额。预算不限制视觉网格，且不承诺总 CPU/GPU 占用上限。视觉和射线网格不会自动创建 FCL；同一资源确实被 collision 引用时才创建碰撞结构。

实际 RTF 为 `Δ已提交仿真时间 / Δ单调墙钟时间`，约 1 秒滚动窗口，5 Hz 发布。目标 50% 就显示接近 50%，实际 63% 不会被改写为 100%；FPS 单独计算。重计算超过周期会自然减慢，固定积分步长不变，不靠跳过碰撞或传感器事件追赶。

暂停显示 0%，统计仍按墙钟发布；run_id 或时间回跳重建基线。统计超过 2 秒没有更新显示连接中断。统计发布仍使用现有 ROS executor，极重单次计算可能延迟心跳；窗口会标识超时，并未另建可抢占物理步骤的线程。
