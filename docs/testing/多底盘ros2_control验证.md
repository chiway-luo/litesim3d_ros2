# 多底盘 ros2_control 验证

2026-10-23，在已有差速 SystemInterface 接入基础上增加阿克曼、三轮/四轮普通全向支持。结果针对本地开发树，不代表已推送版本、真实设备或动力学验收。配置教程见 [阿克曼与全向轮接入 ros2_control](../tutorials/阿克曼与全向轮ros2_control.md)。

## 实现范围

- AckermannDrive 根据后轮速度和实际转角计算机体运动；前轮旋转只读，随实际行程滚动，碰撞时不随驱动轮空转虚增。
- Omni3Drive / Omni4Drive 根据实际轮速矩阵恢复 vx、vy、wz；原 twist 模式保留。
- 阿克曼案例由标准 ackermann_steering_controller 控制；普通全向案例由新的 OmniDriveController 控制。第三方控制器可通过管理器原子切换接管轮速和转向接口。
- RSP、管理器、broadcaster 均由案例 launch 用 ld 配置，显式传入参数文件；共享 launch 不包含这些节点。案例选择独立仿真编码器里程计发布 /odom 与 odom TF，关节控制器切换不切换 TF 所有权。
- 新教程中的 11 个源码块与实际文件逐字一致，三个案例的控制器几何参数与机械模型由测试交叉验证。

## 平台与结果

环境为本机 Lima humble-arm64、Ubuntu 22.04 arm64、ROS 2 Humble；hardware_interface/controller_manager 2.54.3，ros2_controllers 2.54.1。使用独立 /tmp 工作空间、单任务编译，33 个包构建完成。本轮关闭 GUI/RViz/相机，未进行桌面渲染测试。构建中的 Geometry::motion 缺省初始化警告来自已有核心代码；新控制硬件和控制器目标没有编译错误。

## 发现与修复

初次阿克曼接管失败：标准 steering controller 在 on_deactivate 写 NaN，而 Humble 先执行硬件模式切换、再调用控制器生命周期。适配器原先只在 perform_command_mode_switch 重置目标，随后会被该 NaN 覆盖。现于交接后的首次 write 再保持当前位置/零速度一个循环；之后照常处理新控制器指令，非有限运行中指令仍报错。

随后全套 ROS 案例与硬件联调为 15/16 通过，唯一失败为测试在收到零关节速度后立即断言另一话题的旧真值消息。改为等待该真值消息后，三个接管用例定向复测 3/3 通过，并新增全向限幅/NaN 覆盖。首次失败、修复后的完整运行、定向复测及源码摘要均保留。收尾时将全向控制器激活过程的缓冲重置改为线程安全写入，并用激活代次隔离旧回调；三轮/四轮接管再测 2/2 通过。
